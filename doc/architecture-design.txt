Blofeld instrument VM — target architecture

This is the agreed target. Source under reconstruction is not evidence that the
complete instrument or its performance has been achieved.

  app: profile, lifecycle, display UI, live or offline consumer

                |                     |
           MCU owner              DSP owner
           cpu12 JIT             dsp56300 JIT

Each core runs independently in long native sessions, on its own execution
thread. Audioframes and bounded queues govern progress and backpressure.
Synchronize for real command/data ownership, readiness/IRQ transitions, audio,
reset or faults; local MCU memory/register accesses do not advance the DSP.
There is no global per-instruction/per-clock coordinator.

VmContext owns concrete bindings, stable memory, channel lifetimes and shutdown.
Each worker exclusively mutates its core and local device state. Transfer actual
firmware-produced words/messages through bounded channels with explicit ordering,
timestamps and ownership. Other threads do not inspect mutable core state.
Keep native calls typed and direct; no common runtime core hierarchy or mirrors.

Implement device transactions and completion semantics: command/data FIFOs,
readiness, interrupts, USB endpoints, SCI bytes, storage reads/writes and resets.
Decode firmware bit-banging locally into transactions. Do not replay electrical
lines or resolve voltage networks. Never manufacture acknowledgements or data.
MCU U0 controls the active-low DSP reset. A reset epoch stops the previous native
instance before the DSP owner resets SHI and acknowledges it. The MCU releases
reset outside its JIT callback after that acknowledgement; stop cancels either
wait. Restart creates a fresh Core/JIT and retains SRAM. The U0 assignment is
inferred from the firmware hold/release sequence and the documented RESET pull-up.

Port B3/B5..B7 have no input producer in the current instrument contract. Their
input-mode samples are inactive low; output-mode reads still use the MCU latch.
This deterministic VM choice for passive controls is not a claim about PCB pulls.
Active data/status inputs must come from their devices, never from this policy.
The attached SHI SS/SCK/MOSI pull-ups supply released B1/B2/B4 input samples.

PM3 samples an external pedal level, initially inactive in the VM. The MCU sends
its raw 0/8 change event; the DSP's class-3 handler normalizes sustain and applies
GDATA60 pedal polarity. This software contract follows both firmware paths;
it assumes no PCB pull or physical contact type. The host must not duplicate
the pedal event as MIDI. Controls are sampled by the MCU owner, never by mutating
its live Core or GPIO registers from another thread.

Display A/B/E writes decode complete controller transactions. The E4 latch
delimits accesses even after firmware releases DDRE: this is a functional VM
binding, not a recovered physical enable route. B7/B6 select, B5 selects reading
and B0 data. Status reflects completed LCD state; dummy reads retain the actual
holder, RAM reads advance once per completed transaction, and unknown RAM fails.
Peripheral reset is supplied by VM lifecycle; no PCB reset net is assumed.

A selected boot transaction whose SHI receive mode is not published yields its
MCU owner. Outside the native callback, wait for the DSP's actual HCSR write or
shutdown, then capture with that mode. This orders transaction ownership across
host scheduling/JIT latency without synthesizing readiness or advancing clocks.

SHI transfers complete words through one bounded receive FIFO and the distinct
HTX/IOSR transmit stages. HTDE follows actual HTX ownership; CPHA=0 loads IOSR
while deselected, CPHA=1 can load between words. Unpolled writes overwrite HTX,
never the active shift word. Underflow output remains unknown and HCSR/HTX clear
the observed error; no idle word or peer response is manufactured by the host.

Local ISA timing remains correct; cross-core coupling serves observable instrument
behavior rather than hypothetical silicon phases. Qualify ordering, IRQ delivery,
partial transactions and musical latency against firmware and independent tests.

Use documented nominal device clocks and analytical divider/deadline arithmetic.
The UF32 uses its 12 MHz reference and nominal 60 MHz PHY output; qualify clock
availability through the documented detector window, without analog PLL or
external waveform models. Keep oscillator-driven RTI independent of CPU clock
selection. Convert device deadlines to Core progress without counting idle time
twice, and arbitrate actual pending interrupt vectors before resuming native work.

DSP56371 RAM banks are shared physical storage. MS/MSW changes rebind native
windows at the Core's existing OMR boundary; no state mirror or payload copy.
Switched physical tails map in ascending address order into program RAM. Firmware
must obey the documented three-cycle exclusion for affected bank accesses.
Known reserved data writes are discarded, inferred from the original overbroad
clear. This is a VM contract, not measured silicon behavior. Missing ROM/reserved
reads still fail; supplied immutable ROM is borrowed, and unknown I/O fails.

DSP56371 PCTL selects an exact nominal Fosc/EXTAL ratio using its own raw factors
and dividers. The reset clock profile uses PINIT=1. Do not infer a fitted oscillator
frequency, physical lock or host pacing from those fields. Device deadlines use
this ratio when converting local core progress to instrument time.

SCI exchanges decoded characters with explicit start/completion times, baud and
format, without pad sampling or serial line replay. Preserve its status/data clear
sequences, preamble and transmit-buffer handoff, receive overrun and wakeup effects.
Bound completed output and report an undrained consumer instead of losing data.

USB local endpoint windows borrow the selected RAM and byte-knowledge arrays.
Bank changes publish new native memory grants after the complete selecting
instruction; never copy buffer payloads or remap for unrelated register writes.
Preserve ordered high/low word commits and firmware-written configuration quirks.
Enumeration, SOF and transfer completions come only from actual host transactions.

Audio comes from the final original DSP output buffer. Publish complete ordered
frames/blocks, preserving DMA/FIFO status and sample times. Split processing at
relevant MIDI/device events. Live consumption bounds lookahead and paces output;
offline draining runs as fast as possible. No wall-clock substitution for musical
time, missing frames, duplicate frames or serial-PCM bit decoding.

DMA consumes real request edges or a software DE trigger. Arbitrate pending
channels by priority and word ownership, using native memory accesses and typed
data-register transactions. Advance addresses/counters and signal completion only
after the destination accepts the word. Preserve counter reloads and circular
buffer positions; configuration alone does not produce audio. Program writes
publish one changed code revision before native execution resumes.

ESAI_1 consumes complete slot events from its clock source, not individual audio
bits. Its format determines HCKT ticks per slot and slots per frame. Each event
consumes actual transmit-register words and requests DMA refill; unknown data
cannot become valid PCM. Port assignment and personal reset govern activity.
Bind the clock source separately; register initialization alone advances no time.

DAX uploads complete words from XADR and its two channel buffers. Both audio
addresses share alternating A/B ownership; metadata is captured at frame start.
Refill requests and block/underrun interrupts follow actual buffer transactions.
Preserve these effects without biphase encoding or a second host audio stream.

DSP timers derive CLK/2 progress from completed Core base cycles. Predict actual
compare/overflow deadlines; configuration changes move the execution horizon.
Preserve first-clock loading, reload events, W1C flags and TE=1 continuity.
External events supply capture/count input; media readiness is Timer1's input.
Unspecified TLR/TCPR power-on contents use deterministic VM zeroes and survive
RESET; this is a VM choice, not a recovered factory value.

Arbitrate actual interrupt conditions by configured IPL, SR mask and documented
source order. Admit through the Core's native vector path with VBA; acknowledge
only the accepted timer/DMA request. DAX level conditions remain until firmware
clears them. A pending request observes individual architectural boundaries while
masked or inhibited; ordinary execution retains long native runs. WAIT advances
device time analytically without manufacturing retired CPU work.

Storage port writes decode commands, addresses and byte ownership locally. A
complete address publishes an operation; the DSP owner resolves the actual image
page outside its native callback before publishing ready. Read strobes retain a
held byte and advance on release. Unknown bytes/pages fail with transaction
context. Images retain their encoded backing and a direct page index; no cell
physics, payload mirrors or default successful program/status replies.

Keep persistent images for identity, programs and samples. Preserve genuine
operation status, interrupted writes and recovery; remove cell physics, synthetic
pulse profiles and redundant backend wrappers. Reset/update coordinates worker
stop, channel retirement, image publication and fresh core/code ownership.

Source ownership:
  src/vi/       VM lifecycle and instrument-specific behavior
    mcu/, dsp/  concrete cores, local registers and memory
    io/         transaction channels and memory controller
    storage/    persistent device images
    display/    firmware LCD state
  src/host/     reusable audio, MIDI, USB and OS backends
  src/app/      composition, CLI, UI and display publication
Host knows no instrument registers; vi/ knows no host API handles.
app/ connects data/buffer contracts without reverse dependencies.
test/ mirrors src/ with simple unit tests; integration uses the normal emulator.

Use optimized Release and profile the complete instrument. Require >=4x offline
throughput, design for 10x; see OBJECTIVE.md for measurement and full acceptance.
Threads, a short synthetic kernel or lower callback counts are not success proofs.
