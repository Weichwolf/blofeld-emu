Blofeld runtime design

This is the implementation target, not a claim about current functionality or
performance. Original firmware and DSP synthesis remain the instrument.

                         emu()
                           |
          memory -> persistent images -> peripherals -> cores
                           |
             +-------------+-------------+
             |                           |
       MCU worker                    DSP worker
       cpu12::Core                   dsp56300::Core
       mcu.run(stop)                 dsp.run(stop)
       JIT -> JIT -> ...             JIT -> JIT -> ...
       MCU RAM / flash               P / X / Y RAM
       local MMIO / timers           local MMIO / audio / NAND RAM
             |                           |
             +--- MCU-to-DSP FIFO ------->+
             +<-- DSP-to-MCU FIFO -------+
             |    timestamped events     |
             |    IRQ / reset notices    +---- PCM ring ---- audio consumer
             |                           |
             +------ dirty storage ------+---- storage worker ---- images

       Host event loop: MIDI, optional UI, commands and shutdown
       Host input -> bounded input queue -> MCU worker

Application modes and profiles

No arguments select the default local profile and start the live instrument.
A profile names local firmware, persistent memory/sample images and unit
identity. Profile selection changes assets, not the execution architecture.
The instrument CLI exposes no wiring, chip-clock or instruction-budget controls.

A Standard MIDI File plus WAV destination selects offline rendering. Merge tracks
and tempo changes onto the audio timeline before dispatch; a fast render keeps
identical musical spacing. Render completion follows the requested musical range
and release/effect tail. Stream output to disk without a fixed capture-frame
ceiling. Live output uses the same execution and MIDI timing path, paced by
actual audio consumption. Both cores always execute at maximum performance;
only due events, stop and consumer backpressure bound runahead.

Progress reporting belongs to the host event loop. Offline completion prints
actual audio duration, monotonic elapsed time and throughput, with startup and
transport failures separate. Live mode refreshes one status line at a bounded
rate using frame counts, queue fill and measured latency; redirected output is
plain text. No instruction-by-instruction telemetry or core-state copying is
required for these measurements. Unknown quantities remain unknown.

Execution

Initialization loads local images once, creates stable memory views and device
state, then starts each core's long-lived run loop. The DSP starts in its real
reset/bootstrap state; original MCU activity releases and loads it. Shutdown
requests stop at safe execution boundaries, joins workers and closes storage.

Each worker owns its core, JIT cache, ordinary RAM and peripheral state. RAM
accesses use direct native loads/stores. Selected MMIO accesses run the required
local side effects. Unknown accesses remain explicit faults with PC/context.
Do not replace firmware routines, synthesize host audio or fabricate replies.

Translations follow natural control-flow boundaries, without a fixed 64/256
instruction cap. Generated blocks chain directly where execution state permits.
Assume original Blofeld code remains immutable during normal instrument operation;
this is a working assumption, not a hardware-verified fact. The emulator owns
firmware loading and updates; it supplies new memory and resets/recreates cores
and their translation caches. Core libraries have no firmware-update protocol.
Do not continuously check for self-modification in the normal instrument path.
Exit generated execution for
pending interrupts, actual I/O effects, due device events, stop or backpressure;
do not return through board-control code for every instruction or clock edge.

Communication and time

Cross-core transport uses bounded single-producer/single-consumer queues and
explicit atomic notification. A receiver handles its own interrupts and state;
another thread never modifies its architectural registers. Device registers with
read/pop/acknowledgement behavior retain those effects rather than becoming
unconditionally successful plain memory.

Core clocks use one virtual device timeline with bounded lookahead. Grants and
communication boundaries must prevent delivery from the future and late IRQ
service caused by blindly completing a larger grant. Synchronize at relevant
device effects/deadlines, not every electrical edge. Derive idle time and timer
progress in spans. The time-grant protocol is an explicit implementation task;
independent host threads alone do not establish correct virtual ordering.

Live audio consumption bounds runahead; offline consumers may drain faster than
real time. Host capabilities do not change device clocks. Audio callbacks only
consume bounded PCM, with no core execution, allocation, file I/O or mutex wait.

Storage and observation

NAND/sample reads use RAM. A storage owner persists changed pages/sectors and
reports completion before the firmware observes durable completion. Device
identity/MCU NVM and selectable NAND images remain distinct local resources.
Manufacturer firmware, populated images and samples are never published.

Publish display snapshots on changes. Enable diagnostics explicitly; disabled
diagnostics perform no instruction-by-instruction copying or logging. Keep run
artifacts outside doc/. No activity diary is maintained in the repository.

Implementation gate

Prioritize connected instrument execution. Core benchmark percentages do not
block integration; fix and optimize the responsible core for measured defects
or instrument bottlenecks. Scalar and SIMD execution are options, not mandates.
Compile, format and statically analyze without weakening checks. Keep affected
core correctness and sanitizer tests active. Until real time, suspend long
firmware runs. Short optimized startup/throughput probes stop and fail unless
playable within 10 host seconds; do not extend or automatically repeat a failed
probe.
