Blofeld firmware runtime

The implementation target is a minimal firmware execution and I/O layer.
Instrument behavior, original synthesis and musical time define correctness.

  local firmware / persistent images
                   |
           stable memory mappings
                   |
        +----------+----------+
        |                     |
    cpu12::Core          dsp56300::Core
    native MCU code      native DSP code
    direct RAM/flash     direct P/X/Y RAM
        |                     |
        +--- shared I/O ------+
        |    data, IRQ, reset  |
        |                     +--- completed PCM words ---> audio consumer
        +--- USB endpoints <------ USB-MIDI host transport
        +--- LCD RAM ------------> independent display consumer
        +--- persistent writes --> selected memory images

Execution

Initialize memory, persistent storage and register state, construct both cores,
then execute native code at maximum throughput. A shared device timeline orders
actual I/O effects, interrupt deadlines and audio transfers. Preserve elapsed
musical time regardless of host processing speed. Core execution returns only
for required events, I/O, backpressure, shutdown or a contextual failure.
Ordinary guest arithmetic and memory do not invoke the instrument layer.

The runtime does not replay physical address/data lines, electrical bus slots,
voltage networks, NAND setup/hold windows or external MIDI serial bits. Firmware
bit-banged register accesses still require decoding into their actual commands
and data. Those effects are implemented at register transactions and operation
completions, without continuously resampling connections between accesses.
MCU/DSP communication keeps actual data, readiness and interrupts; replies are
produced by the original firmware. Unknown accesses fail with PC and address.

Audio and transport

Read completed original DSP output words directly, retaining DMA positions,
flags, frame order and sample timing. USB uses original control requests,
endpoint FIFOs and interrupts. Host MIDI never passes through an external UART.
The live audio consumer paces output through bounded queues. Callbacks cannot
allocate, lock, throw or access files. Host APIs and capability grants remain
outside the cores and firmware I/O handlers.

Offline rendering uses the same firmware path and timeline, draining audio as
fast as possible while preserving SMF event times and release/effect tails.
Measure throughput as valid delivered stereo frames / (44100 * host seconds).
Separate startup, active processing, pacing, underruns and transport latency.
A core benchmark or a boot screen does not establish a playable instrument.

Storage and reset

Memory images retain identity, programs and samples across instances. Genuine
writes and erases update the selected image; reload preserves incomplete-operation
state after interruption. Firmware updates recreate affected core/memory owners
and JIT translations. No firmware patch, skipped routine, fabricated success
response or replacement synthesis path is permitted.

Keep telemetry runtime-selectable and disabled by default. Formatting, file I/O
and status observation stay outside native arithmetic and the audio callback.
