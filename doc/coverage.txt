Current acceptance coverage

The objective in objective.txt is not complete. The requirement numbers below
refer to that file. Documented Desktop/Keyboard functions are tracked individually
in function-acceptance.tsv; its pending entries are not waived by component tests.
Reference manifests pin specific source/input/test scopes, not an assertion that
all functions or every current binary have passed.

1. Local references — partial
Official 1.25 firmware, manuals, images and sample references are private inputs.
Downloads and primary-source hashes are in downloads.json, dependencies.json,
hardware/sources.json. Storage images
used for experiments declare their provenance and virtual initial conditions;
they are not recovered factory NAND. Required contents and licensing behavior
for every wavetable/sample function remain open. See firmware-layout.txt,
sample-library.txt and nand-board.txt.
The update also contains sixteen verified secondary pages for MCU RAM overlays.
An installed virtual image must include these pages; the earlier bounded audio
cases declared them erased and do not establish a complete installed image.
See secondary-pages-reference.json and firmware-layout.txt.
The native cold-image constructor now retains the complete runtime transport
source and all sixteen overlays. Both sanitizer configurations match the
independent123-page source-only image byte-for-byte and pass authored policy/
rejection cases plus existing parser/CLI regressions. Automatic normal-profile
creation, complete installed contents and connected boot remain separate open
requirements. See firmware-nand.txt and firmware-nand-reference.json.

2. Connected CPU/DSP/device implementation — partial
The regular Board/headless runtime uses the independent dsp56300 core pinned in
dependencies.json. It connects actual reset, MCU SPI download, DSP execution,
GPIO communication, timed NAND, timers, MIDI input and original DSP/ESAI output.
The original firmware has produced MIDI-driven PCM through the normal CLI with
live MCU/NAND stores. Both complete device profiles and normal standalone startup
remain unqualified. Legacy test migration/dependency removal and subsequent
OwnDsp naming cleanup remain open. See own-dsp-integration.txt, runtime.txt and
nand-read-handoff-reference.json.

The successful bounded ordinary case executes 4.8M MCU operations from actual
reset and reaches about 418ms of DSP virtual time. It exports 6792 stereo PCM
frames at 44.1kHz, with 6191 nonzero frames and four received MIDI wire bytes.
Independent WAV-format/native-frame checks pass; both CRC-valid stores stay
byte-identical. Native LCD output shows the boot caption. This is evidence for
that connected interval, not full startup, normal instrument UI or all functions.

3. Deterministic behavioral tests — partial
Instruction, flags, addressing, memory, interrupt, DMA, peripheral, storage and
joint-checkpoint tests exist. Recent affected closures pass ASan/UBSan and
separate TSan; their exact scopes are recorded by the corresponding manifests.
The original MIDI experiment additionally compares clock-only, held note,
NoteOff and an octave above after one actual reset and trusted full-value cuts.
It verifies source-byte counts, unchanged cells, the complete held-note PCM
prefix against the ordinary CLI, pre-NoteOff causality and declared pitch bounds.
This uses cold-value snapshots, not live-store rewind. It does not qualify all
controllers/channels, bank/program selection, bidirectional host MIDI or both
hardware profiles. See original-notes-reference.json and function-acceptance.tsv.
Passive MCU serial output is now captured from resolved PR3/PS5 pads into a
bounded queue, including WAI and joint snapshots. Ten scoped native cases pass
under both sanitizer configurations. This supports Board output capture; original
firmware replies, host delivery and USB remain unqualified. See midi-output.txt
and midi-output-reference.json.

Connected reset/SPI/NAND gates match all56238 known source bytes in actual
protocol and retired DSP samples,107 address sequences and read deadlines.
Unknown tail cells still refuse; fixed evidence corruptions reject. All eight
reset/storage/GPIO/NAND cases pass both sanitizer profiles. This prefix does not
establish loader completion or unchanged persistent storage. See
original-fetch-nand-reference.json and original-fetch-nand.txt.

4. Complete update/recovery — partial
Native flash/NAND command, persistence, interrupted-operation and loader tests
provide component evidence. Full connected valid/damaged update, every power-loss
phase, restart and recovery flow on both profiles remain open. No physical flash
safety is inferred. See mcu-flash-persistence.txt, nand-write-store.txt and the
update/recovery rows in function-acceptance.tsv.

5. Quality, stability and performance — partial
LLVM19/C++23, warnings as errors, format/tidy, dependency instrumentation and
separate sanitizer configurations are enforced by the build. Scoped validation
is used; source identity and evidence scope matter when reusing results.
Fuzz harnesses are offline and run only on explicit request. Current progress
runs do not establish long-run or real-time whole-instrument performance.
See dependency-build.txt, dsp-interrupt-owner-reference.json and AGENTS.md.

6. Tracing and snapshots — partial
Explicit traces, read-only observations, bounded PCM recording and coordinated
trusted in-process snapshots support diagnosis. A live file store cannot be
rewound by a RAM-only snapshot. Complete portable whole-device save/restore and
all persistence/failure scenarios remain unqualified. See reference-board.txt,
mcu-flash-persistence.txt, nand-write-store.txt and device-identity.txt.

7. Independent expectations and reconstruction — partial
Tests use literal ISA/peripheral expectations, primary documents and actual
original firmware execution. Functional GPIO, bootstrap, clock and bus-selection
contracts are explicit hypotheses. Unknown/unsupported accesses remain visible.
The original firmware may have quirks; passing one access does not prove physical
wiring. No teardown or measurement is required to continue the reconstruction.
See hardware/sources.json, nand-board.txt and dsp-gpio-write-decoder.txt.

8. Host-visible USB-MIDI — partial
USB/controller/endpoint/transport components and original-routine fixtures exist.
Complete original enumeration and bidirectional host-visible USB-MIDI through
normal device operation remain open. A separate ALSA port is not that proof.
No USB audio function is part of the Blofeld profile. See usb-runtime.txt.

9. Normal standalone instrument — pending
The executable currently exposes explicit reference configurations, file inputs,
render/export facilities and separate host adapters. A complete Keyboard-default /
Desktop normal device launcher, sustained original instrument operation, all
MIDI/SysEx controls, live audio and their failure behavior are not qualified.
Bank/program selection with original name/number/audio changes is specifically
pending. See runtime.txt and MIDI-BANK-PROGRAM/UI-SELECT in function-acceptance.tsv.

10. Native LCD and viewer — partial
The emulated controller publishes complete display.pbm/display.txt files.
The GTK file viewer is under src/gui; it does not execute firmware or send MIDI.
Actual ordinary Board output and authored/conditional LCD tests are distinct
from the separate paused MCU-only preview that can show Play Sound/A001/Init.
That preview is not proof of coupled DSP, live MIDI or normal full-device startup.
See display-export.txt. MIDI-triggered original UI changes remain unqualified.
