LCD interface

Live files: $XDG_RUNTIME_DIR/blofeld-emu/display.pbm and display.txt.
PBM: P4, 128x64, row-major, MSB first, black=1; 1024 payload bytes.
Text: '#' on, space off, '?' unknown. PNG is optional saved output.
Capture actual LCD state, not buffered MCU drawing RAM. Unknown raster pixels
reject PBM/PNG. Explicit panel geometry remains separate from controller modes.

Publish immutable complete files by same-directory atomic rename; unchanged
pixels skip I/O. Watch the directory, not the replaced inode. Initial reads,
queue overflow and directory recreation must resynchronize from the latest file.
This is software presentation, not physical VSync or atomic firmware redraw.
PBM/text publish separately. A failed publication invalidates the cache so either
old or new pixels can repair both files. Publisher lease and files are private.
Image/file work stays outside native execution and realtime audio callbacks.
The host runtime is tmpfs; active swap prevents a strict no-SSD-I/O guarantee.

Implementation/evidence
capture_lcd copies an inactive controller without native reads or pipeline/RMW
mutation. It honors ADC/COM reversal, start-line wrapping, reverse/all-points and
display-off modes. The renderer models digital 64-COM pixels, not optical drive.
LcdPublisher requires an existing directory and uses the shared atomic writer.

lcd_image: literal pixel/mode/packing expectations, unknownness, read-only RMW.
lcd_export: independent PNG CRC/rows, write failures/repair, 64 replacements,
concurrent complete-file readers and inotify events.
original_lcd_image: hash-pinned local 1.25 setup/clear/pixel/full-flush execution
through the conditional GPIO fixture. Buffered drawing stays invisible until
1024 original GPIO writes flush it. Recovered logical UI Y reverses normal COM
presentation; physical module wiring/timing remains unverified.

GTK viewer
  tools/blofeld-display
  cmake --install build/strict --prefix "$HOME/.local" --component Display
Menu: Multimedia / Blofeld Display. Dependencies: python3-gi, python3-gi-cairo,
gir1.2-gtk-4.0. --runtime-dir selects an alternate runtime root for development.
The viewer reads only, watches directory/parent replacement, coalesces redraws
and scales pixels by integer factors. Missing/invalid files clear the image.
Frame availability is not publisher liveness: abandoned files remain snapshots.
display_gui checks actual GTK redraw and file/directory/session lifecycle under
Xvfb; missing test dependencies explicitly skip. No companion CLI is introduced.
