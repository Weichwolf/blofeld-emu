DSP in-process checkpoints

DspMachine owns a native DspCore and its strict DspBus. checkpoint() captures an
immutable trusted instruction-boundary or healthy reference-access suspension
state; restore() constructs a replacement
machine before publishing it. Allocation or validation failure leaves the live
machine untouched. A prior valid checkpoint can recover a rejected core, but a
failed step itself cannot be captured. Restore invalidates bus/CPU references;
callers must rebind external links. The API is single-threaded.

  cmake --build --preset strict --target blofeld-dsp-checkpoint-test
  ctest --test-dir build/strict -R '^dsp_checkpoint$' --output-on-failure
  ctest --test-dir build/strict -R '^original_coupled_boot$' --output-on-failure

Captured state
- Native registers, all sixteen stack slots, AGU modifier-derived state, current
  execution context and diagnostic instruction/cycle counters.
- Yielded REP count, loaded/unloaded single-word opcode latch, saved LC and
  the completed-REP interrupt-deferral marker; DO/DO FOREVER state in the native
  registers and stack; fast/long/nested interrupt continuation and dispatch.
- Independent P/X/Y RAM/ROM words and knownness, retained physical aliases,
  pending code invalidations and explicit map-switch delay.
- SHI FIFO and partial SPI RX/TX shifts, last pin observations, output knowledge,
  flags and reset/interrupt delays; PLL command/PINIT knowledge; GPIO controls,
  latches and external observations; timer counts, phases, capture state and
  interrupt-priority/controller state.
- For the explicit unclocked access-continuation profile: instruction-start native
  state, captured admitted effects/lookahead and the pending real effect. The bus
  snapshot includes already completed side effects. Restore invalidates old access
  tickets; query a fresh ticket before admission (dsp-reference-execution.txt).
  Explicit interrupt entry also retains its chosen request/priority, both vector
  words and actual acknowledgement prefix. A newer source is not substituted
  during restore/recomputation; the native base remains pre-entry while paused.

The native adapter canonicalizes deferred CCR updates, as existing architectural
state reads already do. Opcode dispatch is rebuilt; cached diagnostic cycle
costs and peripheral pacing deadlines are retained. Native counters and pacing
are not calibrated elapsed clocks. The optional run contract retains reference
time, odd CLK/2 residue, ratio latching and fault status; see dsp-run-clock.txt.
It does not establish a calibrated board scheduler.
The internal access-attempt rollback uses a separate fixed raw register/context
state and cold dispatch at the current instruction. It leaves these explicit
full snapshots and their per-PC diagnostic cycle vector intact; it does not turn
checkpoint capture/restore into a bounded real-time operation.
The API rejects native JIT, debugger/trace/external-bus contexts and SDK interrupt
queues/callbacks, which are outside this custom-bus reference path.

Regression evidence
Own native instructions check ADD value/flags and modulo-eight wrap, unknown RAM,
immutable branch isolation, REP before/after its first body fetch, latched code
despite changed P opcode, actual per-iteration data reads, later coherent normal
fetch, nested two-by-two DO loops and recovery after a reserved-memory fault. Independent expected values
supplement complete debug-state comparisons, including stack and native counters.
Timer vectors check pending/acknowledged sources, nested long entry, native
priority reconfiguration, INC/RTI frame unwinding and fast-vector continuation.
Explicit SPI edges check an outgoing and incoming word across a thirteen-bit
checkpoint; timer compare, unknown GPIO/PLL knowledge and pending memory-switch
completion retain their separate observations.

The original coupling experiment now also captures the executing MCU, DSP and
caller-owned link in a selected mid-transfer state. Restoring all three replays
every remaining CPU/pin trace entry through the unchanged 94-word stage load and
mapped RAM clear, under both declared instruction interleavings. The receiver
resumes its captured machine state, including partially shifted SHI data and
native loop continuation. The existing complete trace stays unchanged
(coupled-boot.txt).

Fifteen native counter cases additionally retain five-bit SC through one to
fifteen real SSH pops, MOVEC reads, pushes across 31->0 and a repeated suffix.
Own unsupported stack-pop/push cases reject with operation/SP/PC/OMR, quarantine
execution/capture and reproduce the failure after trusted restore. These checks
establish no hardware exception/vector or stack-extension implementation.

Scope
These are process-local snapshots of the implemented reference models, not a
portable/persistent state codec, a stock DSP dump or a complete Blofeld snapshot.
They contain native execution metadata and must not be loaded from untrusted
files. Snapshot operations allocate and may throw; they do not belong in a future
real-time audio callback. Caller-owned MIDI/audio, NAND device/store, LCD, pin
wiring and scheduler state need their own coordinated snapshot and restore.
Timed board boot, missing ROM/assets, Desktop/Keyboard profiles, original audio,
complete update/recovery, stress and hardware validation remain pending.

DspScheduledRun separately checkpoints its unfinished nominal completion, epoch
and observation contract. The common-time original MCU/DSP test restores native
machines, source pads and scheduler together mid-frame and near the actual next
reserved-memory write. Recovery after that joint execution fault reproduces the
remaining events, partial register state, completed clocks and error exactly.
Faulted captures reject; failed instructions are not automatically rolled back.
See scheduled-coupling.txt for the declared observation contract and limitations.
