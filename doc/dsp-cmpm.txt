Normal CMPM magnitude comparison

DSP56300FM Rev.5 page13-47 defines CMPM as |S2|-|S1| on 56-bit operands.
The difference updates condition codes without replacing either operand.
Table5-1 defines N/Z/E/U from the result, V from signed56 overflow and L as
sticky on V. CMPM separately qualifies carry only for properly sign-extended
S2 destinations; the test asserts C only within that domain.

Magnitudes include +2^55. The representable difference 0-|min56| has N=1,V=0;
|min56|-0 wraps with positive overflow, N=1,V=1,L=1; two minima compare equal.
The independent DSP core now computes these magnitude boundaries separately
from ordinary signed subtraction overflow. This is the declared mathematical/
manual interpretation; the minimum-operand flags are not silicon captures.
See the pinned core's doc/magnitude-comparison.txt for its generic regression.

The emulator test runs directly through the independent CPU and strict board
bus using authored literal setup/opcode words. Its unchanged independent model
uses right-aligned signed64 magnitudes, subtraction and range checks. It covers
16902 fixed cases: 6144 other-accumulator operands, 10752 X0/Y0/X1/Y1 operands,
and six minimum regressions. Inputs include both destinations, three scaling
modes and four CCR seeds. C is checked in 9506 qualified cases. Every register,
stack slot, operand and instruction retirement remains checked.

The separate immediate-CMP test retains its independent signed56 flag oracle
for 256 cases. It observes real F2 words, changes the later backing extension,
and checks separate native ALU/PCU/retirement publications. Three checkpoint
cuts per case produce 1536 suffix retirements and 768 stale-ticket refusals,
with exact full register/stack state. This replaces the obsolete adapter's
E1/E2 phase contract; it does not claim physical pipeline sampling times.

  cmake --build --preset strict --target blofeld-dsp-cmpm-test \
    blofeld-immediate-compare-test
  ctest --preset strict --output-on-failure -R \
    '^dsp_(cmpm_.*|immediate_compare_publication)$'

Repeat with the thread preset for TSan. Exact scope and identities are recorded
in dsp-compare-native-reference.json. SA/SM-specific behavior, silicon boundary
flags, full ISA, normal device startup and complete instrument operation remain
separate open requirements. No fuzzing or physical traffic is part of this gate.
