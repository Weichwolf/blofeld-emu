Native DSP56371 reference execution

The pinned C++ dsp56300 interpreter is integrated through DspCore and DspBus.
Its JIT is disabled in this reference path. No host synthesizer or host bootstrap
loader supplies executed DSP program words. Original chip data remain external
local inputs. The headless CLI is still MCU-only; combined board scheduling and
host MIDI/audio are not implemented by this library integration.

Native adaptation
patches/dsp56300-reference-bus.patch adds unconditional board-owned memory hooks,
a custom peripheral dispatcher and a bounded execReference entry. Each DO body
instruction yields independently. Positive REP counts also yield per body
instruction, retaining the latched opcode/extension until repetition ends. A
normal revisit sees subsequent code changes. Zero/nested REP, unsupported repeat
control flow and undefined opcodes fail explicitly; this is not full ISA proof.

Program fetches and actually used extensions are checked through the strict bus.
Lookahead may inspect unknown bytes without granting execution permission. Native
program stores no longer perform a synthetic read of their previously unknown
target. Native exceptions can propagate to an address/PC/OMR diagnostic; a rejected
CPU state requires reset. Native reset/interrupt entry incorrectly cast full SR
masks into the smaller CCR enum; UBSan caught this during reset. The patch selects
the correct SR-mask overloads, with instrumentation retained.

Reference bit instructions use a peripheral bit-access hook. For GPIO, BCLR/BSET/
BCHG preserve untouched unknown latches; BTST/bit branches require only their
selected bit. The previous bit must be known when it supplies Carry or a branch.
Effective addresses are evaluated once and reused for writeback. TCSR RMW
preserves full writable-word effects, including unselected W1C flags, while
ignoring read-only DI on writeback. Other memory and peripherals retain normal
word accesses, with no extra destructive reads.
Normal interpreter/JIT bit paths are not changed or qualified by this adapter.

DSP56371 memory and peripheral scope
- Independent P/X/Y windows, 24-bit values/addresses, missing-content tracking,
  ROM protection and RAM retention on external reset are modeled.
- The initial 4K P / 36K X / 48K Y RAM map and 64K P / 32K X / 32K Y ROM windows
  follow DSP56371UM chapter 3. Missing ROM contents fail, including X/Y tables.
- MS=1, MSW1=MSW0=1 switches the upper 8K X RAM to P, preserving physical contents.
  The three instruction-cycle delay is explicit. Affected accesses before supplied
  switch time fail. Other switched layouts remain unsupported.
  The linear X:10000..11fff to P:1000..2fff word correspondence is inferred from
  the window sizes; its physical word order still needs hardware calibration.
- SHI uses the separately tested model in dsp-shi.txt. Only the disabled IPRC/IPRP
  state is accepted; enabling CPU interrupt priorities fails pending integration.
- OGDB writes latch the 24-bit debug value (DSP56300FM 7.2.4/7.2.5). DSP reads,
  JTAG/debug commands, security behavior and debug interrupts remain unimplemented.
- PCTL command/reset state and requested EXTAL ratios follow DSP56371UM chapter 5;
  see dsp-pll.txt. Hardware reset samples observed PINIT, while the DSP RESET
  instruction resets SHI/interrupt state without resetting CPU OMR or PLL control.
- C/E/F GPIO modes, data/pads, unknown latches and Port F's required BIU setup
  are modeled (dsp-gpio.txt). BCR accepts only its documented Port F setup.
- Mode-zero timer counters, shared internal prescaler, TIO GPIO and flag/source
  behavior use explicit CLK/2 events (dsp-timers.txt). Native TIO1 polling and
  TCSR W1C word writeback are tested. No CPU/IRQ clock schedule is implied.
- Port D GPIO, other timer modes, ESAI, DMA, NAND and clock scheduling are not modeled.
  Native power-up register undefined-state tracking and full derivative reset,
  interrupt, pipeline and instruction-cycle fidelity need further validation.

Independent synthetic tests
  build/strict/blofeld-dsp-test

Checks cover physical RAM/ROM boundaries, unknown reads, protected writes, the
explicit memory-switch deadline and retained aliases, mode-five reset vector,
addition/negation/flags, strict extension fetches, original P stores into unknown
RAM, opcode/operand changes, REP latching and bounded DO waits for separate SPI
words. Changing backing ROM in a REP cache regression checks the interpreter's
coherence contract; it is not a physical ROM programming or prefetch test.
Short immediates are checked against DSP56300FM's destination-dependent fractional
versus integer alignment, including a full 24-bit register-specified REP count.
Native RESET and external reset independently check SHI, PCTL and memory-map
retention/restoration; these do not establish complete derivative reset fidelity.
Own native MOVEP/BCLR/BSET sequences drive port C pins and sample explicit port E
input levels. The original first-stage GPIO sequence is not reached by this test.
Mixed-state native bit regressions check C/F addressing, Carry, BRCLR/JSET input
polls, postincrement, ordinary RAM operations, exactly one FIFO read, bit 23 and
an invalid bit-24 encoding. Unknown selected bits and whole PDR reads still fail.

Document-derived SPI bootstrap reference
DSP56371UM Appendix A publishes the SPI path, but references a separate EEPROM
file and other ROM content is not supplied here. The optional fixture assembles
only the 58-word prefix at P:ff0000..ff0039. Page headers are removed and equivalent
label-colon syntax is used; instruction text is retained. The omitted EEPROM entry
uses the separately published address, and the following burn-in entry retains
its source position. Their bodies, main program ROM and X/Y ROM are unknown.
This prefix is not a stock hardware ROM dump or complete mask-ROM image.

After downloading verified references, supply dsp56300-asm 1.0.0 from
https://github.com/xemu-project/dsp56300/releases/tag/v1.0.0 and pdftotext:
  python3 tools/extract_nxp_spi_bootstrap.py --assembler /path/to/dsp56300-asm
  ctest --test-dir build/strict -R original_dsp_boot --output-on-failure

The tool records identities and creates only ignored doc/local/ outputs. The
assembly tool release identity is in doc/dependencies.json. Test assets are
SHA-256 checked before execution; absent private inputs explicitly skip the test.

The fixture starts native mode-five execution at ff0000, then a host pin fixture
clocks the MCU-embedded original 94-word Blofeld first stage through SHI. The
executing ROM instructions receive the length/address, run their own DO loop,
write all 94 P words and jump to P:6a. No host writes P RAM, patches the image or
changes PC after reset. The original first stage programs PCTL and performs 8192
long-memory stores, clearing every low mapped X/Y word pair. After 13015 completed
reference steps, PC is 72, R4 is 2000 and LC is 1e000. The short immediate loaded
into X0 is fractional 020000, so REP attempts 131072 stores, not two. Continuing
reaches reserved Y:002000 and fails visibly with PC/OMR context. The manual gives
the reserved map but does not establish that a write there is safely discarded or
cannot alias another block. Actual reserved/ROM write behavior requires stronger
evidence; no broad RAM allocation, dropped-write shortcut or loop skip is used.
The public regression stops before that access, without requiring an unsupported
access to remain unsupported. GPIO/NAND startup has not yet been reached natively.

The host supplies pin events with explicit instruction interleaving. The original
MCU is not the sender in this fixture, no elapsed DSP/MCU clock ratio is
inferred, and no physical Blofeld has validated the route/timing. Native caches
currently cover the 24-bit program address space and use substantial memory;
these diagnostic runs provide no real-time audio performance claim.

A separate original-MCU regression now executes reset/application and captures
its complete 97-word GPIO transfer, including the trailing word, under explicit
PU0/PB input observations. It does not drive this native DSP fixture: the initial
SS/SCK transition is unordered at the current GPIO observation granularity.
See mcu-boot.txt for reproducible checks and the remaining timing qualification.

Offline DSP bus/model fuzzing
  cmake --build build/fuzz --target dsp-model-fuzz
  mkdir -p doc/local/dsp-fuzz-corpus doc/local/dsp-fuzz-artifacts
  python3 tools/make_dsp_fuzz_seeds.py doc/local/dsp-fuzz-corpus
  build/fuzz/dsp-model-fuzz doc/local/dsp-fuzz-corpus -artifact_prefix=doc/local/dsp-fuzz-artifacts/ -max_len=2304 -max_total_time=60

The expanded synthetic campaign completed 38124 runs in 61 seconds without
sanitizer findings. The model harness also exercises PCTL commands, PINIT
observations and clock-target queries. GPIO pad observations and peripheral
reset, masked writes and peripheral bit requests are included. Timer clocks,
prescaler state, TIO observations and source acknowledgements are included too.
It covers bus/map/ROM/reset/SHI/PLL/GPIO/timer inputs, not arbitrary
native DSP instruction streams or the complete board. Sustained and differential CPU
campaigns, actual NAND/assets, full application/audio and hardware comparison
remain required; see coverage.txt.
