Direct internal DSP data storage

DspBus::data_windows exposes sorted low RAM, readonly data ROM and stable high
RAM for X and Y. OwnDspIo grants those exact words and knowledge bytes to the
native core. No copy or initialization fills unknown cells. Code and data
remain separate; peripheral accesses, holes and protected stores retain the
actual bus route, including its explicit functional-policy behavior.

Low X/Y RAM ends at $3000/$2000. Data ROM spans $4000..$bfff; high RAM starts
at $c000 and ends at the current map's X/Y extent. During a pending three-cycle
memory switch, only the intersection of old/new extents is granted. After the
switch, relocated X storage is no longer visible through a writable X alias.
The existing unqualified Y-to-P program relocation still fails visibly.

Views borrow bus storage and remain valid until mapping revision or paired
restore. The Core rebinds after code/map changes and checkpoint restore; it
checks actual known bytes before reads and marks native stores known. Ordinary
owner data writes and data-ROM installation need no code invalidation.

Full-access read/write observers require actual callbacks. Their unclocked
owner invalidates grants on attachment and detachment, including warmed code.
Captured staged effects keep their existing genuine access route. The separate
peripheral-only frontend observer remains an integration requirement for the
connected fast scheduler; no whole-instrument speed result follows here.

The directed gate passes 462 independent checks in Release and both sanitizer
profiles. Nine affected groups per sanitizer profile retain reset, IRQ, complete
checkpoint, callback lifetime/fault/reentry and native bus behavior. Source and
binary identity, sealed provider reuse and scope are in
dsp-data-windows-reference.json. These are authored diagnostics, not manufacturer
programs or a complete Desktop/Keyboard startup qualification.

Reproduce the focused gate:

  cmake --preset strict -DBLOFELD_OWN_DSP_ONLY=ON
  cmake --build --preset strict --target blofeld-dsp-data-windows-test blofeld-dsp-native-bus-test
  ctest --preset strict --output-on-failure -j1 -R '^(dsp_data_windows|dsp_native_bus)$'
