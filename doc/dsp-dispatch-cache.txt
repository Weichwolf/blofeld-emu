Dispatch storage and independent DSP program boundaries

dsp_dispatch_cache executes literal authored programs through the independent
dsp56300 core after actual Mode5 reset. It checks JMP(R0) at P:ffffff without
an extension read, full register/flag/progress preservation and its three base
cycles. A MOVE immediate crosses P:3ff/400; changed operands and destinations
take effect, and joint restore recovers the original program. Two fresh owners
replay the restored suffix with identical CPU, fault, progress and clock state.

The separate generic DspDispatchCache container checks remain unchanged: sparse
1024-word pages, cold probes, stable pointers, partial pages, bounds and reset.
That legacy host container is not the independent core's decoder implementation
and these tests do not establish physical instruction-cache behavior.

  cmake --build --preset strict --target blofeld-dsp-dispatch-cache-test
  ctest --test-dir build/strict -R '^dsp_dispatch_cache$' --output-on-failure

ASan/UBSan and TSan pass with zero compiler/format/tidy findings, hardened ELFs
and no foreign DSP/assembler symbols. Evidence: dsp-dispatch-native-reference.json.
Canonical object rules and generated link commands were used; legacy Ninja
link-dependency cache repair, real-time execution and complete boot are unqualified.
