DMA controller writes beside program prefetch

The native F2 owner now admits genuine X-space DMA controller word writes beside
program fetches, as it already admits controller reads. The controller register
port is distinct from P memory (DSP56300FM chapter10 register map/figure10-1).
The bus arbiter and native DMA handlers retain all transactions, clock ordering,
busy-channel checks and read-only/unknown-state refusals. Atomic bit effects do
not acquire word-write permission.

The explicit reference order advances DMA before F2/native work. A held word
retains its captured payload; an available destination commits before the native
controller write. Clearing DE preserves an already captured word until its later
grant. This is a functional ordering, not measured silicon bus timing.

The authored matrix covers all28 writable registers in quiet, held-destination
and committed-destination states under native-cycles and reference-effects.
Two further cases retain the contextual read-only-status resource refusal.
Each of170 cases has same-owner and fresh-owner checkpoint continuations.
The official assembler independently confirms all29 high-X instruction forms.
Checks include complete CPU/flags, literal register values and instruction costs,
actual F2 captures/clocks, old DMA payloads, busy-write faults and later grants.
