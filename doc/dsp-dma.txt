DSP56371 DMA reference phases

Sources: DSP56300FM Rev.5 chapter10, DSP56371UM Rev.2.1 tables3-7/4-7,
and NXP APR23 sections1/2. Local PDFs stay ignored; sizes/URLs/SHA-256 are in
doc/hardware/sources.json. APR23's explicit linear-copy example resolves the
ambiguous dash before1 in Family Manual table10-6: DAM101 increments by one.

The component implements six channels, four shared offsets, documented register
addresses, known/unknown preloads, regular request edges, priority/round-robin
selection, separate source-read/destination-write phases and explicit wait grants.
Counter modes A/B/C/D/E, independent source/destination address modes, modular
24-bit addressing and counter reloads follow tables10-2/3/4/6/7/8/9. Offsets replace
the ordinary increment at a line/plane boundary. DE clear retains a captured word
request and an already-read word until its real destination access completes.
Busy address/counter/offset/configuration changes reject; DIE may change without
reconfiguring a transfer. Word modes1/5,
request-driven line mode2 and software-triggered block mode3 are supported;
other modes and DCON reject when enabled. DIE enables real end-of-block and
explicit-stop interrupt events on each channel (dsp-dma-interrupts.txt).
Unknown preloads, reserved
spaces/modes/request sources and missing
inputs fail visibly. Reset DSTR is00003f; DE's DTD clear has the documented three
additional reference-cycle delay. Repeating-mode DTD lifetime after a block is
unqualified: reads selecting that bit reject until explicit disable completes.
Qualified masked status-bit reads still work without inventing the unknown bit.
Before the first reference-cycle sample, each never-enabled channel's reset DTD
and all reserved-zero fields remain independently readable. A cold enabled
channel still rejects reads selecting its DTD or the shared DACT/DCH fields;
a whole DSTR read therefore still fails. A status mask cannot manufacture elapsed
cycles, a request, a grant or a transfer for another channel.

DspDma::advance requires reference_sampled_cycles, consecutive caller-owned cycle
indices, explicitly known request levels and an available/wait bus grant. External
edges require a known baseline. APR23 section5.6 permits either initialization
order: a peripheral's held request also survives late DMA enable and is captured
on its first explicitly known sample. No unknown input becomes an asserted request.
Regular requests cannot silently queue a second word before the first is served.
Only one channel occupies a word transfer, including wait cycles. A higher-priority
request waits for its predecessor's destination phase. No CPU instruction, PLL
value or elapsed host time supplies missing cycles/grants. Initial round-robin
choice and sampled-edge phase are reference conventions, not measured silicon
pipeline/arbitration latency. Controller state commits only after a successful
phase. External I/O callbacks must fail without side effects; rollback of an
arbitrary callback's outside state is not provided.

DspBus routes native register accesses and provides explicit advance_dma phases.
It derives requests10/12/22 from actual DAX XADE and ESAI/ESAI_1 TDE without
reading XSTR/SAISR or arming underrun clear. IRQA..IRQD request snapshots may be
supplied explicitly; other request routes remain unsupported. RAM/ROM accesses
use the strict bus;
peripheral writes currently admit ESAI TX and the three DAX data destinations:
XNADR at X:ffffd1 and the XADR aliases at X:ffffd2/3. DAX data now enters actual
buffers/metadata (dsp-dax.txt); a full XADR write fails visibly. GPIO, peripheral
status/configuration DMA and unimplemented peripheral sources reject.
Unknown/protected/unmapped memory is
never supplied as zero or silently discarded. DspMachine adds current native
PC/OMR to phase errors; trusted owner checkpoints include all DMA state and the
held source value. Source cursor/receiver state remains caller-owned.
The memory-footprint arbiter now also admits these actual peripheral writes
against qualified core RAM/ROM use and read-only DMA-controller inspection
(dsp-bank-arbitration.txt). Core data-peripheral occupancy, controller writes,
unsupported I/O and automatic native timing remain separate refusals.

This is a standalone instruction/peripheral reference experiment. Automatic
clocked native execution rejects an active DMA channel: core/DMA bank contention,
per-cycle instruction bus accesses, request synchronization and dynamic internal
deadlines still need integration. Explicit phases do not establish those facts.
The separate bank arbiter resolves real storage/OMR aliases and can admit or
delay the selected phase against explicitly supplied reference core occupancy;
it reports held-word core stalls (dsp-bank-arbitration.txt).
Native semantic bus observations are available (dsp-native-access.txt); they do
not yet supply arbitration timestamps or stalls.
No physical HCKT/core frequency, original DMA execution, physical DAX output, PCM transport,
full original boot or hardware equivalence is established.

  cmake --build --preset strict --target blofeld-dma-test
  ctest --test-dir build/strict -R '^dsp_dma$' --output-on-failure

Literal manual tables check every pre-transfer counter/address in all three
triple layouts on both endpoints, dual/linear modes and24-bit wrap. Sixty-five
real source reads check the64-word ring, reload and first reused word. Separate
tests cover all six equal priorities, higher-priority arrival between phases,
held-data replay, denied grants, DE clear before/after source read, faults and
strict input/configuration rejection.

Every combination of enabled channels and nonempty DTD masks is also checked in
both request-driven word and software block modes (8064 fixed mask cases).
After those queries, exactly three explicit waited cycles clear only the enabled
DTD bits without any I/O. A further 144 own native MOVEP/BTST programs cover every
status bit with each channel enabled: known fields change only Carry/PC;
unknown fields retain contextual failure and do not retire the instruction.
Own unclocked native MOVEP programs configure
both ESAI maps and DMA registers. Explicit HCKT observations and DMA grants feed
an opposite-edge receiver;66 complete serial words and every actual RAM/TX transfer
match independent expectations, including ring wrap. A checkpoint between the
first source read and destination write reproduces that stream. A separate same-
edge DMA0/DMA3 test proves a real ESAI refill cannot swallow a full-XADR failure. An
independent map test distinguishes all three DAX data addresses from forbidden
status/control DMA. A real
clocked native DE write faults instead of bypassing unsupported bus arbitration.
These bounds and explicit reference phases do not qualify original firmware audio.
An isolated original voice/mix/master composition now supplies finite DMA0
transfers and pin-decoded frames (dsp-voice-pcm.txt); original repeating DMA
and automatic core arbitration remain unqualified.
Consecutive original foreground iterations now consume an enabled repeating
ring under explicit untimed admissions/paused-core serial phases (dsp-foreground-ring.txt).
This does not qualify the original initialization or automatic physical timing.
The DAX fixture independently checks native two/three-register line transfers,
per-line requests, destination rewind and DE clear before/after a line starts.
