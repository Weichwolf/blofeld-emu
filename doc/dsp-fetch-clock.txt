Automatic DSP program-fetch reference clock

OwnDspFetch drives the independent dsp56300 core. Each completed
advance_dma_pipeline or advance_dma_automatic call orders actual DMA admission,
old F2 sampling, one selected native effect, new F1 address generation, then
SHI/map delays and CLK/2. The caller supplies external DMA requests/grants and
the next DMA index; it supplies no program words, CPU results or elapsed-cycle
chunks. The pipeline entry can hold CPU admission while continuing fetch and
peripheral clocks. OwnDspTimeline additionally owns absolute deadlines and
failure quarantine. This is not the complete seven-stage CPU.

Successful captured-fetch and DMA periods do not format fault context strings.
Formatting is deferred until a failing guard or caught exception; the retained
PC/OMR snapshot and diagnostic text stay the same. Existing own_dsp_fetch,
own_dsp_clock, dsp_observed, dsp_reserved_write_decoder and reference_pipeline
groups pass under ASan/UBSan and separate TSan. An authored100000-period NOP/JMP
loop gives local ASan/UBSan medians of1.567s before and1.333s after in three
interleaved pairs, with identical native state/counts/ticks. This is an isolated
performance observation, not original-instrument throughput or a real-time claim.

DSP56300FM Rev5 sections2.3.1/Table2-1 and5.3/Table5-1 distinguish F1 address
generation from the following F2 memory read, with one fetched word per clock.
The first cycle only issues F1. Subsequent cycles can sample the previous F2
and issue the next F1. The eight-word host continuation bound applies real
backpressure; it is not evidence for silicon queue depth. Actual captured
opcode/extension consumption remains that of the underlying frontend
(dsp-program-fetch.txt). No extra P read is invented for an already captured
word, including zero. Native register publication, PC publication and retirement
are separate observed boundaries; the reference profile does not collapse them
into the old backend's single-cycle completion.

A held DMA destination stalls selected native/F2 work and new F1, including
the cycle that commits the destination. Completed stalled or backpressure
cycles still advance peripheral delays and CLK/2, retaining the odd residue.
An actual native OMR memory-switch publication does not consume its own delay:
three subsequent completed clocks are required. End-of-cycle peripheral
sampling is an explicit reference order, not measured physical bus placement.

Each cycle latches the current PCTL requested EXTAL ratio. Exact integral
timebase ticks are committed only when the cycle completes. Unknown PINIT,
nonintegral rates and counter exhaustion refuse rather than round. These
digital command ratios do not establish analog PLL lock or Blofeld clock rates.
The test epoch follows genuine mode5/PINIT-low reset and native MOVEP setup;
that setup is explicitly untimed. A stopped-CPU DMA request observation at the
epoch is not an elapsed clock. Actual elapsed time retains reset hold/recovery,
while completed reference-cycle and CLK2 totals begin at zero.

Automatic cycles share one current native pending snapshot between fetch holding
and effect admission. It stays local to that cycle; accepted I/O and CPU
publications still execute natively.
Fetch eligibility checks precede otherwise unused register snapshots. Program
write hazards still inspect issued and buffered addresses.

Joint checkpoints retain native execution, captured words, issued F1, DMA,
timer/PLL/map state, reference time and divider phase. Trusted snapshots are
portable to a compatible machine and clock contract. A fresh process-local
execution capability detects machine-only restore even when every exposed CPU
field is identical. It is unrelated to persistent device identity. Changes to
clock/epoch, fetch identity or DMA index refuse coordinated continuation.
A live timeline also owns chip execution and reset/time controls through an
independent process-local lease. Direct chip fetch/effect/IRQ/period/DMA/reset
calls refuse before mutation, even when a partial PCU update would not change
instruction counts or clock/epoch fields. Timed native effects still advance
through the captured frontend's real cycle path.

The lease is excluded from checkpoints. Joint restore binds a fresh lease;
held reset and recovery preserve it. Timeline destruction or an explicit
chip-only restore releases scheduling authority, allowing genuine unclocked
chip use. Retaining an immutable snapshot cannot keep a destroyed lease alive.
Private allocation identities are compared without acquiring strong references.
Internal deadline calculation reuses the checked boundary; public entries retain
all ownership, reset, clock/epoch and DMA-index validation.
This is host API ownership, not a replacement for device identity or firmware
execution. The focused regression checks actual PCU publication, both native
X/Y stores, direct control refusals, same/fresh restore and manual continuation.

  cmake --build --preset strict --target blofeld-timeline-ownership-test
  ctest --test-dir build/strict -R '^dsp_timeline_ownership$' --output-on-failure

An entered timeline cycle failure quarantines its owner, preserving already
admitted effects and refusing another advance or checkpoint. This includes a
period that becomes unrepresentable after a PLL command; no DMA/CPU/clock effect
is admitted in that case. Invalid observation boundaries remain preflight errors.
Completed time is a prefix, not permission to retry partial effects. Diagnostics
include PC/OMR, attempted time and the underlying address/operation. Trusted
joint restore recovers the owner. A timeline requires reference-cycle clock
switching before acquiring ownership; it cannot replace an instruction-boundary
clock contract. Matching rebuilt headers and libraries are required.

  cmake --build --preset strict --target blofeld-fetch-run-test
  ctest --test-dir build/strict -j1 --output-on-failure -R '^dsp_fetch_run$'

Authored literal instructions use actual native MOVEP setup before the test
epoch. Independent register/address/clock expectations cover F1/F2 latency,
capacity backpressure, DMA waits/writes, timer compare/CLK2 edges, native OMR
delay, sampled zero/unknown opcode/unknown extension retention, partial failure
and joint replay. PLL cases alter the model command directly; they do not
qualify native PCTL stage placement. Guards check unknown PINIT, nonintegral
periods, invalid/duplicate owners, portable independent continuation,
machine-only restore and preservation of rejected clock contracts.

Digital reset hold/recovery

OwnDspTimeline.begin_hardware_reset asserts real native reset at its current
completed reference boundary. It retains lifetime time and clock units while
cancelling pending effects and the captured frontend. A later observed horizon
cannot be used to assert reset retroactively. Stable mode5/PINIT-low and at
least two bypass EXTAL recovery periods are required; invalid inputs leave the
old owner intact. Entered reset failures quarantine continuation.

The native chip resets documented PC/SR/OMR/stack-control/modifier fields and
retains unaffected registers and completed RAM stores. Held/recovery time
executes no CPU effect, DMA phase, F1/F2 read or timer CLK2 edge. Exact fractional
EXTAL phase survives checkpoints; release starts the supplied recovery interval.
Recovery clamps at its endpoint before a fresh F1 and CLK2 divider epoch, while
lifetime cycle/tick/reset/CLK2 ledgers remain intact. Gated execution requests
refuse before mutation; an unchanged-time observation consumes no reset time.

  cmake --build --preset strict --target blofeld-fetch-reset-test
  ctest --test-dir build/strict -j1 --output-on-failure -R '^dsp_fetch_reset$'

Twenty cycle cuts reach actual MOVE/ALU/PCU/retirement boundaries. Forty
same/fresh-owner suffixes compare full native state, pending effects, actual
F1/F2 observations, outcomes and time against literal register/flag/ADD/JMP
expectations. FM table A-1 supplies base costs2/1/1/4 for immediate MOVE,
CLR, ADD and long-absolute JMP; these remain separate from reference periods.
Recovery snapshots, repeated resets, invalid pins/timing,
retroactive assertion, stale tickets, early release and duration overflow are
covered separately. Four long-store cuts check pending X, completed X/pending Y,
both completed writes and real retirement, including fresh-owner held-reset
recovery. These are explicit staged bus cuts, not measured simultaneous silicon
ports or calibrated asynchronous reset placement. These checks qualify the
chip/frontend timeline; connected MCU reset-net routing remains separate.

Legacy automatic-pipeline qualification

The remaining automatic seven-stage fixtures still use the former backend.
They describe their original harness and do not qualify the independent runtime.
A separate legacy original1.25 loader run retained all94 received words and
reached the9777period Y002000 refusal after91hold+135recovery ticks. It used
document ROM and between-period SPI input, not authentic full ROM, connected
original MCU reset wiring or successful boot. Its older binary evidence does
not qualify the migrated reset test above.

The explicit_effects profile still selects backend begin/admission explicitly.
Separate automatic ALU and selected memory profiles own decode/AG1/AG2/E1/E2
(dsp-automatic-alu-pipeline.txt, dsp-memory-pipeline.txt). General simultaneous
X/Y/P groups, all interlocks, loop/REP and IRQ timelines,
physical stage timestamps and default runtime integration remain open. Native
exceptions/checkpoint allocation are not a real-time callback implementation.
Authentic full ROM, reserved Y:002000 semantics, full original boot, normal
MIDI/audio and complete Desktop/Keyboard hardware acceptance remain incomplete.

An explicit matching access_and_retirement_boundaries execution choice can now
hold actual completed native results separately from their last bus access.
Candidate/redirect checkpoints and clock integration: dsp-retirement.txt.
