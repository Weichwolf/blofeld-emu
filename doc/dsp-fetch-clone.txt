Trusted native snapshot transfer

OwnDspFetch, OwnDspTimeline and McuDspRuntime checkpoint constructors restore
trusted in-process CPU, bus, pending computation, fetch and clock state through
dsp56300. They do not query external input, execute instructions or alter distinct
source owners. External callbacks and source cursors remain caller-owned.

The tests select an explicit effect-per-reference-cycle timing hypothesis.
Silicon pipeline placement and physical reset wiring remain unqualified.

Clone targets must have matching MCU/DSP clock and instruction-backend contracts.
The joint external binding retains its identity, order, budget and callback
presence. Restoring a saved state constructs a new owner; explicit replacement
revokes the superseded fetch/timeline authority. Address reuse after source
object destruction does not substitute pointer equality for ownership.

The original nonzero event floor and any pinned next deadline survive transfer.
Cursor consistency is checked on actual subsequent execution, after the caller
has restored its own state. A lower timeline can retain an excluded reference
boundary and later execute its exact F1 period once. Its caller owns external
events; joint checkpoint tests separately retain pending and exhausted sources.

Construction may modify disposable targets before a later failure. An outer
board must stage replacement owners, attach observers without invoking them,
and publish the complete replacement only after successful preparation. This
API does not promise atomic rollback of arbitrary existing targets or external
I/O. MCU restore drops observers; reattach them before execution. Host PCM and
USB sessions require their own lifecycle handling.

Directed tests cover ten early native F1/F2/effect cuts, twenty24-period suffixes,
independent MOVE/CLR/ADD results and ten interleaved24-period forks. Eight joint
held/released/recovering/running profiles have sixteen complete suffixes with
actual initial MCU POR, minimum DSP reset hold and two-period recovery. OSC
phase4 uses three MCU reset edges to satisfy the DSP hold; it preserves the
fractional clock residue. Literal MCU periods, all CPU registers/progress,
pending effects, available fetch views, observed F1/F2 and reset/CLK2 ledgers
accompany the replay comparisons. Explicit RAM writes distinguish deep copies.

Nine malformed-binding/clock/empty-snapshot controls preserve the live source
and never query input. A late DSP-clock mismatch may retain the already restored
disposable MCU; no joint owner is published. Same-address transfer, revoked
owners, deferred stale input and both nonzero event-floor profiles are checked.
Late attachment retains actual DSP hold from zero; the first real MCU period
completes recovery and the next three admit exactly six native DSP periods.

ASan/UBSan and separate TSan cover these single-threaded owners. They do not
establish concurrent access safety, full instrument boot or real-time performance.
The reference Board stages native transfer separately (reference-pipeline.txt).
