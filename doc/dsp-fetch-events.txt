Native MCU/DSP external event timeline

The regular Board uses McuDspRuntime with the independent dsp56300 core and
OwnDspTimeline. The dsp_fetch_external_events group now uses that same owner,
actual HCS12 NOP periods and authored literal DSP instructions, without the
legacy DSP executor or assembler. Remaining DspFetchScheduledRun callers are
legacy fixtures; this group no longer qualifies that implementation.

Each native cycle or reset-recovery completion re-queries the external source
before another native event. An asynchronous edge created by a DSP completion
must be observed before the next DSP cycle, including two DSP cycles within
one MCU bus period. Simultaneous events require DSP-first, peer-first or strict
refusal. Recovery participates in this arbitration without inventing a CPU,
DMA or CLK2 cycle. A peer-first callback at recovery completion still sees
held reset one integer tick before the release edge.

The source contract is fixed at construction: shared identity, pure next_ticks,
observation callback, explicit order and positive per-MCU-period budget.
Exhaustion retains the contract. A pending deadline cannot move or disappear.
Finite same-timestamp bursts preserve source order; backwards/retroactive edges
and newborn same-tick events preceding their actual DSP cause refuse.
Observations may change peripheral inputs, never CPU/time/frontend ownership.
Callback guards also detect chip-only restoration with identical visible state,
including held reset. They do not prove purity of every arbitrary callback side
effect. Entered failures quarantine the runtime and retain its committed prefix.

Joint snapshots retain pending/consumed boundaries and both native machines.
The caller restores its event cursor and reattaches observers; callback closures
are not serialized. A fresh compatible owner can continue a trusted snapshot.
Identity/order/budget mismatch refuses before native restoration; a mismatching
pending source refuses on the first offer after the caller restores its cursor.
Use a staged target because restored
native state and external effects are not rolled back after an entered failure.
Snapshots require consumed MCU operation boundaries, never half an operation.

  ctest --test-dir build/strict -j1 --output-on-failure -R '^(dsp_fetch_external_events|mcu_dsp_runtime)$'

Independent expectations use 450 common reset ticks,135 recovery ticks,45 ticks
per DSP cycle and90 per MCU bus period.18 MCU NOPs reach2070 ticks:33 native
cycles,15 retired DSP NOPs and16 CLK2 edges. Actual MOVEP reads capture GPIO
at separate read effects, retaining values across later pin changes before
PCU/retirement. Replays cover both source orders, same and fresh owners and
held recovery. Existing mcu_dsp_runtime checks all six causal MCU-write/input/
DSP permutations and both cyclic refusals using a genuine MCU GPIO store.

These are explicit reference-effect timing checks, not measured seven-stage
silicon placement or complete original Desktop/Keyboard boot, MIDI/audio,
USB, persistence, update/recovery or real-time acceptance.
