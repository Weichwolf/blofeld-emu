Legacy MCU-period / automatic DSP-pipeline fixtures

The regular Board now uses McuDspRuntime and the independent DSP timeline.
Its migrated external-event regression is described in dsp-fetch-events.txt.
The basic shared-write and DSP-reset groups also use McuDspRuntime now;
see mcu-dsp-reset-control.txt. Other records below concern remaining legacy
McuDspFetchSchedule fixtures and do not establish native-runtime coverage.

McuDspFetchSchedule orders DspFetchRun pipeline periods against actual native
MCU period offers. It is separate from the instruction-completion reference
contract in McuDspSchedule. It does not own MCU steps, observers, GPIO routes
or a physical Blofeld profile. DspFetchRun::next_cycle_ticks validates its bound
inactive native owner without consuming a pipeline, DMA or peripheral period.

The caller supplies integral clocks, a common-time release epoch, an explicit
per-MCU-period DSP budget and native DMA/cycle inputs. Shared one-byte writes
must be identified before their native period and observed after consumption.
DSP periods before the write are completed first; an exact tie requires an
explicit MCU-before-DSP or DSP-before-MCU policy. No physical ordering is
inferred. Missing observations, invalid geometry, changed/unconsumed native
periods, reentry and execution errors reject and quarantine the owner.

Current scope is automatic_memory execution during ordinary MCU instructions
and native WAI periods. WAI requires wait_order=dsp_before_mcu; the default
unqualified contract still refuses entry. The caller attaches begin_wait_period
to the committed native idle hook and calls end_wait after each bounded slice.
Cancelled pre-commit IRQ/input offers consume no DSP period. A pin IRQ supplied
inside a committed DSP period takes effect before the next native MCU boundary
without cancelling the already committed interval. This is explicit reference
ordering, not measured silicon latency.

COP/reset time requires reset_order=dsp_before_mcu;the default unqualified
contract refuses. A native COP deadline shortens its IPBus offer and completes
DSP periods through that time before the MCU latches the actual timeout.
The incomplete MCU bus/idle period is not counted. begin_system_reset enters
actual MCU drive/synchronization/settling edges;reattach native observers after
MCU owner replacement. Supply observed RESET-pad inputs and explicit3..6 SYSCLK
synchronization. Native vector fetch chooses FFFA(COP) or FFFE(external).
DSP execution/time continue;physical DSP-reset wiring remains separate.
External input now uses one DspFetchScheduledRun owner for both native periods
and peripheral events. Bind its retained source at construction. Non-shared
native offers deliver due external observations before MCU completion; shared
writes require an explicit external_write_order at actual collisions. Together
with shared_write_order and the source's DSP/external order, all six causal
permutations are supported. Cyclic/unqualified orders and retroactive newborn
events refuse; callbacks cannot mutate either CPU or its clocks.

Future DSP epochs retain early input at the current MCU boundary. Input before
the initial MCU owner boundary refuses; the legacy post-vector MCU fixture boundary still excludes its initial five
vector periods. A fresh MCU created with McuPowerOnInputs can instead join while
held at zero, with explicit reset_order=dsp_before_mcu. Every initial SYSCLK and
native vector period then belongs to this owner. Normal reference::Board
pipeline/event integration remains open. Joint snapshots
capture native/timeline state and source identity; restore the caller's event
cursor and reattach native observers separately.
No real-time guarantee or measured physical timing is established.

The original1.25 reset/SPI regression now uses McuDspRuntime and dsp56300 too.
Its explicit initial-held DSP is connected before the first MCU firmware

See mcu-dsp-original-reset.txt for exact times, ROM provenance and acceptance

Trusted joint checkpoints capture both native machines and pipeline/clock ledgers
at completed instruction,WAI-slice or active reset-edge boundaries. Restore
requires the same native owners and exact input contracts. Reattach MCU observers
and restore caller-owned wiring/transport/audio event cursors before advancing.
Snapshots are immutable in-process objects,not a serialized state format.
Early owner/contract/reentry rejection preserves state;an admitted native restore
failure quarantines the schedule. No joint atomic rollback is promised.
