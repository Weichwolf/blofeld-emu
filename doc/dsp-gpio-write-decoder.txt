Functional DSP GPIO pin decoder

DspGpio defaults to DspGpioContract::strict. The explicit logical_pins
contract masks register values and write masks to the port's implemented pins:
12 each for C/E, 11 for F and 2 for D. Upper bits have no register storage,
output driver or peripheral ownership. This is a functional instrument model,
not a measured response of reserved silicon fields.

Validate the original 24-bit word/mask before pin decoding. Invalid host words,
values outside the supplied mask, unknown input samples and strict BIU
diagnostics still fail. Strict mode rejects reserved Port-F configurations.
The logical contract retains transient PCRF/PRRF overlap while firmware changes
the mux in separate instructions; reserved functions supply unknown pads, never
a fabricated peripheral driver. Reading their data or driving an unmodeled
Port-F function still fails. Board-owned pad sources resolve opposing drivers
as unknown; sampling conflicting data fails rather than selecting a winner.
Port F uses logical register/bit access independently of BIU wait-state
qualification. BCR command/read state remains unchanged; no BCR write, bus-master
status or NAND response is fabricated. Strict mode retains its BCR prerequisite.
Reads never acquire guessed external data. Functional PDR writes retain an
output preload even while the pin is input, disconnected or peripheral-owned.
Only later GPIO-output selection drives it. Input reads still require the real
pad. In logical_pins, disconnected reads return only explicitly known PDR
storage; unwritten bits and peripheral-mux reads remain unsupported. No unknown
input falls back to that storage. Strict C/E/F disconnected reads still refuse.
This models data-before-direction initialization and later output-latch bit
operations without inventing a cold reset value, external level or peer. Masked writes preserve unrelated latch knowledge.
Strict diagnostics retain their conservative non-output-write semantics.
Reset clears real configuration and retains the chosen contract; C/E/F latch
history survives and D still resets its latch to zero. Trusted
chip/bus copies preserve the contract, with normal borrowed-pad lifetime rules.

check all 24 bit positions of all three registers on all four ports, mixed and

execute synchronously and through the clock owner; native BSET checks real Carry
and existing/absent pin effects. Additional checks cover transient reserved mux
state, unknown data, unsupported drivers and subsequent defined input/output
operation. Independent PC/flag/pin expectations and fresh
continuations are checked. Firmware programs and private traces remain local.

original_fetch_gpio_start selects both contracts before the original reset. It
executes the full clear, seven immediate GPIO setup instructions and the first
NAND control sequence. All selected RAM, original SPI-loaded words and MCU NVM
are checked. BCR retains its reset value; the original timer1 DI bit test at
PC 0xbb visibly rejects the absent NAND-ready input. Both owners refuse further
execution without CPU/RAM/time changes. Independent instruction, wire, PLL/REP
and endpoint oracles include twelve fixed corruption controls.

Component and connected GPIO checks pass under ASan/UBSan and separate TSan.
The existing strict GPIO component checks also pass, and the original
storage-only reset regression passes again under ASan/UBSan. No fuzzing or
physical traffic is involved. These GPIO checks alone do not establish complete
instrument operation, MIDI/audio or every documented function. See coverage.txt
for connected original NAND loading and later frontiers; dsp-write-decoder.txt
describes the separate storage contract.

Functional disconnected PDR storage

  cmake --build --preset strict --target blofeld-dsp-gpio-latch-test
  ctest --preset strict -j1 --output-on-failure -R '^dsp_gpio_latch$'

Repeat with the thread preset for separate TSan. UM8-47/9-48 calls disconnected
PDR data undefined and says it is not reset. The explicit logical_pins model
retains native writes and reads those known stored bits while the pin driver
is disconnected. This is a functional choice for instrument behavior, not a
silicon readback guarantee. Pad observations remain separate and unchanged;
active-input and peripheral-mux reads retain their own qualification rules.
Unknown reads include control, direction, latch-knowledge and pad-knowledge
context. No firmware address or instruction-specific success path is used.

Seventy directed storage/guard cases per sanitizer cover all 35 C/E/F pins and
both values, strict/unknown/input/peripheral controls, reset and copies.
Another 140 native cases use actual reset, MOVEP and BSET through untimed and
clock-owned execution. Independent literal expectations check the complete CPU
state, PC, Carry, neighboring bits and eventual output selection; 70 fresh-owner
continuations retain the same effects. The same authored clocked E9 sequence
rejects the old model at its genuine unknown read under both sanitizers.
Ten affected GPIO/peer/Board/audio/NAND groups pass per profile, with compiler,
format and tidy checks at zero findings. Source and receipt hashes are in
dsp-gpio-latch-reference.json. No fuzzing or physical traffic is included.
