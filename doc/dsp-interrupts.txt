DSP56371 reference interrupt arbitration and native entry

Primary references: DSP56371UM Rev 2.1 chapter 4, tables 4-4..4-6 and Appendix B;
DSP56300FM Rev 5 sections 2.3.2.3..2.3.2.8, VBA and REP instruction definitions.
The manuals remain private inputs identified in doc/hardware/sources.json.

Implemented subset
X:fffffe (IPRP) accepts SHI[3:2] and TIM[9:8]. Each field encodes disabled,
IPL0, IPL1 or IPL2 as 00, 01, 10 or 11. SR I1:I0 is the actual native CPU mask:
mask 0 admits levels 0..2, mask 1 admits 1..2, mask 2 admits 2 and mask 3 none.
The greatest eligible IPL wins. Ties use the documented fixed order, independent
of source-arrival order: SHI bus error, overrun, underrun, full, transmit, nonempty;
then timer 0 overflow/compare, timer 1 overflow/compare, timer 2 overflow/compare.
SHI bus error has a priority slot but remains an unsupported I2C/master source.
Disabled/masked sources are not probed during arbitration or acknowledgement;
this does not turn unobserved peripheral inputs into known values.

Other IPRP fields/reserved bits and enabled X:ffffff (IPRC) fields fail before
changing controller state. Software RESET and hardware reset disable priorities;
software RESET preserves CPU SR and VBA, while hardware reset restores VBA=0.
Native MOVEC writes preserve VBA's eight read-only zero low bits. The actual
vector address is VBA plus the source's relative vector, without rewriting PC.

DspCore arbitrates at explicit reference instruction boundaries. The native
reference entry fetches two real program words through the strict bus. Unknown
first or second contents fail before acknowledging a timer or pushing a frame.
Once both are fetched, a timer clears only its serviced flag. SHI acknowledgement
does not drain its FIFO or clear errors: the handler must perform the modeled
peripheral's actual read/write sequence. No generic host interrupt FIFO is used.

Both vector words are latched before either executes. A first-slot P store
cannot replace the second instruction in the same entry. One DspCore step
executes at most the two vector words atomically. The separate explicit unclocked
begin_reference_interrupt API can suspend before their actual accesses and
acknowledgement, including a trusted pending checkpoint; see
dsp-reference-execution.txt. A fast vector
executes either two single-word instructions or one double-word instruction,
without advancing foreground PC or implicitly saving SR. A JSR in the first or
second slot enters a long interrupt using the native JSR stack operation. Its
saved return PC/SR are the native values at JSR, after any first-slot effect.
Entry clears S1:S0, SA, LF and FV, and raises SR IPL to source level plus one. Higher-level requests can nest;
native RTI restores PC/SR/SP. Lower/equal pending sources remain pending.

REP defers interrupts throughout repetition, including consecutive REP sequences.
DO is interruptible: the native loop stack, LC/LA and saved LF survive a long
interrupt and resume on RTI. No host SR/PC replacement implements exception entry.
Undefined vector opcodes, unsupported fast control flow, loop/reset/sleep/trap
instructions in vectors, overlong vector instructions and native interrupt stack
overflow fail explicitly. Conditional/relative subroutine calls in vector slots
are outside this conservative subset. A rejected native step requires reset.

Reproducible checks
  cmake --preset strict
  cmake --build build/strict --target blofeld-dsp-interrupt-test
  ctest --test-dir build/strict -R '^(dsp_interrupts|dsp_timers|dsp_shi|native_dsp|original_dsp_boot)$' --output-on-failure

The project-owned diagnostics execute native instructions from reset. Expected
priority/mask combinations, vector order, JSR/RTI encodings and stack/SR effects
come from the manuals, not a second invocation of the tested implementation.
They include all 16 SHI/TIM priority combinations against all four CPU masks,
three JSR placements/encodings at each source level, fast word lengths and status,
SHI FIFO consumption, nested higher-level entry, retained pending timers, relocated
VBA, both reset types, DO/REP deferral/restoration and missing-vector failures.
A self-modifying first vector word checks second-word latching; it fails against
the earlier reread implementation. A first-slot JSR discards its fetched second
RTI word without executing it. Stack overflow rejects before a frame push.
No manufacturer program bytes or physical MIDI/flash transactions are involved.
The model fuzzer exercises priority writes, mask selection and acknowledgements.
The expanded synthetic-seed campaign completed 39720 executions in 61 seconds
without sanitizer findings; it is an initial campaign, not sustained validation.

Limits
This is an instruction-boundary architectural reference, not a physical DSP
pipeline. Interrupt synchronization, recognition/fetch latency, mask-change
latency, DO endpoint pipeline restrictions and entry-cycle accounting remain
unqualified. Neither atomic entry nor semantic access suspension supplies physical
sub-instruction pin timing.
Peripheral clocks still require explicit board inputs; no automatic timer/SHI
clock ratio is inferred. Other core/peripheral sources, DMA, cache behavior,
stack extension and full ISA/derivative reset validation remain outstanding.

These synthetic checks do not advance original DSP startup past the reserved
Y:002000 write, establish original DSP interrupt handlers, complete board boot,
MIDI/audio, update/recovery safety or stock Desktop/Keyboard equivalence.
