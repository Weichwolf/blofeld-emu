Native DSP access observation

DspCore::step(DspNativeAccessObserver) observes actual strict bus operations from
one interpreter step. The existing step() keeps its ordinary behavior. This is
semantic execution order, not a core-cycle, pipeline-stage or physical bus trace.
DSP56300FM sections5.3 and10.2 distinguish those facts: concurrent pipeline stages
and core/DMA memory contention cannot be reconstructed from callback order alone.
The automatic native DMA rejection remains in place.

Each access has a per-step ordinal, starting PC/OMR, kind, target space/address
and before/after stage. Data writes carry the known source value in both stages;
read values exist only after the real access succeeds. A specialized peripheral
bit access includes the bit index/operation and reports its previous bit after
the actual architectural operation. It does not pretend that the indivisible
helper exposes separate physical read/write clock phases.

Opcode, vector and consumed extension fetches have distinct kinds. Decoder lookahead is
not an access; unknown lookahead does not fabricate an instruction operand. The
prepared native dependency has a separate optional readExtension hook. Its array
fallback still uses ordinary P-memory reads. Real P-data reads remain data, even
when an instruction also consumes a P-space extension. Latched REP words produce
no invented fetches. Actual interrupt-vector words are fetched through the strict
bus before acknowledgement; a missing second word leaves the source pending.
A two-word vector instruction consumes its already fetched extension rather than
reading that memory word again. An observer failing after the second vector read
still precedes acknowledgement and native vector instruction execution.

The observer is copied for one step and released on success or failure. It is
not checkpoint state. Callbacks observe only and must not mutate the native CPU,
clock or board. Native reentry/reset, active checkpoint capture and owner restore
reject. Callback failure identifies operation/stage/address/ordinal; the outer
native error adds starting PC/OMR and interrupt context. An after-stage failure
can leave completed bus effects while the native instruction remains unretired.
A rejected step requires coordinated trusted CPU/bus/clock restore; retrying its
remaining effects is unsupported. No observer is called on an already faulted
CPU, a timing preview or a later step that does not supply it.

  cmake --build --preset strict --target blofeld-dsp-native-access-test
  ctest --test-dir build/strict -R '^dsp_native_access$' --output-on-failure

Own native programs pin literal long-immediate and parallel-store encodings,
values/addresses, post-updates, PC and nominal cycle counts. Other checks cover
P-data versus extensions, GPIO bit routes and word fallback, actual FIFO drain,
unknown extensions/data, before/after callback failures, copied callback lifetime,
reentry, loaded REP checkpoint replay and fast-vector acknowledgement/recovery.
These observations are prerequisites for native DMA bus integration, not a
grant/stall/enable-latency model or evidence of original firmware audio.

Consumers adopting the new prepared SDK must rebuild with matching headers and
native libraries: IMemoryValidator has an additional virtual hook. The pinned
SDK checkout and existing frozen consumer bundles are not modified. All source
preparation remains in patches/dsp56300-reference-bus.patch.
