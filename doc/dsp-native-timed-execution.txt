Costs come from actual Core previews. Only completed CPU prefixes commit history;
unknown costs/dependencies stop native prefix planning. Control and DO endpoints
terminate the plan. REP retains the real Core latch. Native execution remains enabled.
Pure resource descriptions, including unavailable descriptions, use a fixed
per-thread cache keyed by the complete opcode and base cost. CPU state, extension
words, actual cost observations, dependency history and bus effects are not cached.
Owner completion requires the offered opcode/extension/base cost and genuine
Core retirement. Staged completion retains its actual Core flow receipt;
changing a host-supplied word cannot replace that offer.

Own normal-NXP timing windows accompany real CPU/register/peripheral assertions,
checkpoint/mutation, REP/DO, native-control and ownership controls. The Board
native timeline clocks qualified dependencies before retirement; MCU
finite budgets charge native and interlock periods. Paired checkpoints preserve
captured words and remaining periods; reset discards pending execution.

Selected literal/effective calls, DOR and P-memory transfers retain genuine Core
stack, memory and code-invalidation effects. False conditional outcomes delay the
next instruction by one period (FM A.2.6.3), using the actual Core flow receipt
including equal taken/fallthrough PCs.

The raw timing kernel defaults to qualified dependency descriptions. The device
timeline defaults to conservative execution: a valid Core instruction without a
dependency description executes through genuine Core effects, with three
functional serialization clocks before and after it. Adjacent barriers overlap;
base instruction costs still come from the Core. These clocks cover pending
resources in the current model; they are not measured hardware instruction or bus
timings. Existing described paths keep their qualified dependency handling.
Unsupported opcodes, real bus faults, inconsistent retirement receipts and known
descriptions with unsupported timing still fail visibly. No peripheral response,
resource description or CPU result is fabricated. Checkpoint/copy preserve policy
and pending barriers; reset preserves policy and clears pending work. Negative fixtures explicitly
select qualified mode. See dsp-conservative-execution-reference.json.
