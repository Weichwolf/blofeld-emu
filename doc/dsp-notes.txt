Original MIDI allocation and connected DSP audio

The regular Board engine renders original note-driven PCM from actual reset;
the connected control and limits are described below. The first sections retain
the separate strict diagnostic fixture, which deliberately refuses reserved reads.

original_dsp_note feeds actual bytes into the original primary input ring. The
unchanged parser selects the sound block, invokes its actual note handler,
updates packed note/velocity history, applies the linear velocity transform and
enters the original allocator. No host writes converted note fields, active-list
pointers or entry-setup results. All 127 original records are pinned through the
shared dsp-voice-reference.json identities before native execution.

The 27 allocating cases cover notes 0/64/127, velocities 1/64/127, all sixteen
matching channel selectors, a three-call fragmented message and running status
after a genuine zero-velocity message. Incomplete
messages do not invoke the note handler. Sixteen mismatched-channel messages,
four zero-velocity Note Ons and three explicit Note Offs return through their
actual frames with an empty active list. These release-only cases establish no
release of an allocated voice.

Every allocating case currently fails at P:0004ce on its first parallel read of
Y:ffffff. The native access observer checks the preceding completed X:c53e read,
the rejected Y access without a returned value, real SP8/DO25 context and the
unaltered original program and slot payloads. The original caller has already
consumed the message and written its independently checked packed history.
The failed staged instruction retains ownership and rejects reentry without
changing registers/progress. A fresh diagnostic snapshot preserves CPU/fault
state; the next case restores the trusted pre-input snapshot. No reserved
read is ignored.

DSP56371UM Rev.2.1, table 3-8 (PDF page 72), marks Y:ffffff reserved. The pinned
manual is recorded in hardware/sources.json. It does not qualify a readable
value or safe access; section 3.1.1 advises against reserved-space accesses.
The discarded destination in this allocation loop is
source evidence, not permission to invent peripheral behavior.

The fixture supplies raw factory sound fields, explicitly empty caller workspace
and original list/event/controller initializers. Register/pointer prefixes stop
at P:011d/P:0185 before diagnostic resets. This does not establish boot RAM,
complete Desktop/Keyboard startup, successful allocation, stealing, live release,
scheduled rendering, PCM transport, real audio or hardware equivalence. The
separate held-note voice regression retains its independent numerical scope.
The separate note-release profile follows real MIDI release from declared active
entries through original envelope retirement/collection (dsp-note-release.txt).

The shared note/release/sustain target uses independent dsp56300 and an authored
literal ROM caller, with no legacy executor/assembler in its closure. Diagnostic
resets use actual mode5 pins, hold and recovery; they are not original MCU boot.
Staged observations prove the real completed X read and rejected Y request.
The explicit laboratory memory-switch step supplies no peripheral schedule or
calibrated instruction timing. All original programs and Python oracles remain
unchanged.
ASan/UBSan and separate TSan pass the complete 27/23/2 note matrix, all 592 release
and 960 sustain cases, including twelve independent corrupted-trace controls per
profile. The normal and isolated target commands/properties are identical.

  cmake --build --preset strict --target blofeld-original-dsp-note-test
  ctest --test-dir build/strict -R '^original_dsp_note$' --output-on-failure

The regular Board engine now emits original DSP audio from actual digital POR
using unchanged 1.25 and official Init in mutable A001. An external caller uses
only public initialize/advance/checkpoint/restore/MIDI/recording APIs. At 274
ms, before input, its 97 SPI frames and all 335102 native NAND observation lines
match the completed R5 reference; 440 decoded PCM frames are zero.

From that trusted checkpoint, F8-only and F8/NoteOn at 275 ms plus NoteOff at
285 ms branches reach 305 ms and each capture 1807 low-FS stereo frames at 44100
Hz. Clock-only remains silent; the note has 1206 nonzero frames, peak 357263 and
equal centered-Init sample pairs. All common 440 prefix frames agree after
native-owner restoration. No routines or firmware bytes are replaced, and no
host synthesizer supplies samples.

This is a regular-engine instrument result with an external MIDI test caller.
Ordinary CLI scheduling/live host streams, long notes, independent release,
polyphony, physical stereo labels and full Desktop/Keyboard acceptance are open.
The separate R5 released-SPI-pad failure near 360 ms is beyond this 305 ms
observation and remains unresolved. Original runtime evidence uses ASan/UBSan;
twelve affected canonical decoder/Fetch/Board controls also pass separate TSan.
See regular-board-midi-audio-reference.json for hashes, counts and remaining
scope.

The canonical functional decoder supplies an explicitly selected virtual word
(nominal 0 on the NAND Board) for reserved Y I/O, with no selected
storage/register resource. This is not a physical read-value measurement.
Default strict fixtures, unknown assigned registers, unknown RAM reads and bit
operations retain their guards; see dsp-reserved-read-decoder.txt. The earlier
frozen candidate used A55AA5 and records 25 actual selector iterations, voice
construction and NoteOff dispatch, 63 IRQ/RTI pairs and serial words matching
both DMA streams. Those instruction observations are not inferred for the new
run, which has no equivalent PC trace. See own-dsp-nand-reference.json for that
narrower reference and raw-word evidence.
