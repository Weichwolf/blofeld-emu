Causal peripheral deadlines in the native MCU/DSP runtime

McuDspRuntime accepts DspRuntimePeripheralEvents after its DspRuntimeEvents input
cursor. The board owns payload, protocols, cells and connections; the runtime
owns only the causal calendar. A peripheral source needs a stable identity, a
pure next_ticks query, an observe callback, positive budget and peer_first order.
With both lanes, inherited input also uses peer_first: inherited input precedes
peripheral input, then DSP. Other combined orders refuse. Both lanes share one
equal budget per MCU period.

The peripheral calendar pins even an absent deadline. Only completed native
periods, inherited observations, peripheral dispatches or accepted MCU shared
writes may refresh it. A native cause cannot create input at/before its own
completion. A peer write can create same-tick input only at an explicitly open
input boundary with no same-tick completed DSP period; an already offered exact
input may remain pending. Closed input boundaries still refuse new exact input.
These are declared ordering contracts, not measured silicon propagation times.
The inherited cursor retains its own later deadline while peripheral work occurs.

Queries and observations cannot change MCU/DSP registers, time or native owner
state. Reentry, incompatible metadata, stale deadlines and budget exhaustion
fail visibly. These boundary guards cannot detect arbitrary callback side
effects: board queries must remain read-only. Unsupported hardware accesses
remain the responsibility of the strict board/bus model.

Peripheral time advances during held DSP reset and between native DSP edges.
Each horizon separately includes/excludes native and input work. Reset control
does not infer a peripheral power cycle or a pin-sampling phase. An accepted
shared MCU write refreshes the calendar after its actual signal observation.
Missing/cyclic tie orders reject before the tied bus action; an illegal deadline
created by an already accepted action retains that prefix and faults the owner.

Joint snapshots retain identity, pending deadline, horizon flags, actor times
and counters. Callback objects and board payload are not serialized. Restore
validates matching source identity/order/budget before restoring native state.
Constructing a restored owner or taking a snapshot does not query live sources.
The caller restores matching payload/cursors before advancing; the first actual
offer checks even an absent saved deadline before dispatch. A failed restore
establishes no usable owner and promises no atomic rollback of native mutations.

The pure calendar test checks literal actor states, open/closed/native-completed
peer boundaries, unchanged refusal state and actual NAND hold/Hi-Z replays.
Ten native MCU/DSP test groups use authored HCS12 LDAB/STAB and DSP NOPs. DSP
reset is held from zero through450 ticks, recovery ends at540, and the shared
write is at720. Running cases contain four45-tick DSP periods and one retired
NOP. Full native register/progress, MCU GPIO/period and CLK2 expectations cover
all three acyclic MCU/input/DSP orders, cyclic/unqualified rejection and joint
restore/clone while inherited900 remains pinned. Additional cases check native-
and peer-born deadlines, exact/sub-edge dispatch, absent-deadline pinning,
combined budget exhaustion, malformed/mutating sources, source-contract changes
and deferred stale-payload rejection. No manufacturer program bytes are embedded.

The 27 scoped integration groups pass ASan/UBSan and separate TSan without skips,
including the unchanged original reset/SPI prefix and regular Board checkpoint/
pipeline groups. The original prefix still refuses reserved Y:002000.

The older standalone DspFetchPeripheralEvents/DspFetchScheduledRun fixtures
remain legacy-harness evidence; they do not establish current native-runtime
coverage. This work qualifies scheduling infrastructure. Actual board payload/
wiring, full original reset-to-instrument operation, MIDI/audio, storage/update/
recovery and realtime remain incomplete on both Blofeld profiles.
