Native program fetch latches

DspMachine::latch_reference_program(ticket) performs the strict P-bus read for
the current pending opcode or consumed extension, then keeps native decoding
and retirement suspended. DspReferencePending::latched_program_word exposes
the actual captured word, including zero. The effect/ticket still names the
pending native admission; the optional word means its physical memory read
has already happened. advance_reference_access consumes that captured word
without reading P memory again. Decoder lookahead alone never creates a latch.
Existing callers that admit reads directly retain their behavior.

DSP56300FM2.3.1/table2-1 and5.3/table5-1 distinguish fetching an instruction
from decoding and executing it. The latch supplies this separation to native
continuations without assigning silicon clocks to calls. The separately enabled
frontend below retains several actual reads across instruction boundaries.
AG/data/execute placement, IRQ/loop timelines and automatic core/DMA arbitration
still need integration. Clocked completion profiles cannot use these untimed APIs.

The owner validates the same process-local capability as normal admission.
Default, foreign, expired and reset/restore-invalidated tickets reject before
accessing the bus. Duplicate captures and nonprogram effects reject before
I/O and preserve the legitimate pending access. A real unknown P read fails
with opcode/extension, address, PC and OMR context, quarantining the core until
trusted coordinated restore. Program data reads and interrupt-vector reads
remain ordinary admissions; they cannot be relabeled as opcode/extension
captures. No caller-supplied word can replace an actual strict bus sample.

The captured word is a fixed optional in the opaque continuation checkpoint.
Coordinated restore retains it alongside CPU, bus and DMA state while replacing
old capabilities. Hardware reset and retirement clear it. Later code writes
still invalidate native host dispatch; they do not erase a word already fetched
by the modeled core. No original firmware or bus memory is rewritten to make
the native interpreter execute the captured word.
Rebuild consumers with matching project headers/libraries for the extended
pending view and checkpoint state. Frozen consumer bundles retain their own
verified implementation until deliberately rebuilt.

  cmake --build --preset strict --target blofeld-program-latch-test
  ctest --test-dir build/strict -j1 --output-on-failure -R '^dsp_program_latch$'

Own programs configure actual P-to-P DMA through native MOVEP instructions.
Independent literal register/PC/flag and instruction-length/cost expectations
distinguish reads before and after DMA overwrites. Both opcode and extension
paths replay coordinated snapshots, preserve a zero opcode, retain an already
fetched long instruction after RAM changes to NOP, and observe new code on a
later genuine fetch. FIFO/type/capability guards and unknown opcode/extension
recovery retain strict failures. Supplied DMA/core occupancy remains an explicit
reference experiment; these tests provide no physical phase timestamps.

No automatic DMA clock, complete ROM, reserved Y:002000 behavior, full Desktop/
Keyboard reset-to-instrument boot, real-time callback bound or silicon
equivalence is established. Manufacturer assets remain local.

Queued frontend

start_reference_fetch(ticket) enables the frontend at a genuine pending ordinary
opcode. No caller supplies an address or replacement word. Explicit
advance_reference_fetch(address) generates the next sequential 24-bit address;
advance_reference_fetch(read) samples that issued address on the strict P bus.
These are owner-selected F1/F2 transitions, not calibrated ticks. Fetches can
continue while the current native instruction waits at a data effect. The fixed
eight-word host bound supplies backpressure; it is not a silicon queue-depth claim.
reference_fetch() returns a copy of this state, not a restore or injection interface.

Actual opcode/extension admissions consume the queue head once. An empty queue
refuses admission without fallback reads or native effects. Decoder lookahead
uses a matching ready word if available but never consumes it. P-space data
operands still perform their ordinary actual bus read. Retirement preserves
unconsumed words; real RAM/code-cache invalidation cannot replace their values.
Checkpoints retain both sampled words and the separately issued F1 address.
Reset clears the entire frontend and invalidates old native tickets.

The native attempt reports whether execution actually wrote the PC through its
control-transfer path. Sequential opcode/extension fetch increments do not set
this result. A taken JMP/JSR/BRA/BSR, conditional transfer or return discards
all younger samples and an issued F1 address even when its destination equals
the sequential cursor. A false condition retains these real samples. A PC that
differs from the consumed cursor without a native redirect rejects contextually;
resulting-PC comparison cannot substitute for an actual branch decision.
The adapter does not reevaluate conditions from later RAM or status values.

The fixed native result is cleared before each attempt, on yield/failure,
hardware reset and both trusted restore paths. It is derived completion output,
not serialized architectural history. A resumed attempt recomputes it from its
retained actual bus reads and native base. Rebuild matching SDK headers/archives;
the SDK's full and bounded architectural checkpoint layouts remain unchanged.
This result supplies no physical branch-stage timestamp. IRQ insertion, loops/
REP, hardware cache, WAIT/STOP, traps/debug and software-reset pipeline behavior
remain strict frontiers. Atomic native execution cannot bypass an enabled
frontend. Per-effect reference and completion-clock contracts remain separate.

  ctest --test-dir build/strict -j1 --output-on-failure -R '^dsp_prefetch_queue$'

Own native-configured DMA tests distinguish F1 from actual F2 sampling, preserve
later opcodes/extensions and zero words through real code overwrites, and replay
both ready and issued-address snapshots. Native literal register/PC/flag/length
and nominal-cost expectations cover their later consumption. Separate P-data
reads see the newer RAM value while the same address's queued opcode stays old.
JMP redirects invalidate ready and issued words, including a fallthrough target.
Capacity, starvation, competing APIs, reset and unknown speculative-read recovery
remain explicit. Full seven-stage scheduling and physical bus timing are open.

  cmake --build --preset strict --target blofeld-prefetch-condition-test
  ctest --test-dir build/strict -j1 --output-on-failure -R '^dsp_prefetch_conditions$'

A fixed matrix executes all 16 Jcc codes with all 256 CCR values using independent
FM tables12-17/12-18 Boolean expectations, including normalized and signed conditions.
Every branch targets the identical sequential PC, so only the real decision
can select retention versus fresh fetch after code overwrite. Literal native
flags, register values, stack, PC and four retirements per case are checked.
Separate native-configured DMA cases pause an actual memory-bit operand or
conditional call, replay two joint snapshots and distinguish the following
queued NOP from the DMA-written instruction. Existing distinct-target branches,
JMP/JSR/RTS, zero/extension captures and strict failure cases remain covered.
These finite ISA cases are deterministic instruction tests, not parser fuzzing.
