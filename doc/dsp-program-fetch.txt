Native program fetch latches

OwnDspFetch::issue reserves the next P address; capture performs its actual strict
F2 sample before native decode or retirement. begin consumes the captured opcode
and its required extension exactly once through the independent DSP core.
A captured zero is a real NOP. Program-memory writes cannot replace a known word
already sampled; an unconsumed extension keeps its own independent F2 time.
Decoder knowledge of length supplies neither a word nor a successful admission.
DSP56300FM2.3.1/table2-1 and5.3/table5-1 distinguish instruction fetch from decode
and execution; these untimed calls assign no physical pipeline timestamps.

Joint frontend/chip checkpoints preserve sampled words, an outstanding F1 address,
native execution, DMA and held source data. Restore invalidates the old frontend
and native tickets. Foreign/stale tickets and empty checkpoints reject before
I/O. Program-data reads and FIFO effects remain actual native operations; they
cannot be relabeled as opcode/extension captures. Hardware reset discards the
previous owners. No caller supplies replacement results to native execution.

A sampled unknown value stays explicitly unknown. Attempted opcode/extension
consumption fails with address/PC/OMR; the production timeline quarantines that
failure and refuses checkpoints/retry. Recovery restores a checkpoint before the
unknown word's F2 read, then supplies actual known memory for a fresh capture.
Restoring a previously sampled unknown word cannot invent a known value.
Untimed F1/F2 and native steps advance no clocks; an explicit held reference-cycle
call has its own clock/resource contract. Competing native ownership rejects.

Own programs configure actual P-to-P DMA through native MOVEP instructions.
Independent literal register/PC/flag and instruction-length/cost expectations
distinguish reads before and after DMA overwrites. Both opcode and extension
paths replay coordinated snapshots, preserve a zero opcode, retain an already
fetched long instruction after RAM changes to NOP, and observe new code on a
later genuine fetch. FIFO/type/capability guards and unknown opcode/extension
recovery retain strict failures. Supplied DMA/core occupancy remains an explicit
reference experiment; these tests provide no physical phase timestamps.

After actual staged retirement, synchronize validates the core's instruction
outcome against the admitted address/opcode and retirement count. The native
control-transfer flag discards both queued F2 samples and issued F1 even for a
sequential target. An untaken condition retains them. No branch condition is
re-evaluated from later registers or RAM. REP latch reuse remains distinct from
a control transfer. Trusted chip/frontend checkpoints retain the actual outcome
when stopped after retirement but before frontend synchronization.

The independent-core matrix executes all 16 Jcc codes and 256 CCR values against
FM tables12-17/12-18 Boolean expectations, including normalized/signed conditions.
Each branch targets its ordinary successor while RAM replaces the queued NOP.
Independent full-register/CCR/stack/PC expectations and four native retirements
per case distinguish retained samples from refetched code. Sixty-four fresh-owner
restores stop after actual branch retirement and before F2 synchronization.
These deterministic ISA cases are not fuzzing. Separate TSan uses build/thread.

No calibrated DMA timing, complete ROM, reserved Y:002000 behavior, full Desktop/
Keyboard reset-to-instrument boot, real-time callback bound or silicon
equivalence is established. Manufacturer assets remain local.

Native queued frontend

The fixed eight-word continuation bound supplies backpressure; it is not a claim
about silicon queue depth. F1/F2 can continue while a native data access waits.
An empty queue cannot fall back to another program read. A full queue, duplicate
F1, missing F1 or competing CPU/vector owner rejects without replacing samples.
The queue view is an observation, not a restore or word-injection interface.
Hardware reset invalidates frontend and native tickets; a fresh owner must read
the retained boot ROM after actual reset hold/recovery.

A captured two-word instruction consumes both owned words before executing its
native data effects. MOVEM P-data reads and SHI FIFO reads remain actual bus
operations. They cannot be relabeled as F2 samples. A pending FIFO read can
therefore coexist with later queued opcodes/extensions and DMA overwrites.
A later code write cannot replace their older samples.

The native queue test covers four FIFO/DMA overwrite windows and 27 restored
frontend continuations. Independent full-register, PC, stack, flag, retirement
and MOVE base-cost expectations distinguish before/after F2 and separate P-data
from an older opcode at the same address. JMP/JSR/RTS and conditional calls
exercise real push/pop and target refill, including sequential targets. RAM-bit
cases change the operand after its accepted native read: only the retained input
may determine the branch. Unknown samples survive later RAM writes and restores;
only a fresh F2 can resolve initialized memory.

REP executes three actual latched bodies despite later code changes. WAIT
retires into the real waiting state and refuses another instruction. Guest RESET
offers its actual native peripheral action, clears programmed DMA/SHI registers
and retains CPU state, RAM and the queued NOP. These checks replace the legacy
fixture's blanket refusal of those controls. A pending native fetch rejects a
competing frontend/timeline; subsequent live timeline execution uses explicit
before/through boundaries and independent 45-tick reference periods. Untimed
native retirement itself advances no clock. Physical control stages, full
pipeline overlap and original instrument acceptance remain open.

Remaining legacy pipeline experiments

The selected automatic_memory OMR bit-branch profile owns an early fetch segment
while preserving older opcode/extension samples. Actual native confirmation
retains newly read target words; generic explicit redirects above still clear
their queue. Scope, timing limits and same-address checks: dsp-branch-pipeline.txt.

Mapped unknown F2 samples

DspProgramSample records an actual address with optional data; absent data is
never a zero/NOP. F2 retains resource,occurrence,loop metadata and occupancy.
DspProgramWord remains known data for Decode and native admission. Unknown used
opcodes/extensions refuse with address,PC,OMR before their effects. Neutral
suspension/loop/REP queries must not demand an unrelated head value. Unsupported
physical maps still refuse at F2; data operands,vectors and untimed latches
retain strict reads.
Explicit scheduling distinguishes a missing F2 from a captured absent value;
the latter reaches strict admission instead of waiting indefinitely.

Later RAM/DMA writes cannot resolve a captured absent value. Copied/joint
checkpoints retain it; only a new actual F2 can observe initialized memory.
The existing automatic branch profile refills even false/sequential targets.
Its original and fresh F2 receipts remain distinct; generic false-condition
retention above is unchanged. Branch F1/F2 timing never depends on value knownness.

Own cases check120 full-state native/automatic return paths,16 bit-branch
vectors with80 joint cuts/160 restored suffixes,used opcode/extension/data
refusals and native-configured P-to-P DMA/wait/stale-ticket suffixes. Literal
native counters are SDK diagnostics; reference periods are not silicon edges.
They do not establish original boot or normal instrument/MIDI/audio/storage.
