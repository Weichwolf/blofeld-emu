Native fixed RAM bit control

The captured native frontend admits fixed six-bit X/Y RAM operands for
JCLR/JSET, JSCLR/JSSET, BRCLR/BRSET and BSCLR/BSSET. The instruction performs
one genuine RAM read; the DSP core retains the sampled bit and executes its
original PCU/stack effects. This is read-only control flow, separate from the
BCLR/BSET/BCHG/BTST reservation in dsp-ram-rmw.txt. Peripheral, effective-address
and register forms retain their existing separate admission contracts.

The encoding and architectural expectations follow DSP56300FM chapter 13:
absolute/relative target, clear/set sense, return PC immediately after the
two-word instruction, full saved SR and unchanged RAM. A taken call publishes
its return frame/sequential PC and then its destination through two native API
boundaries. These reference periods do not claim silicon pipeline timing.
DMA before the sample can change the decision; later writes cannot resample it.
Held DMA and program-fetch conflicts retain the actual pending native owner.

The authored matrix passes 3456 cases per sanitizer (ASan/UBSan and separate
TSan), including both CCR endpoint patterns, spaces, senses, forward/backward
relative displacements and absolute targets. There are 2192 same-owner restore
cuts, 2192 fresh-owner continuations and 160 genuine captured RTS returns per
profile. Full registers, stack, memory canaries, DMA payloads, holds and clock
counts are checked. Seven adjacent clock, RMW, DMA, fetch, checkpoint, interrupt
and bank groups also pass; three reuse identical independently qualified ELF,
argument and log identities instead of repeating unchanged executions.
