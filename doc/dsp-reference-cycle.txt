OwnDspMachine::advance_dma_reference_cycle holds the CPU while advancing an
actual DMA/reference period. advance_dma_native_cycle selects its actual pending
native effect with the explicit isolated_effect hypothesis. OwnDspFetch's capture
and pipeline variants additionally derive F2 occupancy from the already issued
address. Callers provide neither a memory footprint, instruction word nor
peripheral response. Pending native effects identify their original operation,
space, address, PC and OMR. Captured opcode/extension words need no second P read.

The selected reference order is DMA, existing F2, selected native effect; the
pipeline variant then issues a new F1 if capacity/context permits. A fresh
conflicting DMA source waits while actual CPU work proceeds. A held DMA
destination stalls both F2 and the native effect, including the destination
commit cycle. Later admission samples that committed value. A reported source
phase may still wait for a resource; phase metadata alone is not a captured word.

Preflight checks ownership, pending effects, fetch readiness, memory resources,
clock mode and the explicit model before DMA request sampling or real I/O.
Unqualified simultaneous P reads, active-DMA/FIFO sharing and unsupported timing
retain their original native/queue/clock state and DMA index. Core effect tickets
cannot be fabricated; abandoned genuine tickets fail after coordinated restore.
Status RMW does not inherit read-only status-test qualification.

FM table10-10 places read-only DMA status on the controller register route,
distinct from P RAM. A genuine native bit test of X:fffff4 can share F2 while
DMA is enabled. The existing controller handler samples its actual status after
this reference cycle's DMA phase. The test covers both quiet and requested
channel0 activity; a same-cursor JSET preserves or discards the actual F2 word
according to its native outcome. No controller value or branch result is injected.
Other peripheral sharing and physical sampling order remain separately qualified.

Data access, CPU result publication and instruction retirement are distinct
native boundaries. Tests complete remaining CPU effects explicitly without
inventing extra clock periods. The normal automatic timeline owns those periods
separately. After actual retirement, the caller synchronizes the frontend; a
same-cursor JMP can discard a younger F2 word sampled in that very cycle.

Required unknown data returns the original memory fault and latched board I/O
cause, with space/address/PC. Already admitted DMA/F2 prefixes persist, including
an explicitly absent program sample. Checkpointing the failed frontend and
further cycle admission refuse; trusted joint restore retains the original
captured instruction while explicitly initialized data permits recovery. A
hardware reset is the separate recovery path. No success response is substituted.

All admitted cycles advance actual peripheral/reference clocks. At the supplied
540MHz common timebase and 12MHz EXTAL, the selected stable reference period is
45 ticks. DMA wait periods still advance time while holding CPU effects; raw
CPU publication/retirement advances none. An instruction-boundary clock contract
cannot be bypassed with the composed-cycle API. These are explicit ordering and
clock hypotheses, not measured AG1/AG2/E1/E2, bus or silicon timing.

Literal native MOVEP setup and complete register/retirement expectations cover
held Y loads, source-conflicting stores, held F2, actual program-data reads,
DMA-written opcode consumption, same-cursor redirect, required-read failure and
recovery, pure preflight refusal, controller-bit/F2 observation, retained FIFO
and clock ownership. Native and joint frontend restores preserve held DMA words
and discard abandoned capabilities. Both sanitizer profiles pass the scoped
cycle/fetch/checkpoint/runtime regression. Full overlapped pipeline scheduling,
complete ROM, reserved Y:002000 and original instrument startup/audio remain open.
Reference assets and manufacturer programs remain local.
