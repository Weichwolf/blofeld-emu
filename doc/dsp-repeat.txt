Native REP target qualification

DSP56300FM Rev.5 REP13-160 and A.3.8 require a single-word non-flow instruction
after REP. The independent dsp56300 core validates the actual fetched opcode
before offering an extension or executing body effects. A missing extension
cannot replace the invalid-instruction fault. The Blofeld adapter executes real
mode5 reset hold/recovery and forwards native bus effects without an assembler
or the previous executor.

The directed gate checks two-word MOVE with known/absent extensions and six
forbidden bodies: untaken conditional jump, call, return, WAIT, STOP and nested
REP. Only the real body-opcode fetch is offered. Fault kind, address, opcode and
PC are exact; registers, stack, retired counts and processing state remain at
the pre-body boundary. A faulted retry cannot execute, and trusted checkpoint
restore recovers that healthy unloaded REP state.

A legal absolute-short X-memory load is fetched once and retained for three
iterations. RAM is read afresh each time. After the first iteration, both program
and data RAM change. Two restored suffixes retain the original legal opcode,
read the changed data and finish with LC=0 and an independently counted five
instructions. Subsequent ordinary execution reads the changed two-word opcode
and its actual extension, reaching seven retired instructions.

Pure preview uses the board's side-effect-free program sample and the core's
inspect_instruction metadata. An invalid body can be identified and replaced
before execution without changing CPU state or time. This shape inspection does
not establish full ISA acceptance; the real native execution tests above do.
There is no nominal instruction-clock preview in this gate. Only actual reset
advances its declared clock; instruction effects remain explicitly untimed.

  cmake --build --preset strict --target blofeld-repeat-test
  ctest --test-dir build/strict -R '^dsp_repeat_restrictions$' --output-on-failure
  cmake --build --preset thread --target blofeld-repeat-test
  ctest --test-dir build/thread -R '^dsp_repeat_restrictions$' --output-on-failure

The old pinned independent core fails the before-extension assertion; its
successor is pinned in dependencies.json. Generic core tests cover all three
backend selections and six publication modes separately. This component gate
does not qualify other DO-end restrictions, native pipeline timing, full
original instrument operation or hardware equivalence.
