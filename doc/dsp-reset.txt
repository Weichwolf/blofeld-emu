DSP reset with retained reference time

Hardware reset supplies OMR=000305 for the SPI-boot profile: CDP1/CDP0 are
both set, and sampled mode inputs select 5. DSP56300FM Rev. 5 figure 5-3/table 5-2
define these priority reset bits; DSP56371UM section 4.2 retains them. The adapter now
applies that complete word after the generic library's zero OMR initialization.
Software MOVEC can change CDP; the executed RESET instruction preserves OMR.
The four native previous-priority cases check that distinction against literal
manual expectations. This correction does not establish DMA bus timing.

DspRunContract::resets defaults to unqualified: a live clocked reset still
rejects. Explicit reference_instruction_boundary permits a zero-duration native
hardware reset at a healthy completed instruction boundary. This is a nominal
experiment, not a measured reset pulse, PLL lock, held-reset clock or board route.

The existing CPU reset executes its normal bus/peripheral/native reset path.
Completed lifetime ticks, native units and CLK2 edges remain monotonic. Native
epoch units restart at zero; the declared nominal CLK2 phase starts afresh.
RAM/ROM retain their existing reset semantics. PINIT is resampled by the normal
PLL model; subsequent instructions use the resulting requested clock ratio.
Failed or partially timed execution still requires coordinated trusted recovery.

Every accepted reset advances an epoch identity, including a reset before any
instruction. Scheduler checkpoints and pending instructions from a different
epoch reject. Callers must explicitly retire/rearm their schedules at the known
completed boundary; reset does not invent elapsed hold time or cancel external
events. Trusted owner/schedule restore retains the original epoch together.
Resetting an owner from a completion observer remains a visible schedule fault.

Own native expectations cover two odd-phase resets, literal time/rate ledgers,
timer loading, retained memory, native boot entry, partial-epoch replay, default
refusal, failed-step quarantine and both scheduler admission modes.
The original reference additionally reloads all94 stage words from wire inputs
twice, reaches8192 mapped clear pairs each time and retains the second reserved
Y:002000 failure. Five corrupted report fields reject independently.

  cmake --build --preset strict --target blofeld-dsp-reset-epoch-test blofeld-original-dsp-clock-test
  ctest --test-dir build/strict -R '^(dsp_reset_epoch|original_dsp_reset_clock)$' --output-on-failure

No firmware instructions, RAM maps or unsupported-access checks are changed.
Physical reset duration, asynchronous assertion, hardware latency, normal full
startup and real-device equivalence remain open. Reference bytes/traces stay
local; no fuzz or physical traffic runs.

reference_extal_hold additionally admits an explicit held hardware reset from a
healthy completed native step. begin_hardware_reset requires observed mode5,
PINIT-low and a caller-supplied recovery of at least2 EXTAL periods. These pins
remain stable throughout the declared experiment. PLL-enabled recovery rejects;
no analog lock duration or PB0 connection is inferred. The native reset transaction
stages fixed-mode boot registers and resets peripherals at assertion. Firmware
instruction/plan/scheduler admission stays closed through assertion and recovery.
release_hardware_reset requires at least2 asserted bypass EXTAL periods; advancing
recovery stops at its exact supplied endpoint, returning only consumed periods.
All reset periods add to lifetime ticks/hardware_reset_ticks, without executing
native units, generating timer CLK2 edges or advancing peripherals. Held/recovery
owner checkpoints restore that gate and replay literal native/clock suffixes.
Invalid consumed reset periods quarantine the owner; trusted recovery is required.
advance_hardware_reset_ticks retains partial reference periods. The whole-period
API rejects an unaligned phase. Release starts a new supplied recovery duration;
this is not a calibrated oscillator-edge or first-instruction phase prediction.

DspScheduleInputs.resets=reference_extal_hold explicitly enables held scheduling.
External events retain their deadlines while no native instructions execute.
Recovery completion is a deadline, including before/through exclusion. Scheduled
release accepts fractional assertion periods; assertion still requires the exact
completed native boundary and cannot discard pending instruction time or events.
next_event_ticks returns UINT64_MAX for assertion without an external deadline.
Out-of-band reset/clock changes fail snapshot identity checks. Absolute recovery
overflow rejects before changing held state.

The adapter also clears the complete CCR on native hardware reset. The SDK
reset left SR[7:4] set: an own SR=c003ff seed produced c003f0, not the documented
c00300. All256 input CCR values now have independent reset expectations.

References: DSP56300FM2.3.3; DSP56371UM table2-6; DSP56371 data sheet table19
and note4. Their reset/recovery minima do not supply an exact physical latency.
Asynchronous in-flight abort, other boot modes, PLL locking, physical recovery
latency and real reset/ready routing remain unqualified.
