DSP arithmetic saturation

The independent dsp56300 core executes these tests through the board-facing
machine. No foreign DSP backend or patch is used by this target. Real authored
setup instructions load operands and status; the complete architectural state,
stack, progress, instruction length and defined flags have independent integer
and bit-table expectations. These are supporting component tests, not a complete
original-firmware instrument qualification.

DSP56300FM Rev.5 sections 3.1.5 and 3.2.2/3 define SM limiting using EXT7,
EXT0 and MSP23 after rounding. Positive/negative rails are
007fffffffffff/ff800000000000; rounded positive saturation is 007fffff000000.
The stored-value selector does not erase an actual full56 arithmetic overflow:
V records that event or SM limiting, incoming L is sticky, and E/U/N/Z describe
the result. Fused MACR instead measures overflow after widened rounding; opposite
accumulation and rounding wraps cancel. Standalone MAC/RND are separate controls.
The core's fused-rounding reference records independent software/SMT evidence.
Transfer saturation remains separate from arithmetic limiting.

Single-bit ALU ASL/ASR, NORM and INC/DEC participate. Counted BFU shifts,
TFR/Tcc, mixed/unsigned products and qualified DMAC exceptions retain their
specific behavior. INC/DEC use the full56 accumulator LSB. C after ADDL/SUBL
shift overflow has no asserted silicon oracle under the manual's qualification;
all other state remains checked. Authored product/count-shift words avoid
ambiguous assembler aliases. No manufacturer programs are included.

  cmake --build --preset strict --target blofeld-dsp-saturation-test
  ctest --preset strict -R '^dsp_saturation_' --output-on-failure
  # Repeat with the thread preset for separate TSan coverage.

Ten scopes retain 82803 fixed inputs: 8 named regressions, 24330 arithmetic,
11448 multiply, 24948 accumulate, 6912 rounding, 14040 exceptions/transfers,
540 increments, 540 decrements, one legal MAC host-overflow input and 36 literal
full56 overflow/flag controls. A/B, SM clear/set, three scales, both RM choices,
CCR seeds, signed endpoints, all limiting selectors and unused extension bits
are covered. No input is dropped to accommodate the replacement core.

The migration and core-pin qualification are recorded in
fused-rounding-adoption-reference.json. Public ABI and checkpoint layout are
unchanged; retained application objects are checked against the preceding
qualified ELF composition. Complete ISA/numerical modes, physical timing,
original boot, playable audio/MIDI/USB, storage/update recovery and all documented
functions remain separate requirements. Other legacy test migrations are open.
