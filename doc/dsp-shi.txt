DSP56371 SHI SPI slave reference model

Source: DSP56371UM Rev 2.1, sections 2.7, 7.4 and 7.7.1; interrupt vectors,
priorities and encodings in tables 7-1..5. The downloaded primary manual is
identified in doc/hardware/sources.json. This is original project code implementing
register and serial behavior; no manufacturer bootstrap/program bytes are included.

DspShi receives explicit SS/SCK/MOSI observations. It shifts MSB first in all four
CPOL/CPHA modes and handles 8/16/24-bit words, with short receives left-aligned and
zero-padded. Only those upper bits participate in shifting: inactive HTX padding
cannot propagate into received data or the later IOSR echo (section 7.4.1).
CPHA=0 requires SS release between words; CPHA=1 supports continuous
words. Early SS release discards the incomplete received word. MISO is tri-stated
when deselected/disabled; an uninitialized active output remains unknown.

The one- or ten-word receive FIFO preserves arrival order and discards new words
on overrun. HTX and IOSR are separate: HTDE changes when HTX moves to IOSR. A write
before HTDE replaces the pending HTX word, losing its previous value; it does not
replace the prepared or in-flight IOSR word (section 7.4.2). With no
fresh HTX word, SPI shifts out retained IOSR contents, including previously received
data. HROE clears only after HCSR-read then HRX-read; HTUE clears only after
HCSR-read then HTX-write. Empty FIFO reads and unsupported registers fail visibly.

HREQ is active low and depends on receive capacity, fresh transmit data or both,
according to HRQE. It deasserts at the first clock. The precise CPHA=0 reassertion
point after the final data edge but before SS release is uncalibrated: the output
is explicitly unknown during that interval. A board that reads it must preserve
that unknown state instead of inventing a ready flag. Simultaneous SS/SCK changes,
unknown MOSI at a sampling edge, unsupported I2C/master operation, reserved modes
and changes to HCKR without completed individual reset fail explicitly. Changes
with HEN remaining set are conservatively unsupported. Clearing HEN may also
change configuration when HBUSY is known zero (sections 7.4.6.1..5); busy/unknown
configuration changes fail. HRQE changes require idle.

HCSR reports the specified reset HIDLE/HTDE state; HCKR resets with CPHA set and
CPOL clear, HSAR with the documented default address. Individual reset and clearing
interrupt enables require one explicitly supplied DSP instruction cycle. These are
the manual's instruction-cycle units, not an assumption of one tick per executed
opcode. During a configuration-changing reset delay, HCSR/HRX/HTX access and
interrupt selection fail explicitly instead of guessing the transitional FIFO
geometry; a new SPI selection also fails. Idle pin observations remain accepted.
MISO remains tri-stated while idle; an enabled HREQ has known ownership but
unknown readiness until reset completes. HEN-only reset retains its existing
one-cycle status/output behavior. Completed individual reset clears paths/errors
and output drivers and retains written HCSR/HCKR/HSAR controls. Hardware reset
cancels pending reconfiguration and restores the documented hardware controls.
No CPU/clock conversion or analog edge/setup/hold timing is inferred.
Stop-state behavior is not modeled. Reset retains externally observed wire levels.

Polling and interrupt-request selection are covered: HRIE=01 selects nonempty,
HRIE=11 selects full, HRIE=10 is rejected. Overrun/underrun select their distinct
vectors. Requests are listed in documented internal priority order. DSP CPU
interrupt delivery and SHI/TIM priority registers use the separate native bridge
(dsp-interrupts.txt). Entry latency and I2C/master bus errors remain unqualified
or unsupported; this component alone does not establish CPU exception behavior.

Verification
  build/strict/blofeld-shi-test
  build/strict/blofeld-mcu-shi-test
  cmake --build build/strict --target quality

The first test uses independent expected words, flags, capacities, vectors and
priority encodings, including abort/reset, both error-clear sequences and unknown
signals. Fixed pending-overwrite cases cover all four clock modes and three word
widths before clocking and after one bit, including zero data, both real buffers,
retained IOSR echo and HCSR-read/HTX-write underrun acknowledgement. Separate
short-word tests use both values of the first inactive HTX bit in every clock
mode and both short widths, with independent zero receive/echo expectations.
Twenty-four reset mode/width/FIFO combinations each replay a pending component
copy with zero and actual elapsed cycles, retained controls, full/error RX and
two occupied transmit buffers, rejected transitional access, fresh data and the
new FIFO capacity. Busy/unknown-idle failures and hardware-reset cancellation
are also checked. These are fixed directed tests, not fuzz runs. Separate
vectors leave MOSI unknown on every non-capture edge, checking
that each clock mode samples only its specified edge. The second executes
the project's own HC12 diagnostic program: real
STAA writes drive GPIO SS/SCK/MOSI; real LDAA/ANDA reads sample SHI MISO into RAM.
An explicit synthetic pin fixture connects the two models. It verifies the exact
independent words in both directions. This proves MCU/peripheral communication,
not execution of a DSP CPU, original DSP bootstrap or a Blofeld board profile.

Offline edge/register fuzzing, only on explicit user request, using synthetic data:

The current structured-seed campaign completed 43811 executions in 61 seconds
without sanitizer findings. Seeds cover all clock/word-size combinations and
small/large FIFO overrun/reset sequences. This is an initial campaign, not an
exhaustive or sustained-fuzzing claim.

Native DSP integration
The pinned core now uses a custom dispatcher and strict memory hooks in the
reference adapter, with explicit DSP56371 mode-five reset at P:ff0000. Bounded
DO/REP steps let pin-driven SHI reception progress between CPU instructions;
see dsp-core.txt for original first-stage execution and remaining limits. The
existing SHI implementation also differs from the DSP56371 error-clear and receive
interrupt specifications, so it is not used as this model's behavioral oracle.
Its DspBoot helper receives whole words, writes program memory and changes PC on
the host; that HDI08 shortcut cannot establish original SHI boot-ROM execution.

Original MCU transmission is separately executed and checked in the explicit
pin experiment described in mcu-boot.txt. Its first selection changes SS/SCK in
one GPIO write; this model does not guess the pad transition order. NAND loading,
board routing and clock ratios still require combined execution and stock
hardware validation. See firmware-layout.txt and coverage.txt.

Native original MCU/DSP coupling
The separate original_coupled_boot regression now links original MCU GPIO stores
to the executing DSP ROM prefix. It checks both CPUs, 94 loaded words, retained
trailing data, mapped clears, checkpoint replay and strict pin failures under an
explicit receiver pad-order experiment. This does not qualify the physical
route, reset or elapsed clocks; see coupled-boot.txt for exact inputs and limits.

Original receive interrupts, including the nested untagged reset while SS is
deasserted, are separately qualified with their actual stored vectors,
initializer, software ring writes and RTI (dsp-shi-receive.txt). Selected or
transitional SPI reset behavior, physical timing and full boot remain unqualified.
