Native DSP instruction checks and external silicon comparisons

The reference interpreter executes DSP instructions; its behavior is not an
independent oracle. Independent models derived from DSP56300FM Rev.5 and pinned
published hardware captures check normalization, data moves and zero-count loops.
Neither establishes complete DSP56371 or Blofeld equivalence.

NORM correction
DSP56300FM section 5.4.1.2, section 12.4.2 and instruction page 13-146 define
the status bits and NORM behavior. Its incoming E/U/Z bits select right shift,
left shift, or no accumulator/address update. The no-shift path still computes
E/U/N/Z/V for the destination. S/C remain unchanged and L is sticky.

The native SDK omitted the flag update on the no-shift path. CLR A sets Z,
a subsequent MOVE into A1 leaves Z unchanged, and the first NORM does not shift.
It must refresh the flags so the following two NORMs can shift. With A1=000123
and R1=0, the three-instruction result is A1=00048c and R1=fffffe. The previous
interpreter left A1 and R1 unchanged for all three iterations. The independent
regression fails against that uncorrected interpreter.

The SDK patch adds the missing no-shift result-flag update. Existing shift paths
and the JIT are not changed. It applies only to the private build copy of the
pinned dependency; the checkout and manufacturer programs remain unchanged.

dsp_norm checks 4608 combinations of twelve 56-bit values, three scaling modes,
A/B destinations, all eight Rn registers, 24/16-bit address arithmetic, and C/S/L
preservation. Initial E/U/Z/N are consistent with each input; the separate
three-NORM regression covers the observed stale-Z sequence. Expected bit
arithmetic is independent of SDK helpers. Checks include exact PC/result/SR,
address wrap, unselected registers, and absence of modulo/offset effects on the
counter. This does not prove pipeline latency or all accumulator values.

Accumulator transfers and VSL
DSP56300FM 3.1.6, 5.4.1.2 and the instruction condition-code tables define
accumulator data-bus transfers. S records pre-scaling growth and is sticky;
L records limiting and is sticky. Whole-accumulator transfers scale/limit their
bus result without changing the source. Raw A0/A1/A2/A10 and B parts bypass
these operations. Parallel moves read the source before the same instruction's
ALU result or memory load replaces it. Explicit writes to SR replace the flags.

The SDK's transfer helpers omitted S updates. They now compute growth from the
accumulator actually driving a data bus, before scaling or source replacement.
The manual's A/B OR equations are interpreted as bus-enabled contributions:
a captured MCPX mixed-direction move distinguishes this from inspecting an
unselected accumulator unconditionally. This interpretation is not a measured
DSP56371 result. Register bit tests and accumulator-derived REP counts also have
the standard S/L updates in their instruction tables; raw partial moves do not.
The reserved S1=S0=1 mode has undefined S behavior and is outside the vectors.
Scaled-S bit positions follow the explicit S-bit table on page 5-14. The
adjacent scaling-mode summary on 5-13 gives opposite shifted bit pairs. These
conflicting tables remain an unresolved qualification issue: the b2 scaling
cases restore SR before capture and do not arbitrate S. Thus the scaled-S
vectors check this declared reference interpretation, not a silicon-proven rule.

dsp_transfers enumerates 4896 independent vectors: twelve raw 56-bit values,
three scaling modes, A/B sources, four initial S/L combinations and seventeen
transfer/bit-test forms. Other incoming flags are clear for A and set for B.
Forms cover data registers, X/Y/L stores, MOVEC, MOVEM, MOVEP, raw parts and
parallel source replacement/loads/dual stores. Those parallel words use the
documented complete encodings because the helper assembler drops a second XR/YR
move. Tests check data, source/control preservation, address updates and flags against signed integer scaling/limits
and bit-position growth equations. Separate checks cover pre-ADD source timing,
unselected growth, explicit SR replacement and accumulator REP count transfer.

VSL (13-182) stores the raw accumulator MSP in X:ea and the raw LSP shifted left
once, with the opcode's insert bit, in Y:ea. Extension bits, scaling, limiting,
both accumulators and every CCR bit remain unchanged. The previously missing
native implementation now uses one EA calculation and the correct optional
absolute-address extension. An immediate operand is not a valid VSL address.
The assembler lacks this mnemonic; our tests encode its documented bit fields.

dsp_vsl enumerates 9216 independent value/scaling/flag/A-B/insert/Rn/EA vectors,
including all eight Rn registers and all eight addressing forms. It checks exact
raw words, one address update, instruction length, untouched neighbors and
unselected state. A native REP/modulo sequence stores into initially unknown
operand RAM. Negative checks retain strict missing-extension, invalid-encoding,
reserved-address and protected-ROM faults. Unimplemented reference instructions
now report their own name directly: the SDK's diagnostic core dump previously
performed unrelated unknown reads and hid the original missing instruction.
PFLUSH checks this fault path without pretending to implement cache behavior.

Published hardware corpus
doc/dsp-corpus.json pins banks b0/b1/b2 from Matt Borgerson's MIT-licensed DSP56300
project, including programs, metadata, results, provenance and manifest hashes:
  https://github.com/mborgerson/dsp56300
  revision 82fb25a6917a36ac66212ae31f02aab62211f979

The supplier records captures from an original Xbox's MCPX APU GP core, with
explicit register/memory/stack initialization and sequential execution. That
derivative and its peripheral map are not a Blofeld DSP56371. Our fixture
retains the strict DSP56371 bus and uses the low mapped operand windows. It
explicitly writes its zero memory and executes its own register/stack setup
and jump from reset; zeros are not new device defaults. Original corpus words
then execute unchanged, including NOP gaps. No host writes CPU registers or
substitutes instruction results.

The three banks contain 65, 67 and 71 cases. All 46 architectural register fields are
checked, including EP/SZ/SC. Empty-stack SSH/SSL remain explicitly unobserved;
the native diagnostic does not perform destructive pops. All fifteen observed
stack-slot pairs and the captured X/Y/P windows are compared against their zero
seed, including sparse implicit-zero entries. Cycle counts are absent from the
captures and are not timing evidence. The comparator rejects missing registers/
cases, duplication/truncation, unknown fields, reordered cases and mismatched
stack or memory. Separate negative tests ensure incomplete dumps cannot pass.

Reproduce (external corpus is not included in published source)
  git clone https://github.com/mborgerson/dsp56300 doc/local/dsp56300-tools
  git -C doc/local/dsp56300-tools checkout 82fb25a6917a36ac66212ae31f02aab62211f979
  cmake --preset strict
  cmake --build --preset strict
  ctest --test-dir build/strict -R '^(dsp_norm|dsp_transfers|dsp_vsl|dsp_zero_loops|dsp_hardware_corpus|dsp_corpus_bounds)$' --output-on-failure

The hardware-corpus test skips if the external reference directory is absent;
an existing but incomplete or changed reference fails. Native dumps are written
under build/strict/Testing/dsp-hardware-corpus/. NORM instruction vectors and
comparator rejection tests need no external data. Inputs, their MIT notices and
supplier recordings remain in the external checkout.

Remaining scope
The complete b2 bank is now included after normal-mode zero REP and retained
zero-DO stack writes were implemented. See dsp-zero-loops.txt for the primary
manual sections, its internal REP inconsistency, independent failure regressions
and remaining compatibility/pipeline limits. All 17484 observed values across
the three banks match without a discrepancy baseline. Banks beyond b0/b1/b2
remain unqualified. Captures remain MCPX evidence, not Blofeld silicon proof.

Further ISA/control-flow and native instruction fuzzing, derivative reset/
stack-error/interrupt/pipeline behavior, the original reserved Y:002000 frontier,
ROM contents, combined MCU/DSP boot, original audio and measured Desktop/Keyboard
validation remain open.
