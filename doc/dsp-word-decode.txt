Program-word Decode and conditional control

DSP56300FM2.3.1/Table2-1 shows each opcode and extension traversing Decode,
AG1,AG2,E1,E2 in consecutive word periods. Opcode AG1 overlaps extension
Decode. The first opcode reaches E2 in period7; a two-word instruction's
extension reaches E2 in period8. These word phases alone do not identify a
measured architectural PC/CCR publication edge.

The automatic pipeline requires an adjacent actual F2 extension before admitting
a two-word opcode into AG1. It reserves the following Decode period for that
owned extension, even when younger opcodes are already prefetched. The actual
opcode/extension pair follows four retained extension phase slots through E2.
Missing receipts wait; stale identities, wrong addresses and unqualified native
effects fail visibly. Native opcode-based E1/E2 execution retains its separately
qualified reference projection; extension phase records never supply CPU results.
The two-word extension tail is distinct from an architectural retirement claim.

Joint checkpoints retain both the pending extension Decode and its phase slots.
DMA holds preserve these owners with the older actual stages. Rebuild every
consumer of the public/internal pipeline layout after changes. No firmware
bytes, program-counter assignments or invented fetches supply data.

Long-immediate CMP executes through the native interpreter with its captured
extension. Independent signed56 subtraction expectations check all CCR bits,
unchanged operands and full architectural state, including E2 restore suffixes.
Short Bcc supports all16 CCR conditions. CCR control resolves in AG2 after an
older genuine E1 candidate is available; that forecast changes fetching only.
Native branch E1/E2 independently confirm the condition, target and PC/SR.
The short-branch reference timing and false Decode delay follow FM A1/A2.6.3.
