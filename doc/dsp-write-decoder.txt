Functional internal DSP write decoder

DspBus defaults to DspWriteContract::strict. The explicit
internal_writable_storage contract models writes with no selected writable cell
inside the low 128K X/Y address range. It applies to vacant data windows and data
ROM; P space, peripheral decoding and addresses at/above 0x020000 retain their
existing checks. Changes to memory windows still require the modeled switch delay.
This is an instrument-oriented abstraction, not a measured silicon response.

No replacement RAM, read data, instruction or peripheral response is created.
Selected RAM writes retain their actual values and physical backing; data-ROM
contents and missing-content knowledge are unchanged. A write resource with
selected=false has no RAM/ROM bank geometry and cannot contend for storage.
The actual native instruction still executes and retires through its existing
owner. Unknown reads, invalid words, unsupported I/O and missing code remain
visible failures. This write contract does not turn unknown reads into success.
The separate opt-in vacant-data read hypothesis is in dsp-vacant-data-read.txt.

unselected_writes counts actual committed no-storage writes. Resource queries
have no effect on it. Hardware reset begins a new counter epoch while retaining
the decoder contract. Trusted bus/chip/timeline copies retain both; borrowed
observers keep their existing lifetime. Counter exhaustion fails contextually.

  cmake --build --preset strict --target blofeld-dsp-write-decoder-test \
    blofeld-original-fetch-reset-start-test
  ctest --preset strict -j1 --output-on-failure \
    -R '^(dsp_write_decoder|original_fetch_write_decoder|original_fetch_reset_start)$'

Repeat with the thread preset for separate TSan instrumentation. No fuzzing or
physical traffic is involved. Firmware and the document-derived boot ROM are
local hash-pinned references; missing inputs skip explicitly.

dsp_write_decoder checks all 262144 X/Y destinations in each of the five memory
layouts, with independently declared RAM intervals and nonzero values. It also
checks ROM retention, absent reads, strict mode, map-switch deadlines/relocation,
actual synchronous and F1/F2 execution, committed-write observation and fresh
native continuation. These checks qualify the decoder contract, not the whole
instrument or every possible CPU/DMA overlap.

original_fetch_write_decoder uses the same original-MCU/reset/SPI/native runtime
as mcu-dsp-original-reset.txt. The contract is selected before reset; no faulted
CPU is resumed and no firmware instruction is patched or skipped. The test
requires every one of the original 131072 long stores, all 77824 selected RAM
words zero and 184320 actual no-storage writes. Native REP cursor/LC/exit,
unchanged 94-word SPI payload, MCU NVM and independent instruction-cost/wire/
clock records are checked. The next original Port-C direction write remains a
visible unsupported GPIO operation. The MCU continues independently: after 97
complete SPI frames, 71 further Port-B stores change other pins without clocking
another SPI bit. Their actual bus values and delivery timestamps are checked.
This is a complete first-stage clear, not complete NAND loading, instrument boot
or original audio.

The next GPIO callback rejects inside a completed native reference period. That
period advances DSP time without retiring the instruction or publishing a
successful-cycle observer event. The MCU and shared runtime quarantine; the
clock counter itself remains valid. The test checks this distinct failure state
and refusal of further execution without CPU, RAM or time mutation. It must not
confuse this boundary with strict-mode resource preflight rejection.

The original strict reset/SPI regression retains its distinct refusal and
three replay cases. Existing detailed timing tests validate their implementation
contracts; physical bus/pipeline identity is not an instrument acceptance gate.

The decoder, memory-map, block-map compatibility, DMA, reference-cycle and observer checks
plus both original-reset paths pass under ASan/UBSan and separate TSan. Functional
reports and full event/census/phase records match across instrumentation.

The separate logical-GPIO continuation in dsp-gpio-write-decoder.txt reaches the
first original NAND-ready input without changing this storage contract.

The separate functional_decode policy additionally selects no device for writes
to documented reserved internal I/O. It is used by the regular cold-NAND Board
profile. The narrower policy described above keeps its strict peripheral checks.
See dsp-reserved-write-decoder.txt for native/DMA evidence and remaining limits.
