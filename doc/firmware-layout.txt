Blofeld firmware reference layout

The emulator loads the user's local official 1.25 ZIP/MIDI update. The source
repository contains no manufacturer firmware, ROMs, sample data, manuals,
photographs, extracted programs or disassemblies. Download locations and
cryptographic identities are recorded in the reference manifests.

The supported update has six checked transfer blocks. Seven-bit MIDI framing,
packet order and XOR checks precede unpacking the little-endian 24-bit words.
Embedded MCU, DSP and secondary-page objects have additional checksums.
The main runtime container holds a 32 KiB MCU flash image including its resident
boot/recovery code and 127 ordered DSP memory records. Later records deliberately
overwrite earlier addresses; record order is significant. These objects do not
establish that all persistent NAND, ROM, wavetable, sample or device-identity
contents required by the original hardware are available.

Static inspection also identifies a 94-word (282-byte) DSP first stage embedded
in the MCU image. Its transfer header specifies P:0x6a and matches the documented
DSP56371 SHI bootstrap framing. This is separate from the 127 runtime records.
The stage appears to read further records through a GPIO NAND interface; actual
MCU-to-SHI transfer, DSP boot-ROM execution and NAND loading are not yet combined
or validated. Finding this loader does not establish complete persistent contents
or verified board wiring. Detailed extracted code remains private.

The current native MCU executor starts the original reset vector and stops at
an unmodeled input port. Complete boot, DSP handoff, MIDI/audio and real-device
equivalence are not established. See coverage.txt for the full acceptance scope.
Private firmware analysis and execution artifacts belong under doc/local/.

Reproduce locally:
  python3 tools/references.py --fetch
  python3 tools/extract_runtime.py doc/Blofeld_Firmware_V1.25.zip --output doc/local/runtime-1.25
  cmake --build build/strict --target quality
