Local GPIO registers and resolved board pads

A chip's output latch, direction and drive-strength registers describe intended
drivers. They do not establish the voltage on a shared board net. GpioPadBinding
allows an explicitly declared board experiment to provide that separate pad
observation. Its source is exclusive with legacy external peer observations.
There is no automatic attachment or change to the normal runtime.

resolve_gpio_net combines an explicit span of drivers and passive input pulls;
the two-driver overload retains its interface. Unknown active latches defeat
pull knowledge. Opposing known active outputs remain
unknown with an explicit conflict mask, including full/reduced output pairs.
An approximate current ratio does not select a voltage winner. Opposing passive
pulls are also unresolved. Unconnected, unbiased pins remain unknown.

Defined GPIO register writes update local intent without consuming a pad value.
MCU output-latch reads also need no pad observation. Actual pin-input reads and
DSP pad-dependent reads still reject unknown bits with bus address and execution
context. The board can inspect unknown/conflicting observations without replacing
them with levels. require_known_gpio_pads rejects every unresolved selected bit.
An experiment must audit intermediate states as well as values actually read;
successful original helper returns do not qualify unresolved electrical intervals.
Legacy peer-driven contention checks retain their immediate failures.

Reset retains the attached board source. Copy/move/checkpoint state retains the
obligation to reconnect but drops callbacks into the old live board. Detached
pin reads fail; local register state remains usable. Restored owners explicitly
attach fresh sources. DSP peripheral output with this source is unqualified and
fails; it must not bypass the existing peripheral-drive validator.

  cmake --build --preset strict --target blofeld-gpio-pad-source-test
  ctest --test-dir build/strict --output-on-failure -j1 -R '^gpio_pad_sources$'

The directed regression uses independent level/conflict expectations, unknown
reads, source ownership, reset and detached/reconnected copies. It contains no
manufacturer program bytes. Physical wiring, synchronizers, electrical safety,
original startup and normal USB-MIDI/audio retain separate acceptance gates.

gpio_pad_checkpoints executes own native MCU LDAA and DSP MOVEP input reads
through actual machine snapshots. Captures retain no callback ownership;
replacement destroys the old connection and detached reads/captures reject.
Freshly attached inputs drive independent register/flag expectations. The clocked
DSP replays identical native state/time, then retains the fresh connection across
an explicit reference reset epoch. MCU NVM remains unchanged. These are trusted
in-process checkpoints, not serialized board state or measured reset timing.

Resolved Port E interrupt sources

Attaching a Port E source records its current PE0/PE1 levels in the real
IRQ/XIRQ controller. The board calls McuBus::observe_interrupt_pads after
subsequent pad changes, including while CPU interrupts are masked. Selection
stays pure; polling is not a substitute for delivering every modeled edge.
The source supplies voltage observations, never a synthetic interrupt request.
Observed IRQ pulses retain the real pending/acknowledgement semantics across
native bus copies and fresh source attachment. Detached observation rejects;
unknown enabled XIRQ levels still fail. Existing ECLK/package limits remain.
The gpio_pad_sources regression checks the initial baseline, XIRQ release/mask,
masked IRQ pulse retention, clone isolation/fresh attachment and unknown input.
Physical synchronizer delay and omitted board events remain unqualified.

gpio_multiple_drivers checks literal pair/triple tables, all 32 bit positions,
64 drivers, validation, actual MCU direction/PTU/PTIU reads and own native BRCLR.
original_gpio_reset pins unchanged 1.25 preparation and release/poll routines.
A declared PU0/passive pull/supervisor net holds low under an MCU output, rises
after original CLR DDRU, and stays low while the supervisor asserts it. Missing
bias or an unknown active driver still fails at original PC B98D/address 0278;
other U bits remain unknown. Original CLR/BRCLR registers, NZVC and 3/5-cycle costs
have literal expectations. This isolates those routines; it does not execute the
intervening waits or establish a physical PU0/DSP-reset wire, synchronizer delay,
DSP execution, asynchronous reset timing or complete original startup.

  ctest --test-dir build/strict -j1 --output-on-failure -R '^(gpio_multiple_drivers|original_gpio_reset)$'
