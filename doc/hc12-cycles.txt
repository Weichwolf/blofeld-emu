HC12 reference bus-cycle execution

Scope and contract
Hc12CycleBus wraps the native CPU bus without replacing instruction semantics.
It selects S12CPUV2 HCS12 cycle sequences and invokes a caller-supplied clock once
per bus cycle. Logical operands retain native addresses and widths. Optional
read geometry expands a word into two separately clocked/latched bytes; normal
accesses commit after their corresponding clock callback. The caller must qualify
the memory timing contract and reject unsupported accesses.
No general external wait-state, physical prefetch-address, measured board-frequency or analog
pad-timing claim follows from this adapter. The default CLI remains untimed.

The implemented families include common byte/word ALU/load/store modes, indexed
and indirect operands, short/long branches, loop control, MOVB/MOVW, memory
RMW/TST, LEA, integer multiply/divide, DAA, stack/call/return, reset, WAI, IRQ
and RTI. Unsupported encodings and native-length/operand disagreements fail with PC, CCR, operation/address and completed-cycle context.
The clock callback and backing bus may already have advanced on failure;
continuation requires a coordinated healthy CPU/bus/clock reconstruction.
This is not a persistent or complete-board checkpoint implementation.

P/O/f slots count documented un-stretched cycles without reconstructing the
instruction queue's physical fetch addresses. q denotes the loop instruction's
branch-dependent P/O slot; both alternatives take one cycle under this contract.
Register micro-operation timing is not exposed to callbacks. Checkpoints remain
restricted to completed native instructions; DMA/parallel RAM mutation and
physical program-bus reconstruction are outside the supported contract.

Literal instruction vectors check operand-cycle boundaries and CPU state,
five reset cycles, vector-first nine-cycle IRQ entry, eight-cycle RTI and
eleven-cycle reused-frame RTI. Actual restore reads are CCR, B:A, X, PC, then Y.
Both NXP manuals specify that order; the previous native description read Y
before PC. The build-local exception patch corrects it without changing the
final frame layout. S12CPUV2's glossary/section 7.5.5 and S12CPU15UG's RTI entry
agree on eleven cycles; an inconsistent summary-table entry is not used.

Extended independent vectors cover all six MOV modes for byte/word operands,
nine memory modifications across six address modes, TST, LEA/BSR, CCR stack
save/restore and index wrap/flags. Internal RAM permits unaligned words in a
single cycle (S12CPUV2 6.6); the synthetic flat test memory deliberately supports
this. A literal truth table checks all 16 short/long branch conditions, all 16
CCR combinations and both instruction alignments (1024 native executions).
These vectors exposed inverted BGE/LBGE predicates and incorrect grouping in
PC-relative nine-bit address calculation; build-local patches correct both.
The BGE correction changes observed legacy display/helper instruction/write
counts. Private one-change reversion reproduces the former helper expectation;
reverting only PC-relative addressing does not. Original return/frame/NVM and
literal zero-clear checks remain strict; display counts are now exact. See
original-application.txt and display-parallel.txt for corrected fixture totals.

Literal multiply/divide results include signed limits, overflow and zero
divisors; assertions exclude undefined flags/results. Native divide operations
now test zero/overflow before changing protected results or dividing by zero.
The signed overflow comparison uses the correct negative lower bound. Native
DAA executes explicit decimal-adjust intrinsics from the manual's nine-row
valid-input table; Carry uses the original accumulator. All 20000 valid BCD
ADCA/DAA additions match independent integer decimal sums, defined flags and
literal timing. Undefined DAA input combinations reject with PC and operands.
These are deterministic instruction regressions, not fuzz tests.

The optional mapped Flash read contract adds the documented second bus cycle
for an odd FTS32K word. Independent literal values, flags, pointer/data phases,
between-phase latching, strict failures and owner recovery are described in
mcu-flash-read-timing.txt. The original un-stretched contract is unchanged.

CPS immediate and extended forms decode three instruction bytes, not a one-byte
skip followed by a program-memory data read. The build-local arithmetic patch
corrects both constructors; an extended comparison reads only its actual operand.
S12CPUV2 page 158 supplies the independent encoding, flags and access sequences.
hc12_compare_stack checks 4608 literal boundary/flag/address-mode/alignment cases,
including preserved SP/registers, operand widths and exact cycles. Own overlapping
CPS/alternative-LDAA entries check both branch paths and decoder reuse. Four
partially known RAM instructions require each missing operand byte to reject
before clocks, CPU state or memory revision change; fetch faults include PC/CCR.
This correction also removes a native length disagreement encountered after the
first original oscillator-driven countdown. Detailed firmware analysis stays local.

Constant-address p-code operands also retain their original byte/word width.
They can appear directly in unary/binary operations instead of explicit LOAD/
STORE operations. Routing them through the byte-backed MemoryBank had split
direct word transfers into two bus calls. The CPU adapter now uses the same
logical operand API for these accesses.

A synthetic native CPU loop receives one serial byte while instructions run,
advances the real timer, enables IRQ through its own CLI, acknowledges SCI in
its real handler, stores the byte and returns through RTI: 12565 cycles including
reset and explicit initial mark time. A second unmasked loop reaches the existing
unqualified SCI stop-to-data flag phase and must fail, with execution context.
No host receive flag, RAM result or CPU entry is injected during either run.

The original 1.25 MCU bootloader runs through its application entry under the
same explicit GPIO/PHY observations as original_boot. Native SCI and TIM clocks
advance with CPU cycles; PS4 receives an explicit idle mark under the original
bootloader's MODRR route. This is an observation fixture, not qualified physical
MIDI wiring. Its 90314 instructions occupy 233749 un-stretched reference cycles
including reset. The independent total uses manual mnemonic/address-mode costs and branch outcomes
from the existing private trace, not this timing decoder. RAM clear, checksum,
final CPU state and unchanged MCU NVM/history are checked. The additional trace
stays under build/; no manufacturer program bytes are published.

original_cycle_application uses a separate explicit E2/E3 loopback, E0/E1 high,
Q low, PR2 idle and the same PHY qualification window. With no observed timer
capture baseline, native execution fails at PC 87ea after 90340 instructions and
233807 completed cycles, reporting TIM address 0040, channel mask 01 and CCR.
A second case attaches constant-high PT0 only when native output is already
high, immediately before the original TCTL4 capture-enable write. It samples
the input before subsequent timer clocks without fabricating edges/flags.
This conditional path executes 1672474 instructions and reaches the existing
unknown PU input: native read 0278 mask 3f at PC b98d. Its 4850623 cycles equal an
independent untimed PC/CCR census with manual mnemonic/address-mode costs:
4850617 retired-instruction cycles + 5 reset + 1 failed data-read cycle. The
unprimed timer failure occurs inside a clock callback and does not complete its
failing cycle. Both cases preserve NVM/history and latch failures so retry
cannot advance clocks. Traces and disassembly census remain local. No original
instruction/RAM mutation, skipped loops or host peripheral-ready flags are used.
The fixtures do not establish either physical Desktop/Keyboard routing or a
complete application boot; those unknown inputs remain visible.

Normal-run clock integration
McuRunClock now derives OSC edges from native source/divider selection under an
explicit reference-boundary switching/phase contract. original_cycle_application
uses this clock and checks accumulated time/RTI phase at its strict input failures.
original_run_clock completes the first original RTI handler from running CPU time,
with independent frame/state and manual cost checks. See mcu-run-clock.txt; this
does not qualify analog transitions or complete board scheduling.

Remaining requirements
Oscillator/PLL clock-source transitions, whole-board CPU/DSP scheduling, memory
wait states, remaining timed instructions, physical prefetches and complete
interrupt/SCI timing remain open. Full Desktop/Keyboard boot, MIDI ports, voices,
original audio and real-device comparisons are not established. No stock device
is currently available (coverage.txt). These checks never run fuzz tests.
