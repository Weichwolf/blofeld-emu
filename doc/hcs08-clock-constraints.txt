Scope: MC9S08GT16A/GT8A Rev.1, candidate compatible target only. The actual
part/mask/clock and physical reset/BDC routing remain unverified. This adds
clock-range regression coverage, not an ICG oscillator or elapsed-NVM model.
The existing strict original FSTAT=$FF refusal remains unchanged.

Reset register and clock facts

GT9.3.1..9.3.6 figures9-6..9-12 specify:

  register       MCU-reset value       qualification
  ICGC1          44                    CLKS=00 selects self-clocked mode
  ICGC2          00                    RFD=000 divides selected output by1
  ICGS1/ICGS2    00/00                 reset values, not permanent ready flags
  ICGFLTU/L     00/C0                 reset filter setting
  ICGTRM        retained              POR80; unaffected by MCU reset

GT9.4.2 states that any reset enters self-clocked mode with the FLL open.
Its reset DCO frequency is fSelf_reset; it does not retain a former locked
FLL rate. Figure9-1 notes that factory FFBE trim is not copied automatically.
ICGTRM adjusts the internal reference generator; table9-10 has it off in SCM.
Retaining trim does not justify carrying an old FLL rate into the reset
self-clocked DCO.
Writing CLKS=00 from a running FLL is a different, frequency-retaining path.
GT9.4.1.3 likewise distinguishes interrupt/off recovery from reset/off recovery.

Under this candidate map, GT15 figure15-5 selects BUSCLK for active BDM reset
(BDCSCR C8, CLKSW=1), versus ICGLCLK for normal reset (00, CLKSW=0). CPU GO
does not itself supply an oscillator frequency. The application later copies
trim and writes ICGC1=28/ICGC2=30; those instructions do not run at the RAM
programmer entry. Original entry evidence is in hcs08-programmer-entry.txt;
caller review is in private source issue21.

Range calculation, without selecting a board frequency

GT tableA-11 (printed275) gives reset ICGOUT min/typ/max5.5/8/10.5MHz.
The /2 bus relation gives a candidate reset BUSCLK interval2.75..5.25MHz,
nominal4MHz. These are specified limits, not a measured rate or permission
to choose a convenient point. Conditions and the unverified target apply.
GT4.6.1 equations4-1/4-2 require:

  fFLASH = fBUS / ((DIV+1) * (PRDIV8 ? 8 : 1))
  150000 <= fFLASH <= 200000 Hz

The original programmer's FCDIV1E therefore requires BUSCLK4.65..6.20MHz.
Its intersection with the candidate reset interval is4.65..5.25MHz. Nominal
4MHz gives129032.258...Hz and fails, but the full specified reset interval
does not prove programming impossible. The6MHz reference FLASH fixture is
inside the FLASH range and outside that candidate reset interval. It cannot
establish an original reset operating point. No frequency is fitted here.

The helper's polled SYNC observation is not an exact frequency measurement:
GPIO polling, timestamp latency, timer phase and source histories remain
required. Do not infer an exact reset rate from its200..300-count window.
Reset34/38-phase unit ambiguity and physical oscillator evolution remain
separate from these steady-frequency inequalities; see keyboard-reset.txt.

Regression and limitations

hcs08_flash_clock checks all128 FCDIV settings, both attempted DIVLD values
and six boundary/adjacent integer-Hz samples each:1536 fixed cases. Literal
expected totals are624 accepted transfers,312 NVM-rate refusals and600 bus-limit
refusals. This independently exercises both prescalers and exact rational
endpoints rather than rounded division. It checks write-once readback,
operation/address/PC/context, unchanged array knowledge/history and pending
command state on refusals, no transfer-as-completion, and active-clock refusal.
Eleven literal original-divider samples cover the reset interval,4.65/6.20MHz
endpoints and the6MHz fixture. Unknown-rate refusal, two independent FLASH
checkpoint restores and reset/reload with a discarded prior rate are checked.

These are component commands and explicit rate observations; no original
programmer instruction, ICG transition or physical command timing is newly
executed. The prior original entry gate independently pins actual FCDIV1E.
No ICG/control register is routed or synthesized, idle FSTAT is not bypassed,
and there is no new full boot/update/recovery/audio or hardware qualification.
All118 manual contracts and the complete objective remain required. No fuzzing
or physical traffic is part of these fixed regression cases.
