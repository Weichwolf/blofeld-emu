The separate Hcs08 engine executes native SLEIGH semantics against an explicit
Bus. It does not replace key scanning or the flash algorithm with host routines.
Ghidra12.1.2 language sources are hash-pinned and compiled locally. The local
patch adds missing SBC zero-flag updates and removes CPHX direct's extra pointer
dereference. It also corrects BGE to N XOR V == 0 (Family Rev2 p212);
upstream incorrectly used the BLT condition.640 independent BGE/BLT cases cover
all64 CCR combinations and five signed offsets through ordinary native step().
The installed Ghidra and HC12 specification are unchanged.

786432 independent ADD/ADC/SUB/SBC/CMP/CPX cases cover all byte operand pairs
with both carry/stale-flag seeds. Eighty-one CPHX direct cases check signed
overflow, borrow and exactly one big-endian operand read. Own programs check
LDX/TXS high-byte preservation, descending JSR/RTS stacks, all256 TAP/TPA flag
values, native BGND requests, modified RAM-code invalidation, unknown operands
and quarantined failures. CCR bits6/5 are permanently one (S08CPUV2 chapter8).

DIV quotient/remainder/error knowledge, native zero guard and independent
operand/flag/clock qualification: hcs08-divide.txt. Native DAA and undefined
overflow knowledge: hcs08-decimal.txt.

No power-on register values are invented. The engine requires explicit debug
state or a qualified power_on reset before execution or inspection. BGND surfaces a CPU request and blocks
further execution pending an owning BDC decision; it does not report active BDC
status. WAIT/STOP, unimplemented intrinsics and unserviced eligible interrupts
fail visibly. Architectural source/frame/vector entry and masked native RTI are
available separately through service_interrupt (hcs08-irq.txt); stepping does
not substitute an IRQ for the next instruction. Complete timing, physical reset,
timed IRQ/queue integration, complete instruction
qualification, BDC/security privileges and target peripherals remain required.
Opaque Hcs08Checkpoint retains all native registers and the BGND request at a
healthy completed execution or owned prefetch bus boundary. A suspended native
STORE also retains its captured operation and unique temporaries; trusted restore
reconstructs translation pointers instead of persisting raw native addresses
(hcs08-scanner-stores.txt). Rebuild consumers with matching checkpoint headers
and libraries. Its owner must restore memory, peripherals, peers
and schedule separately; failed/reentrant capture rejects. Debug register
replacement remains separate from a coordinated checkpoint restoration.

The optional original_hcs08 gate verifies the local official Controller1.4
archive and all supplied pages plus its132-byte RAM programmer against hashes
in hcs08-reference.json. Original bytes stay local. Each of two explicit entry
seeds executes three programmer instructions, retaining H through LDX/TXS,
then faults at the real FCDIV store (PC00a5/address1820).

Two application cases take E000 from the supplied reset-vector value under
declared RAM/debug-entry conditions, not a modeled hardware reset. Each runs
6165 original instructions: all1024 clear iterations, the overlapping stack
iterator and calibration assignments. Independent complete RAM contents and
3084 writes/2048 native reads agree. The explicit fixture vector reads are
excluded. Execution then faults at the actual unmodeled PTED write
(PCe030/address0010). No GPIO write, trim, omitted flash, ready reply or flash
completion is silently supplied. All inputs, including the runtime SLA, remain
hash-stable through the gate.

Two additional application cases call actual normal warm CPU reset from known
pre-reset A/X, with all1024 initial RAM bytes unknown. Both actual vector reads
select E000 and reset establishes only CCR mask68. The same6165 instructions
define every RAM byte,3084 writes and2050 reads including both vector bytes,
then fail at PTED. CPHX establishes C; CLR preserves it. Final CCR68/maskEF
leaves H unknown. No initial RAM contents or fully known flags are supplied.
This generic Bus gate does not qualify FLASH security, reset pins/clocks, cold
A/X, dummy bus accesses or the board boot sequence. Existing debug trace rows
remain byte-identical; two WARM_STARTUP rows are appended.

This is an untimed instruction component with source-derived entry tests.
It does not establish complete controller operation, the physical GT8A part,
BDC wiring/clocks, scanning/SPI/ADC, programming/recovery or normal Blofeld
boot/MIDI/audio. Those requirements remain in objective.txt/coverage.txt;
all118 complete manual-function acceptance rows remain pending.

The candidate FLASH component and full original page-algorithm gate are in
hcs08-flash.txt. Their explicit idle-launch/event/retention hypotheses do not
qualify actual controller timing, a physical chip or the complete update.

Architectural reset retains warm A/X knowledge; power_on leaves A/X unknown.
Both clear H, set SP/I and read the real vector only for normal entry. Active-background reset precedes
that fetch and retains an explicitly unknown numerical PC. Hcs08State and opaque
checkpoints carry PC/CCR/A/HX knownness; unsupported partial-register semantics
and BDC reads of unknown bits fail visibly. Cold prefix/word-load/retirement
qualification and remaining pin/clock/caller/ISA limits:
hcs08-reset.txt and keyboard-reset.txt. Existing explicit debug entries retain
fully known flags; they are not retroactively reset-proven native startup.
