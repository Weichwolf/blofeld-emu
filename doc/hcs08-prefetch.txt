Family Rev2 p79/95/97 describes actual program fetches and one-period read
propagation; instruction tables/details supply p/f/s patterns. Source hashes:
hcs08-reference.json. start_irq_program requires an explicit supported contract
and the actual completed eleven-period IRQ queue. Two ready bytes plus the
third in flight transfer without another read. Ordinary step/IRQ/retirement
clock/BDC GO cannot steal or discard that ownership. Explicit reset/debug state
replacement remains separate.

Each advance admits the prior read arrival, consumes genuine queued instruction
bytes and issues only its p-cycle replenishment reads. Twenty-one register,
immediate, MUL/DIV and push forms are supported. Push uses native semantics for
the s-cycle before the following p read. Other native register effects complete
at the end of their p/f budget. This is an explicit internal-register reference
point, not physical register-phase qualification. Native operand/CCR knownness
checks remain independent; MUL with partial CCR still refuses. The retained
reference_linear_program_cycles contract refuses data/flow instructions before
effects, preserving every captured byte.

Native SLEIGH decoding and knowledge checks use the captured instruction view;
operand writes retain the real bus. Later RAM/code changes cannot replace bytes
already fetched. Queue-backed translation caches invalidate before another
instruction or ordinary debug execution. A failed write/read/observer retains
committed prefixes and quarantines. CPU/memory joint snapshots retain queue,
pending arrivals, partially elapsed instruction and completed native effects;
fresh owners resume without repeating a completed stack write.

Independent units check41 instruction/mask expectations, all235 unsupported
opcode classifications, every period of a PSHH/LDA17/LDX19/MUL sequence and24
fresh continuations. Further cases cover program wrap, changed backing code,
foreign owners, real refill failure/recovery and refusing retirement observers.
The hash-pinned original gate follows actual FFE0/EA29 reads into native PSHH:
one H stack write and one fourth-byte read. Eight contexts and three cuts/six
fresh continuations preserve partial CCR and queued original BRCLR bytes.
The real next BRCLR remains a strict unqualified data/flow boundary.

reference_data_branch_cycles additionally admits LDA/LDX/CMP direct (rpp,
three periods), extended (prpp, four periods) and BRSET/BRCLR (rpppp, five periods;
Family Rev2 p233/235). The genuine r read is captured with its side effects,
arrives one period later and is consumed exactly once by native SLEIGH. Native
semantics alone select branch PC and C. Reference register effects one period
after r (phase2 direct/bit-branch, phase3 extended) are not physical register
timing. Existing partial-CCR restrictions remain: lower-bit
branch forms require fully known CCR; bit7 forms also support the existing EF mask.
Extended LDX now defines VNZ with partial CCR, independently checked by the
explicit reset classifier. Existing unknown A/HX operand restrictions remain.

Branch reference assumption: p2 reads the sequential successor speculatively;
that real observation is retained as discarded, including its pending arrival.
p3..p5 refill from native-selected PC, for taken and not-taken branches. Exact
p-cycle addresses/refill timing are unverified hypotheses, not silicon facts.
The explicit opt-in keeps that policy distinct from the retained linear contract.
Snapshots retain contract, captured operand, consumption and discarded arrival.

Data units cover7680 independent byte/bit/direction/offset/CCR cases and60 fresh
phase continuations, read-to-change data, failed p2/recovery and changed successor
code. The separate pinned original gate follows PSHH/BRCLR/LDA/CMP: one real
SPIS read arms the existing transmitter, followed by one read of each TX cursor.
Eight contexts,16 cuts/32 fresh continuations preserve ordered actual accesses,
native flags/registers, unchanged FLASH and the queued next BEQ refusal.

reference_short_branch_refill also admits BRA/BRN, BHI/BLS, BCC/BCS, BEQ/BNE,
BHCC/BHCS, BPL/BMI and BGE/BLT/BGT/BLE (ppp; Family Rev2 p112/113). The explicit
reference executes native semantics at phase1, discards the actual ready
sequential successor and refills p1..p3 from the selected PC for both outcomes.
Exact address/internal-register phases remain assumptions. Existing partial-CCR
and unknown-register restrictions stay independent; mask/pin branches remain strict.
