Session audio transport

  cmake --build --preset strict --target blofeld-host-audio-test blofeld-reference-checkpoint-test
  ctest --test-dir build/strict -R '^(host_audio|reference_checkpoint)$' --output-on-failure

Dependencies: pkg-config, libpulse-dev; integration additionally uses pulseaudio,
pulseaudio-utils and dbus-daemon. The asynchronous client uses the session server
and default sink unless a test target is declared; it never spawns a server or
changes routing. No exclusive ALSA device or USB Audio interface is required.

HostAudio::write validates and enqueues 1..256 complete stereo signed 24-bit
SerialPcmFrames without host I/O, waiting or allocation on success. Its FIFO
holds 4096 frames. Full/invalid blocks reject before changing the accepted
prefix. Declared timebase/rate must give an integral serial bit period; each
frame retains precision, uniform bit period, slot span and continuity. Host
submission converts to S32NE without clipping, mixing, fill or local resampling.

poll admits an explicit owner/restore revision/monotonic modeled timestamp,
executes one nonblocking PulseAudio main-loop iteration and submits at most
256 frames subject to actual server capacity. finish closes input and requests
asynchronous drain after the FIFO empties. Completion requires further polls.
The C completion callback only stores flags, is noexcept and allocates nothing.
All operations have one caller; there is no project worker thread. System API
allocation belongs outside emulated execution and future RT callbacks. This is
not a hard realtime deadline guarantee. Destruction/retire cancels pending I/O
without draining. Connection/stream errors poison subsequent operations.
frames_written counts successful client submissions, not physical playback.

Reference Board Execution.live_audio explicitly enables a separate 256-frame
native-output FIFO. Only completed actual serial frames enter it. Overflow
fails with MCU/DSP context; execution cannot silently continue or fill audio. poll_audio transfers a bounded block at an inactive operation
boundary, including after the execution budget ends. It changes no native CPU,
clock, peripheral or NVM state. The FIFO is part of coordinated snapshots;
already submitted playback is external. Restore/foreign owner/backward time
retires the old transport before another host callback. A fresh transport must
consume restored output. Automatic reference replay rejects live audio.

The test uses private D-Bus/server/null-sink/monitor processes, with rewinds
disabled for exact forward frame counts. Both native DSP ESAI routes supply
8192 repeated transport frames; separate precision/channel-order vectors and
a real server shutdown check conversion and failure. Two actual coupled MCU
WAI/DSP runs supply 128 additional frames without host synthesis or repetition.
Two joint restores retain native/output state and retire stale playback before
progress. A withheld consumer stops native frame257 with both PCs, retains the
256-frame prefix and leaves NVM intact. Manufacturer firmware and physical audio
are not used; no fuzzing runs.
