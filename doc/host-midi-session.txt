Common-time SCI MIDI and host sessions

Config::midi_sci_timed selects an explicit PR2/PS4 input and absolute common-time
start. It requires PipelineTiming and external event order/budget. It is exclusive
with fixed-IPBus and DSP-TIO MIDI sources; their existing contracts remain.
This is a C++ reference API, not calibrated Desktop/Keyboard wiring or a new CLI.
If SCI samples before a later configured start, supply an explicit initial
idle-high pad observation; the API does not invent pre-start pad knowledge.

The existing pipeline scheduler applies rational 31250-baud 8N1 pad events during
held POR, native execution and WAI. The MCU alone clocks SCI/TIM/OSC. Enqueue
preserves the pinned free-running bit grid. Snapshots retain queue, partial frame
and deadline. Source collisions and exhausted event budgets fail visibly.

HostMidiSession owns an ordinary Linux sequencer port outside checkpoints. Polls
admit at most 256 bytes within remaining wire capacity and check kernel loss even
when that capacity is zero. Every call checks board identity, monotonic external
restore revision and time before its poll deadline. Restore, owner changes,
transport/native faults and failed admission retire the port; consumed prefixes
must never be retried. A fresh session starts with a fresh kernel queue.

If Board output capture is configured, every poll additionally drains its actual
native SCI bytes through the same bidirectional host port, independently of the
input poll deadline. flush_output() explicitly services output, including after
the operation budget ends. It requires a configured output, checks ownership,
restore revision and time against both directions, then retires at most256 queued
bytes into the existing host MIDI encoder. A host failure can follow an already
delivered prefix; it closes the session and cannot retry consumed guest bytes.
An empty queue produces no response. Output does not advance emulated clocks.
Host parser/partial-message state stays outside modeled snapshots. Kernel pool
negotiation and packetization retain host-midi-port.txt's actual-grant contract.

This remains a reference API, separate from the CLI's file/raw-device input pump
and the pending normal-profile launcher. It does not establish original firmware
replies, physical MIDI-Out wiring, wall-clock output pacing or USB enumeration.

Reproduce with separate strict and thread sanitizer presets:
  cmake --build --preset strict --target blofeld-host-midi-session-test blofeld-host-midi-output-session-test
  ctest --test-dir build/strict -R '^host_midi_(session|output_session)$' --output-on-failure
For input-wire changes additionally use sci_midi_timeline; standard-tool input
interoperability is a separate host_midi_session_tools check.

Directed checks cover literal bits during held reset without IPBus periods,
WAI, native divider setup, partial-frame restore, event-budget failures and
256 native byte reads on each route. Actual owned ALSA endpoints and aseqsend
exercise notes, controllers, program changes, realtime and SysEx through native
SCI register reads. Backpressure retains a three-byte message across successive
single-byte admissions. Same-time restore discards unread host backlog; foreign
owners, absent routes, exhausted execution budgets, trace failures and unsupported
kernel events reject. Only owned virtual ports receive traffic. Unavailable ALSA
or tools skip explicitly; a skip is not transport qualification.

The output integration additionally runs authored native MCU reset/SCI/WAI on
both TX pads. Independent raw kernel records verify two notes with running
status, realtime clock and complete literal SysEx. A distant input-poll deadline
cannot delay output. Same-time restore refuses before consuming or repeating
restored output; a fresh explicit session can bind it. Cross-direction foreign
owners, absent routes and trace failures retire visibly. Final output drains
without another guest operation. The new output and affected existing input
test executables pass both sanitizer profiles, with zero compiler/format/tidy
findings and verified ELF/core identity. See host-midi-output-session-reference.json.

SCI stop-majority-to-RDRF timing remains unresolved. Positive receive experiments
explicitly select SciReceiveReference(SBR12/6, zero transfer delay). Without that
hypothesis, native polling still faults at 0x00cc; the host never repairs it.
Normal profiles, complete original firmware reception/USB-MIDI, wall-clock pacing,
calibrated timing, sustained original DSP audio and hardware equivalence remain open.
