HC12 instruction translation and invalidation

The reference interpreter executes one original instruction per step. It retains
at most 128 immutable P-code translations, keyed by PC, and discards the working
set when a new translation would exceed that limit. It never substitutes a host
loop for firmware execution. Registers, flags, branches and bus loads/stores are
evaluated again on every visit. Execution permissions are checked before lookup
and across the entire instruction before executing even a cached translation.

Bus::code_revision defaults to the general write revision. A backend without
specialized tracking therefore retains conservative all-write invalidation.
McuBus records the union of bytes observed by every decoder, including lookahead.
Only writes overlapping that union invalidate translations; unrelated RAM data
writes still advance the general revision. Both bytes of word writes are checked.
Committed memory-map changes and external reset invalidate all translations.
Reset also clears the observed-byte set; surviving CPU instances must refresh
against the changed generation before executing retained RAM code.

Decoder refresh clears owned P-code before resetting native SLEIGH. Each cached
entry owns its emitted operations and varnodes. Cache eviction occurs between
instructions. Self-modifying code refreshes before the following step; attempts
to invalidate an instruction from a reentrant IO callback fail explicitly before
freeing any active operation. Exception unwinding releases that execution guard.

Native register access
The D/IX/IY/SP/CCR/PC descriptions are copied from SLEIGH into CPU-owned storage
after initialization and every decoder refresh. They contain address-space,
offset and width, never register values. State inspection, debug replacement,
interrupt stacking and the executor's PC writes use these descriptions to avoid
repeated symbol-name searches. Every access still reads/writes the live native
register bank; its overlapping registers and P-code flag operations are unchanged.
The executor references the stable CPU-owned PC description, not a symbol-table
entry. Refresh replaces that description in place before execution resumes.

Verification
  build/strict/blofeld-code-cache-test
  cmake --build build/strict --target quality

Independent synthetic cases cover immediate/opcode/branch rewrites, native
self-modifying stores, byte and word invalidation, mapping and unknown-RAM
permissions, retained RAM across reset, multiple decoders sharing a bus, live
register/flag/data changes, capacity eviction and rejected reentrant refresh.
The generic bus regression also checks default all-write invalidation.

Three serial local ASan/UBSan runs of the same 90314-instruction fixture had
median times of 7.63 seconds with register-name searches and 3.35 seconds with
copied register descriptions. All six traces have the first SHA-256 above.
Complete original flash-command, MCU sender, parallel-transfer and LCD-helper
traces also remain byte-identical. A longer private startup preserves the whole
earlier eight-million-step diagnostic trace prefix; mcu-rti.txt describes its
conditional pin/clock inputs and later native main-WAI result.
These diagnostic runs include tracing and are not controlled benchmarks, release
performance measurements or evidence of real-time suitability.

Limits
This is an interpreter cache-coherence contract, not a model of the CPU12 physical
instruction queue, prefetch bus cycles or pipeline behavior. No CPU/peripheral
cycle scheduler or audio callback has been established. See mcu-boot.txt and
coverage.txt for the remaining complete-board requirements.
