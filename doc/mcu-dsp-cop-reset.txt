Native MCU/DSP COP and external reset

mcu_dsp_fetch_reset uses McuDspRuntime and dsp56300 exclusively. Authored MCU
BRA/LDS/WAI and DSP MOVE/CLR/ADD/BRA code runs through real reset vectors and
native instruction effects. DSP execution follows 450 actual held common ticks,
90 recovery ticks and 45-tick reference periods. This is an explicit effect-per-
reference-cycle profile; physical board reset nets and silicon stage timing
remain unqualified.

31 cases retain independent expectations: four external reset synchronization
profiles, 20 complete watchdog timeouts/recoveries and seven strict controls.
The timeout matrix spans all five OSC phases, OSC/PHY MCU clocks and run/WAI.
A 16384-OSC-edge COP timeout occurs after 81920-phase MCU timebase ticks.
Only floor((duration-1)/period) whole IPBus periods complete, including when the
reset request coincides with the offered period endpoint. The period is 10 MCU
ticks under OSC or 2 under PHY; the shared DSP timebase conversion remains 9.

MCU-only timing failure now makes the coordinator report faulted, even while
the DSP clock/core remain healthy. Ordinary execution/capture requires a
healthy MCU. Explicit system-reset admission independently validates the DSP
owner, consumed time, qualified reset order and any retained COP deadline;
it can therefore recover the actual MCU reset cause without resetting the DSP.
A missing or mismatched cause cannot turn the shortened interval into success.

Each of the 20 timeout cases reaches an actual 131-SYSCLK reset checkpoint and
restores its remaining 64 edges plus five vector periods twice (40 suffixes).
The actual FFFA COP vector selects $8100; external FFFE selects $8000. Native
DSP retirement PCs and full accumulator results remain independently checked.
Registers/flags, progress, pending effects, F1 addresses, F2 capture, reference
completion ticks and CLK2 ledgers match across the two restored suffixes.
External reset separately retains MCU SRAM, oscillator phase and DSP work.

Unknown RESET-pad sampling, wrong SYSCLK duration/epoch, an unconsumed reset
offer and unqualified reset/COP policies refuse before unsupported progress.
An unconsumed first reset offer advances only one 45-tick DSP recovery slice;
no DSP instruction period can replace its missing MCU edge. A genuine reserved
Y:$2000 store during reset fails at DSP PC $ff0004/attempted tick990, retaining
11 consumed MCU reset edges and 9 completed DSP periods. No fabricated opcode,
successful peripheral response or manufacturer program bytes are supplied.

  cmake --build --preset strict --target blofeld-mcu-dsp-fetch-reset-test
  ctest --test-dir build/strict -j1 --output-on-failure -R '^mcu_dsp_fetch_reset$'

Selectors external, cop, wai-cop, failure and unconsumed run bounded individual
paths during diagnosis. The default CTest always runs the complete 31-case
matrix. The thread preset checks the same ownership under TSan; concurrent
MCU/DSP execution, full original firmware boot and instrument acceptance remain
separate open requirements. No fuzzing or physical-device traffic is involved.
