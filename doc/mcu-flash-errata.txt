Observed manufacturer statements
- The byte-write errata describe a MOVB array write starting a command without
  ACCERR. Word programming follows, but only FDATA's high byte is valid. The
  low byte is not specified; a guessed complete programmed word is unsupported.
- An array write immediately following FPROT can omit PVIOL. The errata do not
  establish that protected contents can be successfully programmed. NXP's
  workaround inserts a legal register write before the array write.
- On 0L24N, STOP with FCLKDIV loaded and CCIF set spuriously sets ACCERR.
  On 1L79R, STOP after physical completion but before CCIF can omit ACCERR.
  These are distinct conditions requiring qualified internal timing.
- On 0L47S/1L47S, reset with FF0F.SEC=00/01/11 enables security and the BDM
  mass-erase/security-byte reprogram sequence cannot unsecure the device: its
  secure-firmware blank check fails. The documented alternatives depend on
  SEC=10 before reset or an executable application security-programming path.
  Neither establishes recovery after arbitrary interrupted firmware writes.

Emulator qualification
No target MCU mask has been established. The five-character mask marking is
distinct from its four-digit manufacturing date code. A missing erratum in
another mask's list is not evidence that its silicon follows nominal behavior.

Current McuFlash checks the S12FTS32KV1 nominal normal-mode reference; it does
not select a measured UF32 mask or implement these silicon anomalies. In
particular, byte-write ACCERR and immediate protection-error tests are nominal
module expectations, not hardware equivalence. STOP/BDM remain unsupported;
no emulator BDM mass-erase recovery guarantee exists. CPU, timer, SCI, IQUE and
other entries in these sheets require separate qualification.

The original helper's forced SEC=10 path is tested conditionally on explicit
successful reference milestones. Unknown interrupted security bytes remain
unknown. Successful isolated finalization does not prove an intact executable
application/recovery path after a cut (mcu-flash-commands.txt).

None of these errata resolves idle FSTAT writes with CBEIF=1 and no staged
command. The visible qualification fault and original initialization frontier
remain unchanged. Do not infer a no-op, automatic completion or silicon mask
from the firmware's BSET instruction.
