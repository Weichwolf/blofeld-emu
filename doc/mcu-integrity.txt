CPU integrity at runtime callbacks

The CPU owns a host-only identity and monotonic mutation revision. Read-only
runtime callbacks compare this stamp plus the existing nine clock/wait/fault
fields. reset, debug replacement, trusted restore, step and committed WAI clocks
invalidate the stamp before mutation. Equal-value writes and mutate/revert pairs
are rejected too. Owner/revision exhaustion fails visibly; identities never wrap.

There is no CPU register cache. Full register/clock comparisons remain available
for semantic checkpoint/clone tests. Tokens are neither guest state nor persisted
checkpoint contents. The CPU remains single-thread owned; inspection_stamp is a
nonallocating noexcept getter, not cross-thread synchronization or real-time proof.

Authored controls cover literal LDD/LDX and debug results, WAI clocks, failed
native access, fresh-owner restores,44 forbidden mutations across four callback
lanes and four read-only lanes. Native runtime/peripheral ordering, running DSP,
WAI, reset and clone groups also pass ASan/UBSan and separate TSan. The connected
Board integration is qualified separately. Source/evidence: mcu-integrity-reference.json.

Explicit developer commands, using either strict or thread:
  cmake --build build/strict --parallel 2 --target blofeld-mcu-integrity-test blofeld-mcu-boundary-benchmark
  ctest --test-dir build/strict --output-on-failure -R '^mcu_integrity$'
  build/strict/blofeld-mcu-boundary-benchmark

The benchmark is excluded from default builds and has no CTest registration.
It compares200000 read-only queries per case, full/stamp/stamp/full. This host's
instrumented O1 measurements gave6.87x (ASan/UBSan) and4.08x (TSan) lower query
cost. These are query-only ratios; full-emulator throughput and real-time
operation remain unmeasured. No firmware experiment is rerun by the benchmark.
