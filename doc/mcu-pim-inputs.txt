PIM input register candidate

S12UF32PIMV2 V02.05 section3.1.5 permits up to two bus cycles before PTQ/PTIQ
reflect a DDRQ change; its general register-read note requires internal clock
synchronization. This does not identify a measured steady-input latency or a
physical flip-flop count. Reference hashes/URLs remain in hardware/sources.json.

The functional candidate samples resolved PIM pins in two clocked registers.
After an IPBus edge, input reads see the preceding edge's sample. Unknown and
conflict masks propagate; no last-good value is retained after release.
PTx output bits still read the output latch immediately. PTIx always reads pin
history. Physical observations and SCI/timer input paths remain separate.

Only McuRunClock advances the bus input path, once per completed run/WAI bus
period. Duration offers, register reads and observer callbacks create no edges.
Clock-route changes retain history; reset clears it. Copies retain both stages
but must reconnect external pad providers. Unclocked transaction fixtures retain
their existing direct semantics until a native clock stream is attached.

Authored regressions cover registers, masks, direction, WAI, divider/PHY changes,
reset, copies and pad rebinding. A local replay of recorded original source pins
predicts 32 correct bytes with unchanged clocks and original page data; this is
not an original-firmware boot or a complete 528-byte transport observation.

Ordinary-memory inspection returns decoded space, physical offset and optional
value without a guest read. Unknown storage and I/O have no value. Board range
inspection requires an inactive boundary, including a failed diagnostic boundary;
it does not acknowledge peripherals, advance clocks or clear faults.
