McuDspSchedule::begin_system_reset(source,n,dsp_before_mcu) admits an explicit
inactive reset event only at a consumed MCU/DSP time boundary. It advances the
MCU epoch through the actual owned reset API; DSP state, epoch, clock fraction,
instruction counts and pending scheduled work remain continuous. It does not
assert a DSP reset pin or assign a new CPU PC. Unconsumed/overshot time, pending
idle/shared-write offers and poisoned DSP state reject rather than retime/rewind.
Reset propagation still requires board qualification.

McuRunClock::next_period offers a pure COP-aware duration. A timeout shortens
the reference period to its actual OSC edge, including an exact-end deadline;
the failed IPBus/idle period never counts as completed. Joint DSP execution stops
at that same boundary. A preempted shared write has no bus transfer or observation
to complete. Only the actual owned timeout permits discarding this pending offer
when beginning explicit reset; unrelated faults/missing time still reject.
COPWAI gates idle offers only. Existing DSP-before-MCU reference observation order
remains an explicit scheduling contract, not measured reset-pin timing.

After reset assertion, reconnect required GPIO sources and native observers.
McuMachine::set_reset_period_observer receives qualified McuResetPeriod inputs
before each committed SYSCLK edge. begin_reset_period advances native DSP and
external events through that exact common-time boundary, without inventing a CPU
bus slot. Once pad arbitration permits release, ordinary cycle observation clocks
the real native VfPPP reset sequence. end_system_reset validates its completed
boundary. The observer cannot restore, checkpoint or recursively advance the
active MCU owner. A failed peer operation preserves its actual completed prefix
and quarantines joint scheduling. An unknown final RESET sample advances neither
owner for that unqualified edge.

Joint reset checkpoints retain the actual source/phase/synchronization/edge
state, OSC rate and next-edge fraction instead of inventing an executable MCU
state while reset holds. Both native owners must be restored before the schedule;
different MCU reset metadata/phase or DSP progress reject before schedule commit.
Drive, settling, external-hold and completed boundaries replay in the new MCU
epoch. An active edge/vector callback or poisoned owner cannot be captured.
External callbacks, pad routes and event cursors remain caller-owned and must be
restored/reconnected. These are trusted in-process checkpoints, not persistent
whole-board snapshots or a hardware recovery procedure.

Two documented electrical/reset facts remove false prerequisites:
- The fixed normal-single-chip MEBI profile resets PEAR.NECLK to1 (PEAR10),
  releasing PE4 as GPIO. It does not start with ECLK selected. MODE strap sampling,
  other MEBI modes and explicitly selected ECLK remain unqualified.
- DspBus::observe_irqa_driver resolves the post-boot IRQA input against its
  documented internal pull-up. A released MCU driver becomes a deasserted level;
  known strong low dominates. Unknown active drivers or opposed passive pulls
  remain unknown, with enabled consumption failing through the IRQ controller.

PB0 alone cannot qualify as DSP RESET: display initialization leaves DDRB=f7,
PORTB=80, hence PB0 output-low; physical LCD transfers also end at80. Direct
active-low wiring would hold the DSP in reset; unconditional inversion conflicts
with PB0-high serial boot. Additional gating is not evidenced.
PU0 is a stronger source-consistent reset/readback candidate: PTU=00/DDRU=01
holds low through all delays; DDRU=00 atb98a releases it before the bit0 poll.
DSP RESET has an internal pull-up (DSP56371UM table2-6). Continuity is unproved;
direct active-low HREQ has the opposite ready polarity. The original BRCLR
observes only PU0; the selected-bit native interface preserves unknown unused
inputs (hc12-masked-gpio.txt).
