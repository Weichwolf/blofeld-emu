MC9S12UF32 normal-run reference clock

McuRunClock couples each completed HCS12 reference bus cycle to SCI/TIM bus time
and the oscillator edges driving CRG_U RTI. McuClock::run_clock_route observes
native PLLSEL, REFDV and qualified LOCK without modifying them. An unlocked PHY
falls back to OSC; an unknown qualification fails with the relocated CLKSEL
address, operation, PC and CCR. No host writes a ready flag or interrupt request.

Clock contract
The selected source is OSC or the nominal 60 MHz USB PHY clock. The CPU/IP bus
rate is source / (2 * (REFDV+1)): the device's 60 MHz operating rate corresponds
to a 30 MHz CPU bus. The caller supplies oscillator frequency, initial oscillator
phase and an explicit reference-cycle-boundary switching contract. Omitting the
contract rejects. This ideal boundary rule is a reference assumption, not a
measurement or implementation of analog clock switching/dead time.

The timebase is LCM(OSC Hz, 60000000) ticks per second, computed in 64 bits.
Each source/divider combination contributes an integer number of these ticks;
oscillator fractions survive source switches and lock-loss fallback. No floating
point rounding or per-switch phase reset occurs. Initial phase must be smaller
than one oscillator period in this timebase. The accepted OSC range is 0.5..40 MHz.
Selecting the nominal 60 MHz PHY requires the nominal 12 MHz oscillator; other
OSC rates may run from OSC, but their PHY timing remains unqualified. A 15-edge
observation in three OSC periods cannot independently establish an arbitrary
60 MHz PHY/OSC relation. LOCK observations are still supplied separately.

At OSC=12 MHz the common timebase is 60 MHz:
  REFDV    OSC-selected bus       PHY-selected bus       RTI clock
    0       6 MHz / 10 ticks       30 MHz / 2 ticks        12 MHz OSC
   15     375 kHz / 160 ticks    1.875 MHz / 32 ticks        12 MHz OSC
These are digital reference ratios, not guarantees outside the device's specified
operating conditions. The counter advances SCI/TIM once per CPU bus cycle and
RTI by the number of OSC edges elapsed. Clock/operand callbacks precede native
operand commit, so a CLKSEL write affects the following reference cycle.

Failure and ownership
The clock stores no CPU, bus, pad-source or transport references. A trusted copy
retains fractional phase and counters; it is not a persistent or whole-board
checkpoint. A peripheral clock failure can leave earlier peripheral effects in
place, and latches the clock against retry. An outer CPU/data-access failure also
requires coordinated CPU/bus/clock recovery. Counters report completed cycles;
they are not a transaction rollback. MIDI/pad observations remain caller-owned.
A separate owned WAI API now advances idle IPBus/OSC time and honors SCI/TIM
wait gates (mcu-wait-clock.txt). CRG wait shutdown, STOP/BDM gates, physical
switching, external wait states, asynchronous pad propagation, PHY acquisition
and DSP scheduling remain unqualified.
The default standalone CLI remains untimed. Dynamic-rate host MIDI and complete
MCU/DSP board ownership still require integration.

McuMachine now optionally owns the cycle adapter and run clock under an explicit
McuRunContract. Its trusted checkpoint restores CPU, bus, run-clock phase/counters
and timer observation mask together, and rejects failed/incomplete boundaries or
incompatible contracts. External cycle/bus observers are excluded and must be
reattached. Live mapped-memory guards qualify operands; no wait-state or physical
prefetch model is added. See mcu-checkpoints.txt for the API and regressions.
The default constructor and standalone CLI remain untimed. Owned idle WAI time
is separate from native CPU cycle callbacks; whole-board/transport scheduling
remains pending (mcu-wait-clock.txt).

Flash read alignment
The un-stretched contract retains its rejection of odd Flash word operands.
The explicit internal_flash_reads contract implements the two read cycles from
S12FTS32KV1 section 1.1, with each byte latched after its own clock and native
operand semantics preserved. See mcu-flash-read-timing.txt for independent phase,
value/flag, failure and checkpoint checks. Firmware data placement is unchanged.
The source-fed original_owned_clock regression reaches main WAI under the
controlled inputs and continues through native idle RTI wake/return. Owned WAI
idle clocks have separate independent regressions (mcu-wait-clock.txt). Full
MCU/DSP scheduling remains unimplemented.

Evidence
  cmake --build --preset strict --target blofeld-mcu-run-clock-test blofeld-original-cycle-application-test blofeld-original-run-clock-test
  ctest --test-dir build/strict -R '^(mcu_run_clock|original_cycle_application|original_run_clock)$' --output-on-failure

mcu_run_clock checks all 16 software dividers against literal source rates and
elapsed counts, fractional switches/lock loss, trusted copies, explicit initial
phase, a coprime 64-bit timebase, invalid/unknown sources, relocation and latched
peripheral failure. Own native instructions produce two real RTI interrupts,
acknowledge RTIF and return at 3108 and 5146 bus cycles. Independent instruction
costs, CLI deferral, a three-cycle branch crossing the next timeout, saved CPU
state and oscillator phase supply the expectations; no period is injected at a
foreground poll.

original_cycle_application retains its two strict capture/PU failures and NVM
checks under explicit 12 MHz OSC, phase 0, ideal-boundary switches and idle PR2.
The unobserved capture case completes 233807 bus cycles / 468214 timebase ticks /
93642 OSC edges. The controlled PT0 handover reaches the unchanged unknown PU
input after 4850623 cycles / 9701910 ticks / 1940382 OSC edges. Native RTICTL=0x40
leaves 4679 OSC edges to its next timeout and RTIF set while the CPU masks IRQs.
CLKSEL writes at cycles 75, 233898, 233906 yield 83 OSC-selected bus cycles at 10 ticks,
and the remaining PHY-selected cycles at 2 ticks. These independent register-event
and rate calculations check the accumulated phase and RTI behavior.

original_run_clock supplies the existing explicit GPIO/USB/LCD/ready observations
and continues through the original first RTI handler, without host MCU RAM/PC or
RTI-period injection. After 1944294 retired instructions and one interrupt entry,
it restores every foreground register at 5618487 bus cycles. The real nine-byte
frame has the independent NXP layout, and the original handler clears RTIF.
A separate retired PC/CCR census and manual mnemonic/address-mode costs give
5618473 instruction cycles + 5 reset + 9 IRQ entry. The census uses the clocked
path; its cost calculation does not call the production timing decoder. The
source ledger gives 11237638 timebase ticks, 2247527 OSC edges and 638 edges to the
next RTI period. Traces/census remain local; public tests pin the firmware hash.
These observations establish a conditional first native handler, not the complete
startup countdown, MCU/DSP board boot, physical ready peer, host MIDI/audio or
Desktop/Keyboard hardware equivalence.


Original owned-clock regression
The complete source-built 1.25 MID matches the pinned original MID SHA-256
447f7ec928b5b4144fad2193351f0604011f2ab8ed9b9dbe3d1bb7c594e813c0.
original_owned_clock uses internal_flash_reads, the same 12 MHz OSC/phase-zero
ideal-boundary clock contract and explicit GPIO/PHY/LCD/ready fixture. No host
writes MCU RAM/PC/CCR or injects oscillator periods at foreground polls.

The strict missing-PM3 input stops after 53382260 retired instructions, 6448 IRQ
entries and 137638117 completed cycles. Manual instruction costs give 137580079
cycles + 5 reset + 6448*9 IRQ + 1 failed input-read clock. Every original RTI
restores the foreground register state. A coordinated pre-input checkpoint at
137638116 cycles recovers this failure with the caller-owned LCD fixture rebound.

Controlled PM3 low/high each retire 1570072 further instructions and enter 203
IRQs before the original main WAI. Each completes 141809799 total bus cycles;
the continuation independently accounts for 4169786 instruction cycles + 203*9
IRQ cycles + 70 expanded Flash words. Each word has consecutive high/low byte
callbacks, with the low clock immediately following the high clock. The native
nine-byte WAI frame, saved raw PM3 value and unchanged NVM bytes/knowledge/history
match. Display counts are 344 commands, 4194 writes and 2244 reads in each case.
The owned clock reports 283620262 timebase ticks and 56724052 OSC edges.

Each continuation completes after 1570275 steps with a 20000000-step bound.
The complete successful path is 54952332 retired instructions, 6651 IRQ entries,
5 reset cycles and 70 extra Flash cycles. The tracked wrapper pins the original
ZIP or identical complete source MID and retains private traces, census, phase
ledgers and executable/input hashes as ignored run artifacts.

Native CLKSEL=0x80 leaves system clocks running in WAI; SCI/TIM wait gates are
clear. The original RTICTL write at bus cycle 233874 and source-switch ledger
predict 913 remaining OSC edges, requiring 2282 idle IPBus periods. A trusted
checkpoint after 1000 periods is restored for two native wake/return runs per
PM3 level. The first RTI reuses the WAI frame in six cycles. Its handler and
foreground retire 1358 instructions at 4028 manual cycles and reach WAI again
at 141816115 total periods, 283632894 ticks and 56726578 OSC edges. Full-register
restoration, RTIF acknowledgement, native WAI frame, saved input, unchanged NVM
and equal independent replay/cost/phase records agree. No host period or CPU
state is injected. This still does not qualify inferred board inputs, physical
Flash strobes, a real DSP peer, audio or Desktop/Keyboard hardware profiles.
See mcu-wait-clock.txt for the API, strict unsupported gates and commands.
