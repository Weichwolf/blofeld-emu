HC12 internal p-code storage

The HC12 uses direct word arrays for the first 256 register bytes and 32 KiB of
SLEIGH unique temporaries. Other internal addresses retain the original sparse
MemoryHashOverlay. These are host storage choices, not emulated address limits.
The zero initial state, aligned-word representation and MemoryBank byte packing
are unchanged. The hardware BusBank, clocks, interrupts and execution semantics
are unchanged. No controller JIT is introduced by this change.

Focused optimized Release qualification:

  cmake --build build/release --target blofeld-pcode-storage-test \
    blofeld-hc12-ccr-test blofeld-mcu-checkpoint-test blofeld-headless -j2
  ctest --test-dir build/release --output-on-failure \
    -R '^(pcode_storage|hc12_ccr|mcu_checkpoint)$'

The storage test checks independent LE/BE byte expectations, sizes 1..8,
unaligned values across word/cache boundaries, neighboring bytes, sparse 64-bit
addresses and aligned checkpoint images. The existing HC12 matrix passes all
393,216 independently expected CCR cases and actual XIRQ/reset cases. Existing
MCU checkpoints pass native replay, WAI/RTI, isolation and failure guards.
The storage test supplies width-bounded p-code values. Raw over-width writes and
the upstream bank's unaligned chunk implementation are outside this change's
qualification; neither inherited algorithm was replaced.

Explicit CPU-only measurement, never run automatically by CTest:

  cmake --build build/release --target blofeld-mcu-execution-benchmark -j2
  build/release/blofeld-mcu-execution-benchmark

The authored loop executes LDAA/ADDA/STAA/BRA two million times, checks its final
PC/accumulator and 500,000 real bus stores, and reports monotonic host time.
With identical O3/native/ThinLTO options, the initial idle comparison takes
2.098515551 seconds with the published c6072b3 HC12 versus 1.776456769 seconds
with direct storage: about 18.1% more instructions per host second. This is one
CPU-only comparison on the development host. Later samples overlap a separately
running original-reset experiment and are excluded from idle qualification.
No connected-emulator speedup or real-time milestone is established.
See mcu-storage-reference.json for exact source, executable and evidence pins.

Compiler warnings remain errors and clang-tidy has zero findings for the changed
sources. Broad regression and sanitizer matrices are deferred until original
firmware real-time operation. No fuzzing was run.
