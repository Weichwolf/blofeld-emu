McuMachine::begin_system_reset(source,synchronization_cycles) admits an inactive
owned MCU event; COP requires an actual pending watchdog request. Synchronization
must be explicitly3..6 SYSCLK cycles. It resets modeled modules, retains SRAM/NVM,
replaces native objects and advances the MCU epoch. Old references/observers and
GPIO readers must be reattached. Existing resolved-pad obligations remain strict;
a detached input is never replaced by a guessed voltage. SCI/TIM clocking and
native execution stay held. No implicit board reset policy is selected.

advance_system_reset(maximum_sysclk_edges,pad) advances actual OSC/SYSCLK edges:
- RESET is driven low for128+n edges, then released for64 settling edges.
- High at the final sample selects COPfffa or externalfffe. External low overrides
  COP, holds internal reset and selectsfffe on a later observed high edge.
- Unknown pad observations fail before committing a source-sampling edge. The
  owner is quarantined; trusted pre-event/mid-reset restore is required.
- The native VfPPP CPU reset fetches the selected vector in five IPBus cycles.
  PC is never replaced by a host-assigned restart address. Unknown vector bytes
  fail visibly. Offers stop at the first completed reset, even with a larger bound.

Reset SYSCLK edges advance lifetime ticks/OSC counts separately from completed
native/idle IPBus periods. A COP timeout preserves time up to its actual deadline,
including the uncompleted IPBus period; it does not first clock SCI/TIM for that
failed period. Reset returns to OSC because PHY/module state is reset. Mid-reset
checkpoints retain pulse phase, source, lifetime clocks and epoch; CPU reset state
is withheld until native vector fetch. Restore keeps the existing backend/run
contract checks. Old MCU/DSP scheduling rejects a changed MCU epoch and cannot
advance a healthy independent DSP through a reset gap using stale wiring.

Tests use literal pulse/vector/cycle expectations, all four synchronization
lengths and both sources; source override/hold/unknown pads, native vector slots,
checkpoint replay, repeated resets, WAI timeout time, missing vectors and invalid
admission are checked. Program and sector erase are reset at staged/selected/
buffered/active/completed milestones. Active damage stays unknown; completed NVM,
known bits, erase history, protection/security and volatile reset defaults are
checked independently. Milestones do not qualify physical flash latency.

original_update_coupled now uses the explicit joint reset path described in
mcu-reset-coupling.txt. Nativefffa fetch still selects the unchanged resident
loader; the same DSP continues across SYSCLK/native-vector boundaries. The fixed
normal-single-chip PEAR reset is10, so PE4 starts as GPIO. Startup then fails on
an actually consumed opposed-pull Q7 net, not a fabricated ECLK requirement.
This is not complete whole-board reset/boot. Power-on ramps, asynchronous external
retriggering, physical pin/switch latency, measured synchronization phase and
DSP/board reset propagation remain unqualified.
