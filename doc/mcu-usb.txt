MC9S12UF32 USB configuration window and limits

Current scope
This implements UEPCSELR at 0x030e..0x030f and the banked UUCFGR window at
0x0310..0x0313, before controller enable. It does not yet implement USB tokens,
enumeration, endpoint transfers, USB interrupt masks/status, buffer RAM, reset
commands or a host transport. MEN still fails visibly; no ready/completion flags
are fabricated. Existing UMCR/PHY-clock behavior is described in mcu-model.txt.

Configuration semantics
- UCRSEL selects five physical endpoint registers (1..5), UNCIR (8) or UNASR (9).
  Every bank resets to zero and has independent 32-bit storage. Reserved selector
  bits read zero. Reserved selections fail on window access instead of aliasing
  another bank. EPBSEL0/1 are stored/masked separately; buffer access is pending.
- UUCFGR requires a high 16-bit operand write followed by a low 16-bit operand
  write. The upper word is staged; only the lower word commits the complete
  selected value. Reads during staging still return the old committed value.
  Byte writes, misaligned words, one 32-bit operand, or a low word with unknown
  upper-word staging fail explicitly. Changing UCRSEL between staged words is
  unspecified by the guide and fails; changing only buffer selectors is allowed.
- UNCIR implements mask 0x00000773. Reserved configuration/interface count values
  fail rather than being treated as supported host configurations. UNASR retains
  all eight alternate-setting nibbles. Endpoint fields are stored; their active
  transfer rules and cross-endpoint constraints require the pending USB engine.
- External reset clears selectors, every bank and the staging latch. MCU register
  relocation preserves bank values and staging. Clock-disabled writes are not
  specified sufficiently for this model and fail; no clockless success is assumed.

CPU integration
Native HC12 p-code LOAD/STORE preserves each logical operand width in
Bus::read_memory/write_memory. Normal transfers visit ascending addresses,
most significant byte first, without synthetic read-before-write. This distinguishes
STD's 16-bit operands from STAA's 8-bit operands. It is not a claim that unaligned
or peripheral word accesses occupy one physical bus cycle. Precise bus timing,
cross-address-space-boundary behavior and shared CPU/peripheral time are pending.

Reset/interrupt vector reads and hardware stack writes expose their widths too.
A local SLEIGH correction restores B:A with one word during RTI, rather than two
separate byte transfers. The independent width check fails before that correction.
The byte-memory dependency patch is retained for native memory-bank fallback;
the width-aware CPU load/store path now accesses the board bus directly.

Tests and original-firmware evidence
Run build/strict/blofeld-memory-usb-test or the full quality target. Independent
vectors check operand width/byte order, partial write faults, invalid ranges,
separate banks, staging/commit timing, reserved bits, reset and relocation. An
own HC12 program performs the selector/high-word/low-word sequence and reads
back the result into RAM; a later byte write must fail. No vendor program bytes
are embedded. IRQ entry and RTI word-transfer counts are checked independently.

The unmodified original application passes UNCIR setup in the explicit untimed
private fixture and then stops after 90391 completed instructions at PC 0xbec2,
writing UIMR. This is only a configuration observation, not USB initialization or
a completed Blofeld boot. Physical wiring and stock hardware remain unvalidated.
