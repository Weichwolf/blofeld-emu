Reusable NAND board connection

blofeld_nand_peer promotes the project-owned native NAND fixture into
src/board/nand_peer.{hpp,cpp}. It connects the modeled cell array, protocol,
write/read timing, output driver and Ready input to the native dsp56300 owner.
It does not load DSP program records directly. Native tests retain a small
compatibility header and execute the same board implementation.

The explicit connection uses Port C RE/WE/CLE/ALE, Port F data and timer1 DI
Ready. CE is held selected in this candidate profile. A 100us power-ready
reference and the chosen NAND read-continuation profile are declared model
assumptions, not observations of a fitted part. Firmware correctness is judged
as an instrument; physical part identification is not an acceptance gate.
Unknown cells, invalid commands and missed deadlines remain visible failures.

Ready also feeds Timer1's capture stage. The functional board observes the
device's actual known R/B level at each published NAND boundary, including
Busy caused by a native GPIO latch and Ready caused by its scheduled completion.
This establishes the baseline before capture arming and delivers real selected
edges afterward. Unknown power-on Ready remains unknown. Repeated levels cannot
capture, acknowledge an IRQ or restart a halted counter. This contract does not
claim a calibrated silicon synchronizer delay; the raw/synchronized distinction
and all unknown-input guards remain in the standalone timer model.

The authored nand_capture test uses native GPIO commands, both capture
polarities, both bus contracts and 540/1080MHz timebases. It checks CLK/2 capture
values independently, executes an actual two-word native interrupt vector,
resumes its foreground and repeats a joint checkpoint continuation. The peer
timebase test also checks fresh-owner capture baseline without a false edge.
All eleven affected timer, NAND, checkpoint and audio-clock groups pass under
ASan/UBSan and separate TSan with strict compilation and zero tidy findings.
An isolated original-firmware continuation reaches the actual Timer1 vector
and stops at unknown initial page 0x360; it emits initialization silence only.
See own-dsp-nand-reference.json/functional_ready_capture_candidate.
A separate one-page-erased initial-state experiment retains the exact ELF and
all previous image cells. The original firmware reads/stores 528 bytes and
executes 15 table-decoder stores before requesting unknown Global settings at
page 0x11e0. Both suffixes match; audio remains silent. This does not establish
manufacturer table contents or a factory NAND image.

All interval conversions use the native owner's timebase. The new timebase test
checks independently expected 54000/108000 tick power events at 540/1080MHz,
unknown initial Ready, incorrect-event rejection, same-rate clones and atomic
rejection of incompatible clocks. A second live pad owner is rejected before
changing the established peer's Ready input. There is no production 1080MHz
constant.
The autonomous scheduler must dispatch exactly the offered completion/output
boundary before the next CPU observation.

The board attaches a resolved Port-F pad reader. DSP and NAND output intentions
remain separate; opposing active levels are unknown at a read. Transient driver
overlap between native instructions alone does not stop execution. NAND command,
address and data latches sample resolved pads on real WE events, so contention
cannot silently program a chosen value. Unused overlap supplies no success or
sample. Native snapshot restoration detaches borrowed pad bindings; trusted peer
payload restoration is staged before reattachment. Expired peer callbacks fail
before accessing destroyed state.

  cmake --build --preset strict --target blofeld-nand-peer-timebase-test \
    blofeld-nand-native-runtime-test blofeld-nand-write-medium-test \
    blofeld-nand-busy-status-test blofeld-dsp-gpio-write-decoder-test \
    blofeld-dsp-gpio-test
  ctest --preset strict -j1 --output-on-failure \
    -R '^(nand_peer_timebase|nand_native_runtime|nand_write_medium|nand_busy_status|dsp_gpio_write_decoder|dsp_gpio)$'

These six groups pass under ASan/UBSan and separate TSan. Warnings-as-errors,
clang-format and clang-tidy remain enabled. Validation scope is the reusable
connection and its native component continuations. Connected original reset/NAND
loading is being investigated separately; complete boot, original audio,
MIDI/USB, reset/update/recovery and all instrument functions are not qualified
by these component results. No fuzzing or physical-device traffic was used.

Regular headless Board connection

The optional reference-board setting imports a private cold image:

  nand-image j "/absolute/path/to/device.bfnand"

Use j or p to select the explicit read-continuation contract. Paths follow the
process working directory; quoted paths may contain spaces. The Board connects
the same causal NAND peer to its MCU/DSP scheduler, with logical GPIO/writable
storage and selected-quiescent SHI reset. Secondary ESAI setup uses the
cold-before-bit-clock contract when a declared audio source routes HCKT_1;
otherwise it retains the cold-unclocked contract. These interpretations supply
neither an SS edge nor an implicit audio clock.
Timer1 Ready belongs exclusively to NAND; conflicting pinned TIO1 inputs fail.
Inherited inputs, NAND events and DSP periods use the supported combined order.
The default shared event budget is eight when NAND is attached; an explicitly
configured input budget is retained. Other input orders remain subject to the
runtime's visible combined-source guard.

Board checkpoints retain NAND protocol, cells and pending deadlines with both
native owners. Restoration creates a fresh NAND binding before execution resumes.
Board::nand_image returns an explicit cold power-loss projection of a copy;
exporting it preserves the live device, including Ready and pending work.
This connection imports RAM state. Durable NAND publication through the live
VirtualDeviceState store is still pending; that combination explicitly fails.

  cmake --build --preset strict --target blofeld-reference-nand-test \
    blofeld-reference-pipeline-test blofeld-reference-checkpoint-test blofeld-headless
  ctest --preset strict -j1 --output-on-failure \
    -R '^(reference_nand|reference_pipeline|reference_checkpoint)$'

reference_nand uses authored MCU/DSP instructions and sparse cells at both
540/1080MHz timebases. It checks independent 100us Ready deadlines, quoted-image
imports, source collisions, joint restoration before/after power, actual native
callbacks after restoration and nonmutating cold export. This is Board connection
evidence, not a completed original-instrument boot or durable-update proof.

The three Board groups pass under ASan/UBSan and separate TSan. The rebuilt
headless executable and these tests link only the independent native DSP core.
Full original instrument operation and durable NAND publication remain open.

reference_nand_audio_clock connects the causal NAND peer and explicit shared
HCKT/ACI source in the regular Board. Authored native MOVEP instructions select
ESAI pads before clock/format programming. Both initial MCU schedules produce
independently expected signed stereo PCM and exact bit periods while NAND power
completes. Four joint cuts reproduce native, source, NAND and PCM state and full
suffix traces with fresh owners. This group and existing audio runtime/restore/
guards, reference_nand and reference_pipeline pass under ASan/UBSan and separate
TSan. See reference-audio-clock.txt; this is integration evidence from authored
programs, not original instrument audio.

Functional shared-bus transactions

The regular Board selects NandBusContract::functional_transactions. Both-low
RE/WE encodes a neutral shared-bus phase, interpreted as inactive strobes by
the NAND transaction model. Raw GPIO values remain unchanged. Entry requires
both strobes inactive, or the initial complete observation; exit requires
both inactive again. Interrupted active pulses and unknown controls still fail.
CLE/ALE and data retain their values. Neutral creates no read, write latch,
reset, Ready response or cell change. Single-strobe transfers use the existing
real command/address/data protocol, cells, Busy deadlines and timing checks.
The ordered_pins contract remains the default for direct peer fixtures.
This is a functional board abstraction, not a claim about CE wiring or physical
edge ordering. It leaves unsupported commands and unknown cells explicit.

nand_bus_decode checks 512 directed transitions, real FF-reset Busy, cell/pointer
preservation, a fresh owner restored during neutral, and the ordered-contract
refusal. nand_write_medium runs native program/erase, computed status, GPIO
readback and pending-job restores in both contracts. Its functional sequence
actually executes neutral, FF reset and main-area selection before program.
Fourteen affected groups are qualified with the d03de44 SDK under ASan/UBSan
and separate TSan; the corrected write fixture alone was rerun after its
missing post-reset area-selection command was fixed. The other test binaries
retain their hashes. No fuzzing or physical traffic is part of these checks.

A separately frozen 94d4a30 original-firmware run preserves the complete cold
load and repeats its actual connected suffix twice: real FF reset completes,
642 audio-DMA words and 159 silent stereo PCM frames reach the next native RAM
instruction-admission limit. See own-dsp-nand-reference.json. This does not
qualify original startup on the newer SDK or a complete sounding instrument.
The live durable NAND store, complete original boot, MIDI/audio operation and
update/recovery acceptance remain outstanding.
