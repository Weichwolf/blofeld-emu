This supporting fixture checks one declared NAND page, independently extracted
from the hash-pinned original1.25 update. nand-first-records-reference.json pins
its size, hash, source offset and original record expectations. Original bytes
and detailed traces stay local; this is not a recovered factory NAND image.

The native caller supplies explicit BIU/GPIO/clock conditions and one ready page.
The original packing loop reads528 bytes and performs131 checked stores across
P/X/Y, including15 original MOVEM template patches. Independent expected words,
banks, addresses and untouched guards detect stale cached code after X-to-Y
transitions. A trusted joint checkpoint after the first Y-template patch must
reproduce code, memory, NAND, timing and native state with fresh owners.

This fixture deliberately ends at the next refill's unsupported write-enable
with address/PC/OMR/page/column context. The pending partial record is not supplied
or completed by the host. That boundary is a fixture limit, not the current
connected runtime frontier: the regular Board executes native reset, SPI/NAND
loading and bounded MIDI-driven DSP audio (nand-board.txt, coverage.txt).
Timing assumptions are in nand-read-timing.txt. Complete startup, both profiles,
all storage contents and update/recovery remain separate acceptance work.
