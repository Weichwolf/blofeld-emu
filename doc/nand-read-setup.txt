NandReadSetup supplies the separate 3.3V K9F1208U0C Rev.1.1 array-read setup
contract. Printed page 13 and the diagrams on pages 20/22/25 require ALE-low
to RE-low >=10 ns, CLE-low to RE-low >=10 ns, WE-high to RE-low >=60 ns and
observed Ready-high to RE-low >=20 ns. The source PDF identity/URL is pinned
in hardware/sources.json. Monotonic ordered control/Ready observations retain
their stable intervals; an unknown Ready does not inherit older high knowledge.
Whole-tick minima round upwards. Elapsed-time checks avoid future-deadline
overflow. A selected falling RE is admitted only after all requirements pass;
rejected observations retain previous value state. No data, Ready transition,
protocol mode, chip selection or output drive is generated by this component.
Status reads during busy need a separate contract.

The own deterministic test uses independent fixed conversion vectors at 1 GHz,
1.08 GHz and 216 MHz: one tick before and exactly at all four minima. Directed
unknown/mode/selection/order tests, restored value copies, withdrawn Ready
knowledge, backwards time and the final representable reference tick are covered.

The optional original-firmware gate validates the official 1.25 ZIP and loads
its unchanged 94-word stage. An own native caller supplies BCR/GPIO/OMR/cursor
preconditions and calls original P:9c. Four rows (0, ff, 100, 7ff) run the actual
command and four address writes through NandWriteTiming. The native TIO poll
really remains busy for eight calls. The test then explicitly supplies a lab
read-completion observation at that boundary; this is not an automatic device
completion rule or a measured tR/Ready/clock relationship. NandReadSetup admits
the later original RE edge before NandReadTiming consumes the first own reference
byte and exposes the bounded unknown output window.

This joins actual native code and the three timing components. It does not
qualify the earlier reset/clear or installed NAND contents. CE is explicitly
held selected; F8/F9 are separate low lab inputs and F10 is not inferred to be CE.
The declared reference uses 12 MHz EXTAL, an unmodified reset PLL setting and
1.08 GHz ticks; instruction-completion edge observations do not calibrate BIU
pad timing or the actual original stage's programmed PLL/pad sequence.

All four paths stop on the original reserved Port F function write at P:94,
Y:fffff7, OMR600389. Independent FM13-135/Table12-13 opcode fields identify an
immediate MOVEP with its extension: the fault context is P:94, while the native
decoder has fetched through P:95 and stands at P:96. The rejected register value
is not committed. CPU/clock remain faulted, and another step requires recovery
without advancing state/time. Real call/loop frames retain SP4 and LC176.

One protocol byte is consumed, but no CPU GPIO-data read or payload RAM store
has happened; the destination word remains unknown. DSP data drivers remain
enabled at the first RE edge, and NAND output drive is still uncertain. This
is not a successful turnaround or evidence that the physical bus tolerates it.
Every case remains explicitly unqualified as a board. No pin winner, immediate
Hi-Z, reserved-mode behavior, data default, skipped instruction or fake ACK is
supplied. The component detects read setup; it does not resolve that pad conflict.

A joint native-machine/clock/NAND/three-timing checkpoint at the supplied Ready
transition is restored into fresh owners. The complete 296-byte native state/time
suffix, first-byte consumption, untouched destination, fault and final debug
state match in all four cases. These trusted in-process checkpoints do not
qualify portable state files. Stock mask ROM, reserved writes/modes, NAND variant,
physical timing, complete refill/boot, original MIDI/audio, updates/recovery and
both-profile hardware comparison remain open in coverage.txt.

The same gate retains those four lab-release traces and adds four clocked rows
plus a missing-byte control. NandOperationClock owns the actual protocol and
requires reference_maximum explicitly. Real WE latches admit command/address;
the last address starts the timer. Neither the host nor the poll counter supplies
completion. A saved first-busy-poll boundary is restored into fresh native/device/
pin-timing owners; its complete event/read/fault suffix and debug endpoint match.
A one-tick skewed clock rejects before pin drive. After a missing-byte fault the
coupled owner refuses further steps before its still-healthy CPU can advance.
