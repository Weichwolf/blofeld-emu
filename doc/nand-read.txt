Small-page NAND read reference and native GPIO experiment

The explicit K9F1208U0C candidate profile uses Samsung's Rev.1.1 June 2007
datasheet, pinned in hardware/sources.json (manufacturer PDF on distributor host):
  https://www1.futureelectronics.com/doc/SAMSUNG/K9F1208U0C-PIB0000.pdf
Pages 8/9 define 512 main plus 16 spare bytes, 131072 rows and four read-address
cycles. Pages 26/34 define Read1/Read2, completion and reset. The read checks cover
00/01/50 page reads and FF reset; program/erase/status extensions are described in
nand-write.txt. Readiness requires explicit power/completion observations. Reset
preserves cells when no write is active; interrupted writes remain unknown.
Read-ID uses separate immutable observations (nand-identification.txt); no
identity, ECC or successful write outcome is inferred. Unobserved cells stay
unknown, including spare and bad-block markers. A missing byte fails with row/column/command context and
does not advance. Post-page sequential-row behavior remains unqualified; readiness
becomes unknown. Nonzero upper spare-column bits fail conservatively because the
address table and read prose describe them differently. This profile is not
automatically attached to either Blofeld board.
Surplus addresses are ignored only while the current transfer is pending.
After completion, address-only restart semantics remain unqualified and fail;
supported subsequent reads require a new explicit read command. A regression
distinguishes rejection from silently treating those inputs as harmless extras.

Checks
  cmake --build --preset strict --target blofeld-nand-read-test blofeld-nand-gpio-test
  ctest --test-dir build/strict -R '^(nand_read|nand_gpio|original_nand_address)$' --output-on-failure

nand_read checks 42 row/area vectors, main/spare boundaries, upper row bits,
explicit busy/completion, address-only power-on Read1, repeated/aborting reset,
retained cells, unknown-byte retry and rejected ranges/commands/phases.
nand_gpio uses native own DSP instructions, without firmware assets: command and
address output, actual TIO1 ready polling, input/output turnaround, all 528 bytes
and native X-memory stores. Two synthetic pages and a withdrawn byte check the
candidate link. No host writes operand RAM or computes instruction results.
Unknown/deselected chip-select observations and unordered simultaneous RE/WE
transitions fail before any NAND operation, retaining CPU/device context.

The harness bounds eight-byte action records and observed page fragments. It also
exercises program/erase, masked status, WP/block observations and power loss.
Its 1024-action limit admits full 528-byte program sequences plus setup, status
and interruption events. A 61-second smoke campaign with own structured seeds
completed 7706 sequences without sanitizer findings. It is not native instruction
fuzzing, physical power-loss validation or a sustained complete-board campaign.

original_nand_address separately calls an unchanged original first-stage routine
from a native own caller with explicit register/GPIO preconditions. It checks the
actual command, all four address bytes, row increment and ready-poll behavior
for a low row, then requires a visible first-data-turnaround failure. A higher
row independently requires the earlier reserved upper Port F write to fail;
neither silently masks those bits nor extrapolates a complete high-row transfer.
The experiment neither executes nor claims to complete the original preceding
clear/init sequence. The routine
asserts RE while data outputs are still enabled; accepting that transition would
require measured pad timing/drive behavior. Its later Port F mode transition
also requires qualification. Neither failure is ignored or patched around.

A separate original_nand_read_timing regression calls the original byte helper
from explicitly released data-pin/ready-page conditions. It reads all 528 bytes
through the candidate output timing model and native JSR/RTS; missing contents
and an own premature sampler fail. This does not execute the earlier refill
turnaround. See nand-read-timing.txt for reference timing contracts and limits.

Candidate test-only routing: C8 RE, C9 WE, C10 CLE, C11 ALE, F0..7 data and
TIO1 ready. Chip-select is an explicit held-active laboratory observation, not an
inferred GPIO route. In particular, F10 is not assumed to be CE; its role remains
unqualified. Non-NAND F8/F9 low levels are separate controlled inputs.
Completion after three executed polls is an explicit untimed laboratory event,
not a measured NAND delay or DSP clock ratio. The tests do not establish board
wiring, polarity, CE timing, setup/hold or real-device equivalence.

Full original boot still stops on reserved Y:002000 before reaching NAND GPIO.
Input-side timing now has a separate component/reference gate: actual original
commands and addresses pass bounded setup/hold/pulse/cycle checks, pending-WE
restoration matches, and busy stays asserted through eight original ready polls.
No data read or array completion is fabricated. See nand-write-timing.txt;
this does not qualify the full refill or its Port F turnaround.
The joined original transition in nand-read-setup.txt supplies an explicit lab
Ready edge and checks read admission before the first protocol byte. It still
fails at the actual reserved Port F function write, without a CPU data sample
or payload RAM store. Unknown NAND drive while DSP outputs remain active is
retained; all board cases stay unqualified.

The 131072-store clear is unchanged. Actual NAND/ROM/wavetable/sample mappings and
contents, original data reads, full scheduled boot/MIDI/audio/update/recovery,
full original NAND updates and stock Desktop/Keyboard comparisons remain pending.
A static candidate reconstruction from the updater's source ranges also leaves
264 trailing page bytes outside the supplied update object. It is not an
installed NAND dump; those bytes are not assumed erased or zero. Detailed source
analysis and candidate extracts stay private and do not initialize a board model.

Clocked operation reference
NandOperationClock owns the protocol and requires an explicit reference_maximum
contract. Samsung p.13 supplies tR=15us maximum and tRST=5/10/500us maximum for
read/ready, program and erase interruption. Durations round up to whole reference
ticks. Busy recognition is explicitly zero tWB (the table permits up to 100ns);
R/B pull-up delay, exact silicon timing and board attachment remain unqualified.
Only the final address starts a read timer. Status polls and ignored surplus
addresses cannot advance or restart it. advance() reports the exact event tick;
the board must interleave peers using next_event(), processing events before
same-tick inputs. Reset replaces the read event; power loss cancels all events.
Unknown-power and repeated-reset timing reject. Program/erase completion still
requires an observed outcome. No timer creates known data or successful writes.
Failed operations poison the owner; trusted value copies restore cells, protocol,
time and event together. Counter exhaustion fails instead of wrapping.

  cmake --build --preset strict --target blofeld-nand-operation-clock-test
  ctest --test-dir build/strict -R '^nand_operation_clock$' --output-on-failure
Four independent timebase vectors check read and all reset deadlines, fine/coarse
advance, polling invariance, cancellation, unknown data and complete owner copies.
The same scoped gate passes separately under ASan/UBSan and TSan.
original_nand_read_setup additionally couples this owner to four unchanged
original read-address paths and a missing-byte control, with saved-busy replay
and visible rejection of skewed clocks or further steps after a device fault.
Its event/publication distinction and remaining board limits are in
nand-read-setup.txt.

An ignored full-first-stage experiment retains the explicit memory/PRRC/BCR
counterfactuals from dsp-core.txt. Five original GPIO latches schedule the read;
the 540MHz reference event occurs 8100 ticks after the final address. Instruction-
boundary publication is 30 ticks later, explicitly separate from the event time.
After 160 original polls, read setup admits the first RE edge. Unknown contents
fail before consuming the byte. A separate synthetic-byte control reaches the
unchanged reserved Port F write; no CPU payload sample occurs. Both sanitizer
modes retain byte-identical traces. This does not qualify actual flash contents,
physical pin timing, ROM/reserved-write behavior or the default board's boot.
