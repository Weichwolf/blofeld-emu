Timed NAND file ownership

NandWriteStore owns the existing NandWriteMedium controller and cell model.
The part/read-continuation, device timebase and cell profile stay explicit.
It never supplies an external pass/fail completion or infers WP, block validity
or manufacturing contents. Unqualified programming remains a visible error.

A private .bfnand file and an exclusive writer lease belong to one owner.
Existing state is decoded exactly; a supplied seed is used only for a missing
file. Corrupt state is not repaired. Host publication writes and synchronizes
an atomic replacement before a persistent device transition becomes visible:
confirmation publishes the interrupted-operation projection, and autonomous
completion publishes the computed cell/history result before Ready/status.
Reset and simulated power loss retain interrupted physical uncertainty.
Ordinary reads and elapsed read/idle periods do not write the host file.
A publication failure quarantines the owner until cold reload, including when
the replacement already became visible to the host.

NandPeer accepts exclusive ownership of this timed backend. Its existing GPIO,
Ready, output timing and independent event calendar use that same controller;
there is no second protocol or untimed completion path. A live backend rejects
RAM-only snapshots/restores. The existing value backend retains full pending
work and fresh-owner checkpoint support. File failures retain DSP address/PC
context and stop the peer before a fabricated successful Ready observation.

Directed controls (ASan/UBSan and separate TSan):
- read neutrality, exclusive lease, seed/create/reopen and partial-program history;
- actual 500-us program, 3-ms erase, reset cancellation and physical inhibit failure;
- five host publication failure phases for both confirmation and completion;
- ten independent-core GPIO program/erase/status/readback endpoints across the
  ordered-pin and functional-transaction contracts, including inhibited cells;
- two native publication-failure/quarantine paths and fresh clock/power admission;
- existing native NAND cell, Ready, output, calendar and checkpoint regressions.

Build/run only this affected component scope, for either sanitizer build:
  cmake --build build/strict --target blofeld-nand-write-store-test blofeld-nand-durable-peer-test
  ctest --test-dir build/strict --output-on-failure -R '^(nand_write_store|nand_durable_peer|nand_write_medium|nand_peer_timebase|nand_native_runtime|nand_capture)$'

These tests use authored programs and cell fixtures, not manufacturer program
bytes. They establish timed storage/pin integration, not original-firmware
preset saving, a complete dual-store boot, updates/recovery or brick safety.
Regular Board/CLI mounting and original 1.25 live-store execution are separate
integration requirements. Evidence pins are in nand-write-store-reference.json.
