Independent DSP integration (transitional)

The pinned independent DSP source is built as a separate CMake subproject.
Set BLOFELD_OWN_DSP_ROOT to its clean pinned checkout when it is not located
at ~/Git/dsp56300. DSP56300_SANITIZER must match BLOFELD_SANITIZER. The source
and license are recorded in dependencies.json; reference firmware remains local.
The adapter target links only the own core and board peripheral libraries.
During migration, configuration still also requires DSP56300_ROOT to point to
the separate legacy checkout pinned in dependencies.json for the old runtime.

OwnDspIo forwards genuine DSP reads, writes, bit tests and peripheral reset to
the strict DspBus. Unsupported atomic read/modify/write operations are refused.
The first refusal is latched with operation, space, address, PC, value/action and
any underlying exception; the caller must explicitly clear it before reuse.
It does not schedule the processor, DMA, interrupts, cache ownership or clocks.

The synthetic test covers known RAM, rejected and latched accesses with retained
context, actual GPIO bit updates, invalid bit indices, peripheral reset and
a user-authored NOP executed through the real bus. It contains no firmware bytes.

OwnDspInterrupts selects requests through the board's interrupt controller and
admits them to the paired own core. Its advance method executes the genuine
native ticket before updating the state of vector fetches. A stale ticket or refused
read cannot acknowledge a source. After the second accepted vector read, only
the admitted source is acknowledged. Core and board must share the same I/O bus;
the caller must route every staged advance through this owner during entry.
This supplies functional ownership, not clock timing or reset.
The synthetic IRQ test covers SR masking, two vector bases, stale tickets,
fast-vector return and refusal of an unknown second vector word.

OwnDspMachine pairs the bus, adapter, own core and interrupt owner. It requires
explicit mode5/PINIT-low observations and at least two supplied recovery periods.
The existing DspRunClock holds execution closed through assertion and recovery;
partial reference periods and the exact recovery endpoint are retained. Inputs
are a caller-supplied stable reset contract, not recovered physical board wiring.
The owner initializes PC/SR/OMR/SP/SC/VBA and all M registers from documented
reset values. Other visible registers are retained, including uninitialized EP
and SZ (FM 4.3.2 and 5.4.3.3). RAM and installed ROM survive the board reset.
Only reset time advances: subsequent staged execution remains explicitly untimed.
Published OMR changes reach the real bus, whose switch delay still needs explicit
scheduler cycles. Assertion at a native effect boundary drops staged CPU work
and vector ownership without acknowledging an old source. Published unaffected
registers and accepted memory writes retain their reset semantics; speculative
register values do not survive. This does not model subcycle assertion latency.
The synthetic reset test covers fractional assertion/recovery, early release,
execution gates, memory retention, independent reset values, own MOVEC EP/SZ
instructions, warm register retention and old-ticket refusal across reset.
It also covers cuts before/after EP publication and the first vector fetch,
fresh real IRQ admission afterward and both actual vector reads. FM 2.3.2.7/8
keeps the foreground PC unchanged during those fast-vector fetches.

OwnDspMachine also captures immutable trusted in-process chip checkpoints:
native architectural/hidden state and staged publications, all bus RAM/ROM and
knowledge bits, memory-map transitions, peripheral state, vector ownership,
reset clock fractions and the first I/O refusal. Restore prepares allocations
before committing state and requires identical clock inputs. It supports the
same owner or a fresh owner; old effect tickets cannot be reused. GPIO readers
are detached and must be explicitly reconnected before consuming pad inputs.
External board devices, shared event queues and persistent files are excluded.
Capture/restore allocate and are not real-time callback operations.
The synthetic checkpoint test passes under ASan/UBSan and resumes all 32 native
effect cuts of an own immediate/CLR/REP/ADD/store program against literal final
register/RAM expectations. It
also checks knowledge rollback, ROM rollback, reset fractions/gates, empty and
incompatible handles, both cuts around the first vector read, explicit pad
reconnection, retained failure context, healthy recovery and rejection of
capture/restore reentry from a genuine native pad read.
No original-ROM boot, MCU wiring, calibrated pipeline, DMA timing, joint board
checkpoint or real-time instrument behavior is established by these fixtures.

Connected original-firmware evidence (local only):
The strict diagnostic receives all 94 original first-stage words through 7,275
MCU SPI writes and refuses the reserved Y:002000 clear at DSP PC 000072. Its
explicit link inputs omit foreign DSP libraries; no dsp56k symbols occur.
The owner handles actual MCU interrupt entries and WAI boundaries. It uses
scripted reset/input observations, candidate peer routing, a document-derived
partial boot ROM and one DSP instruction per MCU boundary. Estimated peripheral
cycles and instruction-boundary GPIO observation are uncalibrated; neither
physical wiring nor reset-to-instrument operation follows from these runs.

Conditional board contracts, each separately controlled and recorded:
- A no-selected-cell hypothesis admits only reserved/ROM writes in the low
  128K X/Y window. It creates no cells/read values; real RAM and peripherals
  remain strict. Twenty controls pass, including unchanged ROM and default
  refusal. The original clear produces exactly 184,320 distinct logged writes.
- A Port-C lane hypothesis projects direction/control writes onto twelve pins.
  Forty-eight pin/function cases and scope controls pass. The original 00FF00
  write selects 000F00; its outside-lane silicon response remains unqualified.
- A functional Port-F contract retains reset BCR=1FFFFF rather than writing a
  fitted 01FFFF. Real word/bit accesses and unknown-input controls pass; BBS
  after access still refuses. This supplies no BIU wait-state timing law.
- The NAND contract composes the existing protocol, write/setup/output timing
  and operation clock with actual GPIO and Timer1 DI. It declares reference
  power readiness and 15us reads, explicit P/J contracts, fixed-selected CE and
  floating auxiliary inputs. Initial pad history and physical nets stay open.
  Tests cover two synthetic cells, access-time uncertainty, busy/ready deadlines,
  unknown cells and PF10 independence. Simple direct/inverted PF10 CE candidates
  conflict with reconstructed programming constraints under the NAND contract.
- A register-retention hypothesis permits the transient reserved Port-F mode
  while retaining unknown pin functions. It invents no high-Z input or data:
  CPU data reads during that mode refuse with context. Controls verify default
  refusal, retained PCR/DDR values, unknown pads and valid input-mode recovery.
  Each conditional write is logged with operation, address, PC and value.
- The board-owned Port-F resolver combines GPIO, unknown functions and NAND
  drivers without choosing a winner for contention. CPU sampling still refuses
  unknown/conflicting pins. Sanitized controls cover both conflict polarities,
  all-lane disagreement, agreeing drivers, original-order direction changes,
  access-time uncertainty and explicit ownership. They establish logical pad
  behavior, not electrical current, damage or calibrated transition timing.
  The latest controller also samples resolved NAND inputs and interleaves
  output-valid/release deadlines; same-tick feedback creates no extra pin edge.
  Independent 17/33-tick hold/release cases pass at the 1.08GHz reference.
- A local extension joins the same resolved GPIO link to NandWriteMedium under
  an explicit reference cell profile. With a known writable block and WP high,
  synthetic GPIO strobes erase the block and program one byte. Busy stays low
  until 3,240,000/540,000 reference ticks respectively; actual cell contents
  match independent erased/programmed expectations. Prior read/conflict
  controls also pass under ASan/UBSan. This is not original updater execution,
  physical timing qualification or evidence of installed NAND contents.
- A separate isolated original program-helper run uses the own DSP core and
  that write link. Host-supplied registers, original update payload and an
  explicitly erased writable target are fixture preconditions. Under a declared
  1,000-tick instruction spacing, the native helper sends the program setup,
  four address bytes and eleven data bytes matching an independent source
  extraction. At DSP PC 002ed9 the next Port-F word write is refused because
  it sets reserved data-register bits. No program-confirm command is observed.
  Reserved-bit silicon behavior, physical wiring and timing remain unqualified;
  this component run is not an uninterrupted update or a NAND image.
- With a separate local hypothesis that PDRF upper data bits have no pin or
  hidden-storage effect, the same helper emits all 528 data bytes; every byte
  matches the independently extracted first source page. The reference cell
  controller accepts the program command and reaches its modeled completion.
  The next original status-read instruction simultaneously changes CLE and RE;
  the declared direct-net/timing model refuses the tCLR setup requirement at
  PC 002ecb. Thirteen single-upper-bit scope controls pass; 67 full firmware
  writes with upper bits were logged. Physical pin skew, routing and reserved
  write behavior remain unqualified. No firmware instruction is patched or
  skipped, and this is still an isolated helper with synthetic timing.
  A separate Z3 bound assumes CLE follows the candidate GPIO immediately, the
  next three 1,000-tick instruction boundaries publish PCRF, PRRF and the CPU
  read, and NAND RE falling is independently delayed. Requiring PRRF's input
  publication strictly before RE, plus reference tCLR=11 and tREA=33 ticks,
  gives a feasible delay of 2,001..2,967 ticks at 1.08GHz. The two adjacent
  outside bounds are unsatisfiable; both endpoints are feasible. The calculation
  covers only these constraints; it does not establish a physical delay circuit,
  signal routing, calibrated instruction time or other NAND timing requirements.
  A local ngspice counterexample uses an ideal 3.3V source, 27k/100pF and an
  assumed 50% threshold. With the conditional helper trace's shortest observed
  5,000-tick low and 4,000-tick high intervals, the first falling edge crosses
  after about 2,021 ticks, but the seventh crosses after about 1,304 ticks.
  This simple RC candidate therefore does not maintain the conservative
  DDR-before-RE bound through repeated reads. Component values, loading and
  thresholds are experiment inputs; no actual board circuit is established.
  A further local candidate delays falling RE by 2,100 ticks and preserves
  partially known NAND status bits through the resolved GPIO pads. An own JSR
  caller executes the original helper, which programs a known-erased target;
  all 528 resulting cells are known and match the original source page. After
  program completion, the NAND status has known mask C1 and value C0. At
  PC 002ed1 the actual full-word GPIO read refuses unknown status bits 3E;
  no status values are invented and the helper does not return. The delay,
  direct nets, cell profile, host setup and instruction spacing remain explicit
  experiment inputs, not demonstrated physical hardware or a full update.
  The candidate NAND's 70h status table marks bits 1..5 as don't-care. In 32
  separate runs, each possible value was supplied as an explicit hypothesis
  after the modeled successful program, retaining real known bits C1. Every
  run programs the same 528 source bytes and returns through the native JSR
  frame after 9,428 instructions. The returned A1 status varies from C0 to FE
  in steps of two; checked SR, R0, R1, SP and remaining A bits stay equal.
  These are distinct conditional paths, not an observed device status, a full
  CPU-state equivalence proof or a substitute for the full updater caller.
  A subsequent isolated run calls the secondary helper's original combined
  program-and-compare entry for row 37. The two extremes of the five unused
  status bits both produce the original 528-byte write and 528-byte read;
  independently extracted bytes, all resulting cells and 176 captured words
  match. The original mismatch register is zero and the helper returns after
  14,974 instructions. Source RAM, erased writable target, upper-bit policy,
  status hypotheses and RE delay remain explicit fixture assumptions. This
  component result does not establish full firmware update or hardware timing.
  At the first page of a known writable block, the same original entry also
  performs the actual block erase before program and compare. In both extreme
  unused-status cases, the other 31 pages become erased, a checked neighboring
  block cell remains unchanged, and all 528 programmed/read bytes match the
  source. Reference erase/program durations are independently checked.
  A separate single-cell program-inhibit case reaches real NAND failure status
  and changes exactly one readback bit. The original compare returns a raw
  mismatch count of 010000 while its Z flag is set by the final matching word.
  These are isolated own-core component runs with explicit initial cell state,
  pulse model, GPIO/timing and unused-status hypotheses, not a complete update
  or evidence of physical flash safety.
  A larger isolated own-core run starts the original main updater with its
  host-loaded complete transfer, actual transport padding and the 86 words
  captured in a separate startup run. It executes the marker/checksum path and
  reaches the original NAND configuration without a NAND command latch. The
  strict run stops on the Port-C upper direction bits; with the previously
  scoped Port-C projection enabled, the fixed 2,100-tick RE delay asserts RE
  during an active WE pulse at PC 002e91. The 86-word capture predates a full
  boot and this input setup is not an uninterrupted MIDI update.
  Under the same direct-net, fixed-delay and 1,000-tick-per-instruction model,
  this observed initialization keeps WE low for at least 3,000 ticks after raw
  RE falls. The separate status-read fixture requires RE delay <=2,967 ticks
  for timely sampling. Z3 rejects their joint constraints. This refutes that
  combination of fixture assumptions, not every physical circuit or timing.
  Three further runs explore explicit digital gating candidates. Suppressing RE
  while raw WE is low avoids the first overlapping pulse but reaches a read of
  the unknown PE7 output latch. Initializing that latch low is a separate
  fixture hypothesis motivated by a conditional startup path; it is not an
  observed complete boot. With CE tied selected, initialization then violates
  the reference NAND tCLS constraint. A second candidate gates CE using PE7,
  raw control signals and PF10. It reaches the actual ID command and address,
  then detects active contention on data bits ec before the firmware switches
  Port F to input. In this path the caller lowers raw RE before calling the
  byte-read routine, so the previous 2,100-tick propagation model publishes
  NAND data too early. The candidate is disproved for these fixture conditions;
  neither its gates nor the NAND part and clock are established board facts.
  The local run's inherited banner incorrectly also says CE is tied low; the
  candidate implementation and its CE-gate field describe the tested wiring.
  With the same candidate and a 4,100-tick delay, the first ID byte becomes
  available after Port F becomes input. This exposed and fixed the model's
  incorrect rejection of RE release during ID output. A subsequent run with
  pull-downs on floating Port F pins reached later operations, but those pulls
  were fixture assumptions: the output log is not proof of the DSP's sampled
  bytes. Without any pull-down the first read refuses unknown PF8/PF9. With
  pull-downs assumed only for those two auxiliary pins, the second ID read
  refuses all eight NAND data bits before the delayed output becomes available.
  Thus neither the later operations of the all-pulled-down run nor that gate
  and delay combination establish a valid firmware ID exchange.
  A further candidate inhibits RE for 5,100 ticks following WE rising and
  otherwise delays RE by 2,100 ticks. With floating data bits left unknown and
  auxiliary PF8/PF9 pull-downs assumed, all four ID bytes become driven before
  their firmware reads. The original code then performs block erase and status
  polling, begins programming and presents 528 data bytes before the model
  rejects a CE transition. That boundary exposed two model defects: ID must
  preserve a known area selection, and the reference part permits CE pauses
  during program data loading. Both now have independent component tests.
  These results do not qualify the timing gate, clock, fixture, NAND part or
  complete update; the full page has not yet been confirmed and compared in
  that run. A subsequent running fixture includes both model fixes. An
  immutable log snapshot independently compares ten completed page cycles:
  each contains 528 programmed and NAND-output bytes equal to the corresponding
  host-loaded fixture bytes. A separate audit also checks both four-byte row
  addresses and the program/read completion events for those transitions;
  altered-address and missing-completion controls are rejected. That confirms
  only the logged prefix, not final firmware completion, the remaining pages
  or a real board. One earlier run
  pinned a mutable build archive which was later rebuilt; later runs retain
  frozen library inputs.
  A separate snapshot compares the NAND output event sequence with actual
  DSP Port-F read values: 9,336 values match, including status bits under the
  declared unused-bit hypothesis. Eight later NAND output events have no
  corresponding CPU trace in that snapshot and are not included. A modified
  CPU value is rejected by the audit. This is still the isolated candidate
  setup, not a complete update or a hardware timing measurement.

pages and 270 bytes of the last page. Every raw CPU PDRF value matches the
original-derived source. All 107 address requests have their own reference read

independent ordered-record expectation finds 18,276 distinct resident P/X/Y

The regular device and reference scheduler still use the legacy core. Migrating
that scheduler, full clock/pipeline/DMA ownership and joint board checkpoints,
removing the legacy dependency and all reset-to-instrument requirements remain
open. The independent adapter and local hypotheses do not establish full boot,
real timing, MIDI/audio or hardware equivalence.
