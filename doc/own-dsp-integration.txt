Independent DSP integration (transitional)

The pinned independent DSP source is built as a separate CMake subproject.
Set BLOFELD_OWN_DSP_ROOT to its clean pinned checkout when it is not located
at ~/Git/dsp56300. DSP56300_SANITIZER must match BLOFELD_SANITIZER. The source
and license are recorded in dependencies.json; reference firmware remains local.
The adapter target links only the own core and board peripheral libraries.
During migration, configuration still also requires DSP56300_ROOT to point to
the separate legacy checkout pinned in dependencies.json for the old runtime.

OwnDspIo forwards genuine DSP reads, writes, bit tests and peripheral reset to
the strict DspBus. Unsupported atomic read/modify/write operations are refused.
The first refusal is latched with operation, space, address, PC, value/action and
any underlying exception; the caller must explicitly clear it before reuse.
It does not schedule the processor, DMA, interrupts, cache ownership or clocks.

The synthetic test covers known RAM, rejected and latched accesses with retained
context, actual GPIO bit updates, invalid bit indices, peripheral reset and
a user-authored NOP executed through the real bus. It contains no firmware bytes.

OwnDspInterrupts selects requests through the board's interrupt controller and
admits them to the paired own core. Its advance method executes the genuine
native ticket before updating the state of vector fetches. A stale ticket or refused
read cannot acknowledge a source. After the second accepted vector read, only
the admitted source is acknowledged. Core and board must share the same I/O bus;
the caller must route every staged advance through this owner during entry.
This supplies functional ownership, not clock timing, reset or checkpoints.
The synthetic IRQ test covers SR masking, two vector bases, stale tickets,
fast-vector return and refusal of an unknown second vector word.

OwnDspMachine pairs the bus, adapter, own core and interrupt owner. It requires
explicit mode5/PINIT-low observations and at least two supplied recovery periods.
The existing DspRunClock holds execution closed through assertion and recovery;
partial reference periods and the exact recovery endpoint are retained. Inputs
are a caller-supplied stable reset contract, not recovered physical board wiring.
The owner initializes PC/SR/OMR/SP/SC/VBA and all M registers from documented
reset values. Other visible registers are retained, including uninitialized EP
and SZ (FM 4.3.2 and 5.4.3.3). RAM and installed ROM survive the board reset.
Only reset time advances: subsequent staged execution remains explicitly untimed.
Published OMR changes reach the real bus, whose switch delay still needs explicit
scheduler cycles. In-flight assertion and reset during vector entry refuse.
The synthetic reset test covers fractional assertion/recovery, early release,
execution gates, memory retention, independent reset values, own MOVEC EP/SZ
instructions, warm register retention and old-ticket refusal across reset.
No original-ROM boot, MCU wiring, calibrated pipeline, DMA timing, full machine
checkpoint or real-time instrument behavior is established by these fixtures.

Original-firmware diagnostic evidence:
A local original MCU/own-core run through this owner received all 94 original
first-stage words over 7,275 MCU SPI writes. It stopped visibly at the known
reserved Y:002000 zero write, DSP PC 000072, after 191,073 retired DSP instructions.
The executable has no dsp56k namespace symbols; its explicit link inputs omit
the foreign DSP libraries. Pinned input files, program artifacts and copied
persistent device state were unchanged. Detailed commands, hashes and native results remain local in
  doc/local/own-core-live-reset/{inputs,build,validators,relink,runtime}.json
This is evidence for the connected software path up to that strict refusal.
It uses candidate peer routing, scripted reset/input observations, a documented
partial boot ROM and one DSP instruction per MCU instruction, with estimated
base cycles for peripheral advance. Those are uncalibrated hypotheses. The
reserved write's silicon response, physical reset/wiring, complete ROM and
reset-to-instrument operation remain unqualified. No refusal was bypassed.

Explicit local decoder hypothesis:
A separately declared no-selected-cell model admits writes to reserved/ROM
classes in the low 128K X/Y window. Reads, real RAM, other address ranges and
peripherals retain strict behavior; every hypothesis write records address,
operation, PC, value and decoder class. Twenty manual-boundary/control cases
pass under ASan/UBSan, including strict default refusal and unchanged ROM data.
With unchanged original firmware and decoder, the corrected diagnostic owner
handles six genuine MCU interrupt entries and completes the original long clear.
Its trace contains exactly the expected 184,320 distinct hypothesis writes;
R4 reaches 020000. The next refusal is the reserved-one GPIO direction write at
X:FFFFBE, value 00FF00, DSP PC 000073. No hardware response is established by
this conditional execution. The regular memory map remains strict and full
instrument operation remains open. Local evidence and hashes:
  doc/local/own-core-memory-decoder/irq-boundary/{runtime,audit}.json
Z3 also finds both direct and alternative bijective peer maps satisfying the
bounded software constraints. These constraints do not uniquely recover the
physical nets; the query and models remain in that directory as peer-ambiguity.*.

Port-C lane experiment (local only):
An additional declared hypothesis projects direction/control word writes onto
Port C's twelve documented lanes. Forty-eight pin/function truth-table cases
and strict scope controls pass under ASan/UBSan. In the original run, exactly
one write uses this rule: 00FF00 selects 000F00 and addresses 00F000 outside
the implemented lanes. The memory-write trace is byte-identical to the prior
audited clear; artifacts and copied persistent state are unchanged. Twelve more
DSP instructions retire before the first NAND routine refuses its Port-F PCRF
write at Y:FFFFF7, DSP PC 0000A3. The modeled family-reset BCR remains unchanged.
This neither proves reserved-bit masking on silicon nor resolves the documented
Port-F BIU wait-state prerequisite. No normal instrument operation is established.
Local code, control results, provenance, full traces and audit:
  doc/local/own-core-gpio-lanes/{build,runtime,audit}.json

Validation:
  cmake --build build/strict --target blofeld-own-dsp-io-test blofeld-own-dsp-interrupts-test blofeld-own-dsp-reset-test -j2
  ctest --test-dir build/strict -R '^own_dsp_(io|interrupts|reset)$' --output-on-failure

The regular device and reference scheduler still use the legacy core. The new
adapter and its synthetic test are not evidence of full boot, real timing, audio,
MIDI or hardware equivalence. Migrating the scheduler and removing that legacy
dependency remain required.
