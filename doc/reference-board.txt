Standalone board execution and explicit reference inputs

  blofeld-headless --firmware doc/Blofeld_Firmware_V1.25.zip \
    --reference-board scenario.bfboard --dsp-rom private-rom.bin \
    --instructions 2000000 --trace doc/local/reference.trace

The Board uses the independent dsp56300 core and McuDspRuntime, not the legacy
scheduler. Its supplied wiring/timing remains an experiment, not a verified
Desktop/Keyboard profile. The complete instrument objective is in objective.txt.
No firmware PC selects inputs, bypasses an instruction or supplies a result.
ROM inputs contain1..65536 big-endian24-bit words starting at P:ff0000. Missing
values remain unknown. Manufacturer firmware/ROM and generated extracts stay local.

Format2 uses ASCII tokens and decimal numbers except hexadecimal pin bytes:

blofeld-reference-board 2
clock 12000000 0 12000000 540000000 reference-boundaries
dsp-execution reference-effects
ordering dsp-before-mcu dsp-before-mcu 16
spi-b 02 04 10 clock-before-select
dsp-release 450 low
operations 23
initial drive B 16 02 00
initial drive E 03 03 00

All six settings are required exactly once:
- clock: MCU OSC Hz, initial MCU oscillator phase, DSP EXTAL Hz and common Hz,
  followed by reference-boundaries. Both owners use explicit cycle boundaries;
  the common timebase must be an exact positive MCU-timebase multiple.
- dsp-execution: reference-effects selects explicit DMA/F2/native-effect/F1 ordering,
  program-access priority and real native interrupt/vector effects, with one period
  per admitted effect. native-cycles groups CPU-only publications and waits for the
  real instruction's computed base budget. Both choices preserve actual bus/vector
  effects and visible unsupported accesses. Physical pipeline/interlock timing and
  complete instrument operation remain unqualified; see dsp-native-budget.txt and
  reference-native-cycle-cli-reference.json.
- ordering: DSP versus MCU shared-write order (dsp-before-mcu, mcu-before-dsp or
  reject), committed WAI order (dsp-before-mcu), positive DSP-cycle budget per MCU
  period. Reset periods also use the explicit DSP-before-MCU runtime contract.
- spi-b: distinct one-bit PORTB masks for active-low SS, SCK and MOSI, then
  clock-before-select, select-before-clock or reject for simultaneous pad edges.
  Only actual byte PORTB data writes qualify as shared transfers. A control
  register changing these pads without a qualified transfer fails visibly.
- dsp-release: requested common tick, or mcu-u0 for a release caused by the MCU,
  followed by observed PINIT level. The functional U0 source supplies a passive
  pull-up and preserves other U inputs. An actual known MCU low must precede
  its release to input or high output; an initial high does not release reset.
  Configuration/data writes use their actual MCU bus boundary. Conflicting
  sources and unknown levels fail explicitly. A later MCU low asserts hardware
  reset again; high releases it through the same hold/recovery path. Existing
  completed-native-boundary/alignment guards remain. Format2 declares mode5 and
  two reference recovery periods. The supported reset requires PINIT
  low; high is retained as an unsupported observation and fails. Release requires
  known SPI pads and deasserted SS. The DSP clock includes hold/recovery time;
  it is not rebased to an artificial instruction epoch at release.
- operations: positive budget including MCU instructions, IRQ entries, WAI periods
  and, when selected below, real reset edges. --instructions separately bounds
  retired MCU instructions. A reached budget does not establish instrument boot.

Format1 and dsp-interrupts/native-vector-estimates are rejected. They describe
obsolete planning controls; the new owner does not silently accept ignored options.
The C++ Config stores DspRunClockInputs and McuDspRuntimeInputs directly. It has no
DspRunContract, legacy scheduler input or alternative execution backend.

Actual MCU power-on

  mcu-power-on 3 high

This selects digital POR from tick0, with an explicitly supplied3..6 SYSCLK
synchronization delay and observed RESET pad (high, low or unknown). Real reset
edges and vector-fetch periods execute before guest MCU instructions; unknown
RESET fails when sampled. Power rails/oscillator quality are not inferred.
Without this setting, the nominal MCU reset/vector fetch has already completed
when the Board is constructed. That profile is an isolated reference convenience,
not evidence of full power-on. initial inputs apply at the chosen start boundary.
DSP clocks/input observations can progress while the MCU remains held in reset.

External MCU inputs and logical routes

  initial drive E fb 03 00
  at 10000 drive U 3f 01 00
  at 11000 phy-window 15
  at 12000 usb-decoder 08
  at 13000 timer-inputs 01
  loopback E 04 E 08
  shi-hreq U 01 inverted
  shi-miso P 01 direct

at inputs apply at the first completed owner operation at/after the requested
tick, preserving equal-tick file order. Due inputs precede a due DSP release.
They never backdate a native bus access. Trace rows retain requested/actual ticks.
- drive: port A/B/E/T/M/J/P/Q/R/S/U, driven mask, levels, floating mask. Unlisted
  bits stay unknown; masks may not overlap and levels must fit the driven mask.
- phy-window: observed PHY edges over three oscillator periods, not guessed LOCK.
- usb-decoder: post-decoder reset/suspended/enumerated/full-speed bits0..3. This
  does not add analog USB wire decoding or an automatic host enumeration.
- timer-inputs: MCU timer pad mask sampled by the native owner, including WAI.

Loopback forwards only its declared bit; an unknown source remains unknown.
SHI routes expose actual HREQ/MISO driven levels with direct/inverted polarity.
Disabled outputs are high impedance; driven unknowns are not receiver-pull values.
Unknown required reads and electrical contention fail with execution context.
Return routes cannot feed SPI input pins or overlap another external driver.
Physical nets, buffering, propagation delays and board pull resistors are not
established by these logical route declarations.

Functional MCU/DSP GPIO peer

  gpio-peer direct ff none

Optional declared Q[7:0]<->C[7:0], J0->IRQA and DSP PE9->MCU PE0/XIRQ nets.
Fields: hexadecimal idle data pull-down mask, notification pull none/up/down.
Only actual chip outputs/biases cross each net; no protocol replies are supplied.
Q, J0 and PE0 cannot share another input/return/loopback driver; other E/J pins
remain available. Byte writes to MEBI/J/Q synchronize with the selected common-clock
write order. DSP effects publish return levels at their completion boundary.
Unknown latches and conflicting drivers stay unknown. Native resets reconnect
replacement MCU owners; coordinated Board restores rebuild both pad bindings.
This functional topology/pull choice is a hypothesis, not measured wiring or
proof of original-firmware boot, MIDI, audio or complete instrument behavior.

Optional passive Port B network

  port-b-pulls 82 7d

Hexadecimal disjoint up/down masks declare weak bias for floating inputs. The
example deselects SPI and LCD: B1=/SS and B7=/CS1 high, other B pins low. This is
an explicit functional hypothesis, not measured wiring. Native outputs/internal
biases and external drivers resolve together; strong/unknown conflicts cannot
be hidden by pulls. SHI return or loopback destinations on B are rejected.
External B state and fresh-owner pad bindings survive Board restore.
Actual DDRB writes publish resolved SPI transitions in shared-write order,
without incrementing PORTB-write counts. A native word store declares exactly
one shared byte; only its actual write observation can consume that period.
Undeclared words and foreign observations remain errors.
Authored tests check literal reads, real 24-bit SHI reception through latch,
direction and aligned word writes,42 fresh-owner suffixes,14 native fault
suffixes and configuration guards. Shared-word tests cover both write orders
and either byte of aligned DDRA/DDRB words, eight fresh-owner suffixes and
five declaration/delivery guards. Odd register words remain unqualified in the
MCU reference timing profile and fail visibly; internal RAM has its separate
unaligned contract. Original connected startup remains separate.

Optional LCD candidate

  lcd-parallel st7565 reset-release 12000

Declared routing: A[7:0] data; B7=/CS1, B6=CS2, B5=R/W, B0=A0, E4=E.
The peripheral starts in explicit reset; release is sampled at the first native
pad boundary at/after the common-tick deadline, including with E already high.
This is a functional POR contract, not a recovered reset net or measured latency.
Every MEBI write observes actual pads. The LCD exclusively owns external A data;
unknown read bits remain active unknown drivers, so MCU pulls cannot invent FF.
Controller RAM/holder/overlap and reset history restore with both native owners.
Status.lcd_cycles counts commands, data writes and reads. display_image(panel)
is read-only; it supplies no bus cycle. Host publication is separate work.
Native tests cover 32 prefixes / 64 fresh-owner suffixes, nominal and actual POR,
literal pixels/dummy reads, reset release during a held read, unknown/status
faults and driver ownership, with strong or passive B inputs. Complete
original LCD boot and instrument reset remain unqualified.

Exact DSP inputs and shared-write ordering

  dsp-input-order input-before-dsp 4
  dsp-input-write-order input-before-mcu
  dsp-initial tio 0 high synchronized
  dsp-at 1200 tio 0 low synchronized

TIO indices are0/1; levels are high/low/unknown. raw changes the observed pad;
synchronized also supplies a qualified synchronized level and requires known
input. The last applied synchronized level remains observable across DSP
reset, independently of future timed edges. Raw/unknown inputs do not acquire
qualification. NAND Ready exclusively owns TIO1, including against MIDI routes.

dsp-at timestamps increase strictly and execute at exact common ticks, including
inside MCU periods. dsp-input-order selects input-before-dsp, dsp-before-input or
reject plus a positive event budget per MCU period. dsp-input-write-order selects
input-before-mcu, mcu-before-input or reject for a simultaneous actual shared MCU
write. Unqualified ties and cyclic three-way orders fail before consuming them.
All six acyclic orders execute the actual native effects. Exhausted sources remain
bound; snapshots retain their cursors. Independent sources at the same timestamp
form one input deadline: all apply on the selected side of the DSP cycle, without
executing native work between them. The per-period budget counts these deadlines;
each contains at most six distinct source targets. Competing TIO, ESAI or DAX
writers still fail with both CPU contexts. See reference-audio-clock.txt.

With actual POR, declared observations may start at tick0 under reset. The nominal
MCU-start profile retains the post-release timestamp restrictions. Static initial
levels remain available before release in either profile. An actual release is
quantized to a completed MCU operation; native input clocks are not host clocks.

ESAI and common audio-clock sources

  dsp-initial esai 1 unknown unknown low reference-reset-edges
  dsp-at 2000 esai 1 unknown unknown high reference-reset-edges
  dsp-clock esai 1 hckt 2000 23 516 reference-reset-edges
  dsp-audio-clock 11289600 2000 low 6 reference-reset-edges

The dsp-at, dsp-clock and dsp-audio-clock rows above are alternative sources,
not simultaneous declarations for the same instance.
An ESAI snapshot supplies SCKT/FST/HCKT together. Index0 is primary X-space,
index1 secondary Y-space. Each level is high/low/unknown. raw selects ordinary
external observations; reference-reset-edges qualifies generated-clock timing.
Missing levels do not inherit known inputs. Configuration, mux, clock-source and
unknown-input checks stay strict.

dsp-clock declares start tick, positive half-period and positive observation
count; HCKT begins high then alternates, with an independently declared low
baseline. Sources are compact, not expanded event arrays. Final ticks must fit
uint64. At most one source per ESAI instance is supported.
dsp-audio-clock declares frequency, epoch, initial level and destinations mask:
bits0/1 select ESAI0/1 HCKT; bit2 selects DAX ACI. It is a supplied net hypothesis,
not a recovered physical clock or sample-rate claim. Conflicting sources fail.

PCM, MIDI and state

  pcm-receive esai 1 tx 0 after 2000 rising 32 24 2 high
  midi-sci PR2 6000000 after 2000
  midi-sci-timed PR2 after 2000
  midi-output PR3
  midi-transfer-reference 12 1
  midi-dsp-tio 0 after 2000 synchronized

PCM selects instance, TX lane, threshold, edge, slot/payload bits, slots/frame and
active frame-sync polarity. It observes actual mux-qualified clock/FS/data after
native DSP periods and external inputs. Partial words/frames are never padded.
Samples retain actual ticks and causal ordinals. Native I/O failures keep both
PCs, addresses, time and source. See serial-pcm.txt and pcm-wave.txt for bounded
recording via --audio-out/--audio-rate/--audio-max-frames.

MIDI routes are exclusive. SCI uses PR2 or PS4 and a declared bus rate; its optional
transfer reference is experimental. The alternative midi-sci-timed uses the
common timebase at31250baud, including held POR and WAI; it requires mcu-power-on
and dsp-input-order with a positive event budget. Input clocks remain unchanged
by host negotiation. midi-output selects actual resolved PR3/PS5 serial capture.
--midi-port NAME binds input/output to one ordinary host sequencer session;
see host-midi-session.txt. DSP MIDI uses an explicit31250-baud timer-pin
wire, order/budget and source timing; see dsp-host-midi.txt. These route fixtures
are not proof that the original complete instrument receives or plays notes.

  checkpoint 10 2

At the requested completed operation, retain the trusted in-process state and
repeat its suffix twice. Native failures remain failures. Snapshots include real
MCU/DSP/frontend/timeline state, peripherals, modeled event cursors, wire/PCM
partials and wiring. Restore stages fresh owners before publishing; preparation
failure preserves the live Board. Reentry/foreign identities are rejected.
Host audio/USB sessions are retired, not rewound. This is not a portable state file
or a rewind of physical devices. A .bfnvm export contains MCU NVM only.

Unknown/duplicate fields, malformed numbers, extra tokens, NUL bytes, nonregular
files and inputs over65536 bytes fail. ROM/config paths participate in hardlink/
symlink output-collision checks before outputs open. Reference-board/ROM arguments
are paired and exclude inspect/port-E injection. Exit0 means budget reached,
exit1 setup/input/output failure, exit2 a visible execution fault.

  ctest --test-dir build/strict --output-on-failure -R '^(reference_pipeline|reference_checkpoint|reference_shi_cli|reference_echo_cli)$'

DSP-PIPELINE rows expose real cycle start/end, optional F1 and advanced native
instruction PC, each with its own known flag. retirement=1 marks a genuinely
retired native instruction; prefetch and successor PCs are not execution counts.

Directed authored programs check native words, GPIO/IRQ behavior and joint replay;
original component tests retain separate qualification. See coverage.txt for
current evidence and unresolved boot, clocks, storage, USB/MIDI/audio and complete
Desktop/Keyboard instrument requirements. No component result proves brick safety.

Board observation

status() includes encoded MCU cold NVM; runtime_status() returns the same live
fields with cold_nvm empty. Both require an inactive boundary and change no guest
state, clocks or file publications. Release retained PCM histories before advance
to avoid copy-on-write. Empty cold_nvm is not a persistence checkpoint.

  cmake --build build/strict --target blofeld-reference-runtime-status-test blofeld-reference-flash-test --parallel 1
  ctest --test-dir build/strict -R '^reference_(runtime_status|flash)$' --output-on-failure
Repeat with build/thread for TSan; strict uses ASan/UBSan. No fuzz.

Paired authored POR/flash programs use polling or WAI/flash IRQ, with DSP held in
reset. Frequent queries preserve complete final state, trace, publication counts
and expected flash word0x1234 against an unobserved control. Both profiles pass
these and existing full-status cut/publication-failure regressions; sixteen unit
files match independent complete wire expectations. Host-only query timings have
no threshold and do not establish whole-instrument real-time performance.
Source/ELF/log pins: reference-runtime-status-reference.json. Full original boot,
Desktop/Keyboard functions and storage/update/recovery remain open in coverage.txt.

Host storage inspection

Board::inspect_dsp_memory copies P/X/Y storage at an inactive boundary, including
a faulted one. Unknown words stay absent. I/O, vacant or switching maps and
wrapping ranges fail visibly; no guest read, clock or acknowledgement occurs.
It follows the current physical memory alias, without returning borrowed memory.
reference_memory_inspection checks literal RAM/ROM/alias/unknown results, pending
switches, selected/unselected I/O refusal, range checks and failed-boundary purity.
This diagnostic API does not establish factory-image mapping or sample playback.
