Standalone runtime: available interface and acceptance target

The current executable is blofeld-headless. Its explicit --reference-board
configuration connects the original MCU and independent DSP core, reset, clocks,
SPI, GPIO, NAND, MIDI input and native ESAI output. Configuration and memory inputs
are declared experiment contracts; they do not yet qualify the complete
Desktop SL instrument. See reference-board.txt for the format and diagnostics.

The required dsp-execution setting selects reference-effects, native-cycles or
native-regions. Native-cycles uses computed native instruction budgets with
CPU-only publication grouping (dsp-native-budget.txt). Native-regions couples
bounded native CPU/RAM work to MCU/peripheral horizons and deferred IRQs
(dsp-native-regions.txt). These diagnostic configurations do not qualify the
complete normal Desktop SL instrument.

  blofeld-headless --firmware update.zip --reference-board scenario.bfboard \
    --dsp-rom packed24.bin --device-state /private/existing-dir/unit.bfnvm \
    --display-dir /private/existing-dir/display

Manufacturer firmware, reconstructed reference ROM and storage images stay local.
--device-state owns a persistent virtual identity and native MCU flash, not a
replacement normal profile (device-identity.txt, mcu-flash-clock.txt).
Bounded WAV export, traces, inspection and sample tools are development facilities.
Original 1.25 reaches Main from actual POR with live stores. A frozen observer
linked to production Board/runtime accepts A4 on/off through aplaymidi and
produces 11,560 new nonzero original DSP frames per channel. Its 15-byte Identity
reply reaches aseqdump, retaining the original ASCII1.24 quirk. Under the explicit
vacant-data decoder profile, C0 01 returns to Main without fault and the actual
LCD changes A001 to A002. Initial note/Identity/selection input/output totals
are14/15 bytes.
Counts, hashes and limits: original-midi-controls-reference.json. The earlier
X011cc1 program-change refusal remains in original-midi-runtime-reference.json.
The A002 Init volume witness holds A4, sends CC7zero/max, then NoteOff. Its
4096-frame tails retain constant signed24 -15/-30 after zero/release; changing
audio returns at CC7max without another NoteOn. The bit-zero expectation remains
failed. The separate independent-Core master-history test preserves the original
fixed words; the specific live residual cause remains unproven (dsp-master-history.txt).
One edit Sound Request also returns392 original bytes with valid checksum/name.
Two passive readers retain its255/137-byte ALSA fragments after the first
one-virtual-second observation expires. The same instrument returns to Main;
the timed-out controller remains failed. Configured USB IN has no host consumer
in this witness, and observed MCU PCs enter its original capacity/flush loops.
Physical response timing and all dump/transport variants remain unqualified.
These note/volume/selection witnesses do not qualify all programs/controllers,
factory SL, normal-profile launch, host audio or realtime instrument operation.

Execution ownership
One emulation owner advances MCU and DSP against the common board timeline.
Core memory views borrow stable board-owned storage; peripheral accesses retain
their real owner and visible failures. Direct RAM views add no virtual memory
manager. The DSP uses Core(Memory::external(), &io, options), including its
existing native program/data grants and invalidation contract. CPU12 follows the
same setup shape in its independent library; replacing the current MCU execution
still requires its missing ISA, addressing, reset and interrupt support.

Host audio uses its bounded worker queue; host MIDI has independently negotiated
kernel queues and common-time delivery. Host workers do not mutate CPU state or
advance device clocks. A separate DSP execution thread is a future option only
if measured gains exceed event/memory synchronization costs. No such thread or
whole-instrument performance improvement is established by the memory API change.

Display
The controller exports complete packed 1-bit display.pbm and display.txt files.
The GTK application in src/gui/ consumes those files without executing firmware
or sending MIDI. Its default source is $XDG_RUNTIME_DIR/blofeld-emu/;
--runtime-dir selects the XDG root, not the final frame directory.
Atomic file replacement permits redraw at complete-frame boundaries. Abandoned
files remain snapshots, not evidence that the producer is running.
A separate paused MCU-only preview can show Play Sound/A001/Init. The connected
original runtime additionally shows the MIDI-driven A001-to-A002 response above;
these scopes remain distinct. See display-export.txt for Board publication.

Host adapters
The reference API accepts owned ALSA sequencer input through a common-time SCI
wire during POR/WAI (host-midi-session.txt). Restore retires that host session.
With configured native output capture, HostMidiSession also delivers SCI bytes
through the same port. --midi-port NAME selects it in the ordinary CLI, publishes
the actual kernel address/grants, and requires one input route plus midi-output.
The common-time midi-sci-timed route supports POR/WAI; see host-midi-session.txt.
The frozen original-runtime control profile produces a complete Identity reply
(original-midi-controls-reference.json). All SysEx replies and the normal-profile
launcher remain separate requirements.
Separate MIDI port negotiation and refusal tests are in host-midi-port.txt.
The normal instrument must expose bidirectional MIDI/SysEx; input acceptance
alone does not establish output, bank/program changes or USB enumeration.

The session audio adapter negotiates actual formats and buffer grants. A bounded
AudioRuntime worker connects DSP/ESAI frames to the host service without changing
emulated clocks; restore retires the stream (host-audio.txt, audio-runtime.txt).
Private PulseAudio/PipeWire tests qualify their named transport scopes.
The ordinary CLI now binds this worker with --audio-live --audio-rate HZ.
--audio-server SERVER optionally selects a service; absent it, the native client
uses the ordinary session service without daemon autospawn. --audio-buffer-frames
N requests256..65536 frames (default4096); these are backend request bounds,
not global hardware limits. Startup prints the actual first client stream rate,
channels and maximum/target/prebuffer/minimum-request grants. Audio and MIDI
negotiation remain independent. Live output may run alongside --audio-out WAV
recording with its separate --audio-max-frames bound. Replay/missing PCM routes
reject, faults retire output, and successful completion drains accepted frames.
See reference-audio-live-cli-reference.json for authored native DSP/ESAI monitor
and WAV evidence; this is not original live-instrument or realtime acceptance.
Normal profile wiring, sustained playback and complete overload/disconnect behavior
remain open. Host buffering must adapt independently of device clocks and MIDI.

Required normal operation
The product is one Blofeld Desktop with active SL sample capability. It has no
Keyboard/Desktop selection modes. Its instrument interface is MIDI <-> emulator
-> audio, including bidirectional USB-MIDI and normal host audio output.
There is no internal keyboard scanner/HCS08 requirement. Original firmware owns
SL sample behavior; qualified factory storage, not a host license-success
response or firmware patch, must establish the virtual unit's sample capability.
A separate end-user CLI and exclusive ALSA hardware ownership are not required.
Complete normal Desktop SL initialization remains unqualified.

USB is MIDI-only; it must not expose USB Audio endpoints or a virtual sound card.
Normal host-visible USB-MIDI enumeration and bidirectional original transfers
remain pending (usb-runtime.txt). Live host audio is independent of USB.
Complete startup, every documented function, update/recovery, long-run stability
and realtime behavior require the acceptance evidence in objective.txt and
function-acceptance.tsv; component tests do not complete those requirements.
