USB/IP session and nonblocking loopback transport

UsbipSession joins management framing, a qualified UsbipExport, transfer framing
and UsbHostQueue. DEVLIST without a publication returns no device; import without
one fails. The publication is selected when the complete management request is
received, not when a socket opens. A successful import holds that exact export
for the connection and keeps it claimed after close/abort. The board owner must
qualify reset/state and publish a fresh capture before another import. Host-side
lease bookkeeping never supplies a guest reset, rollback or successful status.

Fragmented requests and import/transfer coalescing retain exact wire boundaries.
The transfer decoder exposes remaining frame capacity so a full-size OUT request
can end in the same read as the next command without exceeding the one-frame
buffer. Live sequence identities remain reserved until a complete reply is
consumed; cancellation suppresses the target's later submission reply. Already
completed submissions retain FIFO position before a zero-result unlink reply.

Input chunks are bounded at4096 bytes; pending requests remain capped at32 and
1MiB each. Outbound data is bounded by32 maximum transfer frames and4096 queued
replies, with input headroom reserved for the next chunk. Backpressure stops
socket reads and further USB packet polling until capacity is available. Partial
socket writes consume only their accepted byte prefix. A valid input half-close
retains accepted pending transfers and drains actual replies before closing;
truncated EOF or invalid input poisons that connection. Abort discards host
queues/output only; already accepted MCU effects and IRQs remain observable.

Host OUT/status packets additionally check the controller's known DATA PID
against independently retained host state. A new/stale host queue must not count
a device's duplicate ACK as new data. Unknown EPRST PID state and mismatches fail
with request/endpoint/PC/CCR; no state is silently synchronized or repaired.
Linux USB/IP's hub-class SET_FEATURE(PORT_RESET) proxy is rejected explicitly
until a board-owned reset implementation is qualified. It is not forwarded as a
Blofeld firmware class request or assigned successful reset status.

UsbipTcpServer binds IPv4 loopback as a regular user, with nonblocking/CLOEXEC
listener and accepted sockets. It has at most4 active connections,4 accepts and
one bounded read per connection per poll. Output has a per-connection byte budget
(up to64KiB) and bounded send attempts; no sleep, socket thread or MCU execution
exists inside the transport. The caller supplies actual MCU execution/context
between polls. These scheduling limits do not establish USB wire timing or
real-time performance. TCP_NODELAY is enabled; SIGPIPE cannot terminate a poll.
SO_REUSEADDR permits fixed-port restarts after an actively closed management
connection, including while an old peer still retains its received FIN. A second
active listener on the same loopback address/port is rejected; SO_REUSEPORT is
not enabled. Tests repeat actual DEVLIST exchanges across listener replacement
and after prior clients close, with process descriptor ownership checked.

Malformed input and ordinary peer I/O errors close that peer and return a visible
event. Imported closure reports required board-state qualification. A modeled
hardware fault propagates its real context, retires all connections/publication
and stops the listener; it is never turned into a fake transfer success/STALL.
Withdrawal also closes live connections without changing guest peripheral state.
Socket/session state is noncopyable and excluded from board replay/checkpoints.
Decoded full-speed suspend retains the import and pending phases while the TCP
server continues management/output/cancellation without device packet polling.
Actual packets resume only after a supplied decoder resume (usb-suspend.txt).

Input frame deadlines
The TCP adapter uses a separate monotonic host clock. The default frame timeout
is30 seconds; UsbipTcpOptions accepts a positive millisecond duration up to24
hours. The initial management request has a deadline from socket acceptance,
including a peer that sends nothing. After import, only a partial next frame
arms a deadline. Completing one frame and starting another in the same read
starts a fresh deadline; additional bytes within an incomplete frame do not
extend it. Expiry is checked before I/O at the next caller poll, not by a timer
thread. It is a host resource policy, not USB wire timing or reference common
ticks. A backwards clock or unrepresentable deadline retires the adapter.

Fully framed pending URBs and idle imported connections have no frame deadline:
MIDI IN may legitimately NAK until data exists. Expiry closes only the affected
peer with a visible error and imported recovery requirement. It never sends a
synthetic URB completion, releases the lease or resets guest SETUP/IRQ/RAM.
Deterministic own TCP/native tests inject the host clock, check idle management,
byte trickles, partial headers/payloads, coalesced boundaries and an IN request
still pending after two simulated host hours. Actual own HC12 ISR execution
after expiry retains the already accepted SETUP. No sleep or fuzzing is used.
Output-stall and valid-half-close drain deadlines remain unqualified separately;
the pure session itself has no clock or timeout policy.

Explicit runtime CLI/common-clock board binding has own native/actual-process
tests and capture/session invalidation guards (usb-runtime.txt). There is no
kernel USB attachment. Normal original enumeration, USB-MIDI class binding,
Wine Spectre transfer, keyboard/PipeWire routing and full boot/MIDI/audio remain
open. Original USTB/NISOF/automatic configuration status frontiers remain strict.
Loopback own-fixture tests are not hardware or original-firmware equivalence.
No fuzzing, physical device traffic, module loading or system routing is used.

Deterministic gates:
  cmake --build --preset strict --target blofeld-usbip-session-test blofeld-usbip-session-boundaries-test blofeld-usbip-tcp-test blofeld-usbip-tcp-native-test blofeld-usbip-frame-timeout-test
  ctest --test-dir build/strict --output-on-failure -R '^(usbip_session|usbip_session_boundaries|usbip_tcp|usbip_tcp_native|usbip_frame_timeout)$'

usbip_session_boundaries supplements the packet/native/TCP cases with all89
split positions of a coalesced40-byte import and48-byte IN request, all40 truncated
imports,47 incomplete IN headers and4 partial OUT payloads. It also checks actual
MCU ACK/NAK bytes, full-queue cancellation, a partially sent reply's reserved
sequence, malformed coalesced suffixes, half-close/abort after accepted SETUP,
exclusive import and unchanged context-rich strict controller faults. These fixed
cases do not qualify original enumeration, board timing or physical USB behavior.
