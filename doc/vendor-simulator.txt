Optional local Symphony Studio reference

The user-provided Symphony Studio 1.1.0 archive is pinned in reference-tools.json.
It is a local reference, not a production dependency. No installer, vendor code,
DLL, extracted assets or manufacturer program words belong in this repository.

The dedicated 32-bit Wine prefix is:
  $HOME/.local/share/wineprefixes/blofeld-emu

The application is installed at C:\SymphonyStudio. Reproducible installer options
are /mode silent /prefix C:\SymphonyStudio. Run Wine as the ordinary user with
WINEDEBUG=-all and WINEDLLOVERRIDES='mscoree,mshtml=;winemenubuilder.exe=d'.
Do not reuse the separate CodeWarrior or Spectre prefixes. No physical debugger,
OpenOCD connection, hardware programming or extra system installation is needed
for the local simulator experiments.

  WINEPREFIX="$HOME/.local/share/wineprefixes/blofeld-emu" WINEDEBUG=-all \
    wine 'C:\SymphonyStudio\dsp56720-devtools\dist\gdb\gdb56300.exe' --version

The installed console debugger reports GNU GDB 6.4ps001, target dsp56720.
The simulator server can load the DSP56300 library and explicitly reports
'Created 56371 device'. Use its containing directory as the working directory:

  WINEPREFIX="$HOME/.local/share/wineprefixes/blofeld-emu" WINEDEBUG=-all \
    wine 'C:\SymphonyStudio\dsp56720-devtools\dist\dsp56720\gdbsimapiserver.exe' \
    -dll libdsp56300simapi -port <unused-port> -loud

The -dll argument takes a library basename, without '.dll'. -h prints usage;
omitting the required port also prints usage and returns failure. Disconnecting
the debugger terminates this reference simulator. Use one simulator owner at a
time under the shared native-process budget. The Eclipse GUI is not qualified.

The installed server has a memory-transport incompatibility: the 56300 callback
uses Boolean success, while the server's RSP handlers expect zero. Reads return
E00 and writes echo packets although the underlying operations can succeed.
The custom GDB frontend still displays zeros and exits successfully. Do not use
those displayed zeros as memory observations. An unchanged-server control now
executes an independently encoded immediate MOVE and reports its exact nonzero
X0 and two-word PC increment, proving that the write actually occurred.

A local copy corrects only the two RSP memory success tests. The installed
executable and processor DLLs are unchanged. A strict client checks checksums,
reply sizes, actual OK responses and explicit errors; the server's trailing
boundary NUL is recorded separately. Program readback, native instruction/PC
expectations and independent X/Y canaries validate that reference transport.
The transformed binary, derivation and all program/packet data remain local.

The tested 56371 model is still not qualified as a memory-map oracle. Native
MOVEC plus three subsequent NOPs and 140 fixed endpoint cases expose 20 RAM
disagreements with DSP56371UM tables 3-1..3-6. A fresh model with the original
first-stage OMR operand independently retains writable X:010000 and loses
previously written Y:000000, contrary to table 3-2. The cause/configuration
remains unresolved; these observations do not override the chip manual.
The explicit -fastmode option produces identical native instruction/register
observations in that fresh counterexample and does not resolve the disagreement.

Initial model OMR=000300 independently agrees with the documented CDP reset
bits. Initial PC=C00000 and BCR=0 do not qualify a hardware SPI-reset sequence
or complete derivative initialization. The release note primarily describes
the DSP56720 platform configuration. The observed reserved-write/ROM results
cannot establish silicon behavior from this inconsistent model. Our emulator
therefore retains its reserved Y:002000 and missing-ROM failures; no write-
discard policy or guessed memory alias follows from these experiments.
The server log explicitly reports internal-reserved-memory access for Y:002000
while the debugger still receives a stepped-stop response. Neither that response
nor a later zero value establishes successful access or harmless silicon writes.

The separately pinned NXP assembler 6.3.28 qualifies the document-derived SPI
prefix encoding independently of the simulator. It preserves the manual's three
forced-short BRA forms, producing 55 words; see dsp-core.txt. This does not
qualify processor memory semantics or turn the prefix into a hardware ROM dump.

Archive/payload inventories, installed-tool hashes, registry backup and exact
session logs remain under ignored doc/local/dsp-vendor-simulator/.
