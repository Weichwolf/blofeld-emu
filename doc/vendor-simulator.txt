Optional local simulator references

Symphony Studio1.1.0, the NXP assembler and TASKING reference tools are pinned in
reference-tools.json. They are optional offline comparison tools, not production
or build dependencies. Installers, DLLs, transformed local reference executables,
manufacturer program words and detailed sessions remain ignored local inputs.

Symphony uses the dedicated ordinary-user 32-bit Wine prefix
$HOME/.local/share/wineprefixes/blofeld-emu. Its console server can create a56371
model; that identifies a simulated device, not validated Blofeld hardware.
The installed RSP server has incompatible memory success conventions. Its raw
E00/echo responses and the bundled debugger's displayed zeros are not qualified
memory observations. Independently checked local transport corrections and
native instruction/canary controls are recorded in the private reference archive.

Both examined Symphony and TASKING models disagree with documented switched-RAM
behavior. Their successful API returns do not establish reserved-write semantics,
missing ROM contents or physical memory decoding. Normal/fast simulator modes
also report different clocks for identical instruction/register results.
Neither model is a silicon memory-map or timing oracle.

Bounded instruction expectations remain useful where their independent encoding,
PC/register effects and transport readback are qualified. The NXP assembler
independently checks the document-derived SPI prefix (dsp-core.txt); that prefix
is not a recovered hardware ROM. dsp-pipeline-timing.txt and the named instruction
records state their narrower timing/operand scopes and unresolved cases.

The current emulator uses the independent DSP core and explicit functional board
contracts. Historical vendor-tool disagreements are not a reason to stop native
firmware reconstruction. Complete acceptance remains defined by objective.txt.
